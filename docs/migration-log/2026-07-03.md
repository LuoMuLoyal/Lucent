# 2026-07-03 Security PIN replacement for 2FA

## Schema

- Removed `twoFactorEnabled`, `twoFactorSecret`, and `twoFactorRecoveryCodes` from `User`.
- Added `securityPinEnabled`, `securityPinHash`, `securityPinChangedAt`, and `securityElevationVersion` to `User`.
- Migration: `prisma/migrations/20260703125744_replace_two_factor_with_security_pin/migration.sql`.

## Domain

- New `SecurityPinModule` with `SecurityPinService` and `SecurityElevationGuard`.
- PINs are 6-digit numeric strings hashed with argon2id.
- Enabling, changing, or disabling a PIN increments `securityElevationVersion`, invalidating prior elevation tokens.
- Successful PIN verification mints a 15-minute signed JWT elevation token (`scope: security_elevation`).
- Elevation tokens are read from the `x-security-elevation` header as `Bearer <token>`.

## Settings API

- `POST /api/v1/settings/security-pin/enable`
- `POST /api/v1/settings/security-pin/verify`
- `POST /api/v1/settings/security-pin/change`
- `POST /api/v1/settings/security-pin/disable`

All endpoints require authentication. Verify returns an elevation token and expiry.

## Sensitive route protection

The following routes now require a valid elevation token via `SecurityElevationGuard`:

- `POST /api/v1/account/password`
- `POST /api/v1/account/email`
- `DELETE /api/v1/account/identities/:identityId`
- `POST /api/v1/user/data-export-requests`
- `GET /api/v1/user/data-export-requests/latest`
