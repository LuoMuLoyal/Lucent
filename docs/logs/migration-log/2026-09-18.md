## fix(medicines): searchText 不再进入 matchedBy,查询改两层 OR

（来源：2026-09-17 审查报告 W1/S5，报告 `plans/Lucent-review-09-17.md` 保留中。）

### 背景

搜索响应的 `matchedBy` 此前会把预拼接的内部索引字段 `searchText`（import 脚本已含
name/CAS/UNII/ids/groups/前 20 synonyms）一并上报，命中任一业务字段时同时返回
`[name, searchText]` 等重复键，前端无法判断真实命中字段。

### 变更

- `src/modules/medicines/adapters/drugbank.service.ts` / `cn.service.ts`：
  `toSearchItem` 不再把 `searchText` 喂给 `detectMatchedBy`，只保留业务键
  （drugbank：name/casNumber/unii + synonyms；cn：name/brandName/approvalNumber/
  barcode/nationalDrugCode）。
- 同文件 `buildWhere` 由 4~6 个并列 OR 改为「searchText 主发现 + 业务字段嵌套 OR
  兜底导入遗漏」的两层结构（消除 searchText 覆盖 name/CAS/UNII 的冗余匹配路径）。

### 验证

- 新增单测：两个 adapter 各增「matchedBy 只含业务键、不含 searchText」用例，
  buildWhere 断言更新为两层 OR 结构。
- 全量 `pnpm test`：322 files / 3821 tests 全绿；`pnpm typecheck`、`pnpm build`、
  `pnpm lint:check` 通过。

## fix(medicines): 缓存读写失败降级而非抛错

（来源：2026-09-17 审查报告 W2，报告 `plans/Lucent-review-09-17.md` 保留中。）

### 背景

`cacheGet` / `cacheSet` 的 try/catch 只 `logger.warn` 后直接 `throw`，catch 实质冗余：
缓存抖动会把药品读请求变成 500，与「缓存故障应当被捕获降级」的注释意图不符。

### 变更

- `src/modules/medicines/cache/store.service.ts`：`cacheGet` 失败返回 `undefined`，
  `getOrSet` 把它当 miss 走 `load()` 穿透读；`cacheSet` 失败 swallow（读已成功，
  写失败只影响下次请求）。保留 try-catch + warn（AGENTS 要求 cache 调用必须保护）。

### 验证

- `store.service.spec.ts` 增两用例：cache get 抛错时仍返回 load 结果、cache set
  抛错时业务返回不受影响。

## feat(medicines): cn 源 sequences 走统一 cache+adapter 调度

（来源：2026-09-17 审查报告 S2，报告保留中。）

### 背景

此前 cn 源的 sequences 调度在 `MedicinesService.getSequences` 内联
`Promise.resolve({ drug: [], targets: [] })`，绕过统一 cache + adapter 分发路径，
cn 的 sequences 缓存键永远不落。

### 变更

- `cn.service.ts`：新增 `getSequences(id)`，返回空序列集（CN 源无序列列，
  药品本身存在故不 404）。
- `medicines.service.ts`：cn 分支改调 `cnMedicinesService.getSequences`，
  经 `getOrSetSequences` 走统一缓存路径。

### 验证

- `medicines.service.spec.ts` 增 getSequences 三用例（drugbank 路由 / cn 路由 /
  空值 not_found）；`cn.service.spec.ts` 增空序列集用例。
