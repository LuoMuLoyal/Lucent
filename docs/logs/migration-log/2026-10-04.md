# 迁移日志 2026-10-04

## 模型思考开关提取为环境变量(语义化 `AI_THINKING`)

### 背景:线上思考开关其实一直是「无人控制」

生产主站 6 个 AI role 全部指向阿里云 MaaS(`...maas.aliyuncs.com`)上的
`deepseek-v4.1-flash`,而 `src/llm-runtime/llm-runtime.service.ts` 的两条硬编码
探测**一条都不命中**:

- DeepSeek 分支要求 baseUrl 含 `api.deepseek.com` —— 阿里云域名不含;
- 阿里云分支要求 model 以 `qwen3` 开头 —— 实际是 `deepseek-v4.1-flash`。

于是关不关思考既不取决于配置也不取决于意图,只取决于「域名与模型名的巧合」。
而 LightRAG sidecar 早有 env 化先例(`EXTRACT_OPENAI_LLM_EXTRA_BODY`),主站没跟上。

### 变更

**语义化开关**(`src/config/env/{env-keys.enum.ts,environment.validation.ts}`、
`src/config/services/llm.config.ts`):

```text
AI_THINKING                    # auto | enabled | disabled,默认 auto
AI_ANALYSIS_THINKING           # 按角色覆盖,未设则继承 AI_THINKING
AI_VISION_THINKING
AI_LANGUAGE_THINKING
AI_CHAT_THINKING
AI_CHAT_COMPRESSION_THINKING
```

- 值经 zod `enum` 校验,**写错即启动失败**,不会静默回落 auto 让运维误以为开关已生效。
- `LlmRoleConfig.thinking` 与 `LlmConfig.thinking` 都是可选字段,`undefined` 等同
  `auto` —— 这样既有的手写配置字面量(测试、port)无需同步改,语义也正好是「保持旧行为」。
- 嵌入 role 没有 chat model,故不设 `AI_EMBEDDING_THINKING`。

**请求形态仍按 baseUrl 决定**(`applyProviderQuirks` 拆出 `applyThinkingMode`):

| 场景                                 | 行为                                     |
| ------------------------------------ | ---------------------------------------- |
| `auto` + DeepSeek 域名               | `thinking: { type: 'disabled' }`(旧行为) |
| `auto` + 阿里云域名 + `qwen3*`       | `enable_thinking: false`(旧行为)         |
| `auto` + 其它组合                    | 不发任何字段(旧行为,如线上现状)          |
| 显式 `enabled`/`disabled` + 上述两族 | 按值下发,**即使 auto 本来不会命中**      |
| 显式值 + 无法识别的网关              | 不发字段                                 |

最后一行是有意的:未知网关收到未知推理字段会被严格 OpenAI 兼容服务判成请求校验错误,
「没有效果」比「请求报错」可诊断。第二行则是这次修复的落点 —— 线上那种组合现在可被显式控制。

### 验证

`llm-runtime.service.spec.ts` 断言 `modelKwargs` 实际值(而非仅「model 能构造出来」),
覆盖上表全部分支,含线上组合(`auto` 不发、显式 `disabled` 发 `enable_thinking:false`);
`llm.config.spec.ts` 覆盖全局默认、角色覆盖、非法值回落 auto、大小写不敏感。
`pnpm lint:check` / `pnpm typecheck` / `pnpm vitest run` 全绿。

### 部署前提

`.env.development.example` / `.env.production.example` 已补全部键(默认 `auto`=行为不变)。
**生产要真正关掉思考,需在部署侧显式设 `AI_THINKING=disabled`** —— 这一步是运维决策,
未在本轮代码改动中代设。参考 `docs/reference/environment-variables.md` 的
「Reasoning ("thinking") mode」小节。
