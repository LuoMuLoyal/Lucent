### 关键点

- **第 4 项的隐藏陷阱已避开**：`get_chain_head()` **不在**
  `ProvenanceStorage.__abstractmethods__` 里（基类默认 `return None`，注释写
  "该后端不支持链式"）。只实现 5 个抽象方法会**静默关闭哈希链** —— 写入看似正常，
  `verify_chain()` 却报 `chain_break`。实现里显式覆盖，共 6 个方法。
- **第 10 项补了一处试点未覆盖的缺陷**：事实参数**保留原文引号**

  直接比较会让 `D != 'a'` 恒真。已统一按去引号后的值比较（`_normalise_term`）。
- **第 12 项的自动派生仍不可用**：本次只修了"重复前缀"这一条。
  `sh:minCount` / `sh:maxCount` 依旧只在词条显式声明 `cardinality.min`
  或 `required` 时才发出 —— 这是**有意保留**的：自动发明约束会在 CI 里挡掉合法数据
  （源码 `#1105` 注释即为此）。落地时 SHACL 形状按 §6.4 手写。

## feat(semantica-service): 新建英文侧 OAG sidecar 骨架

（来源：同一计划的 §6.5 落点切分与 §8.2 执行顺序。新仓在**工作区根目录**
`semantica-service/`，独立 git 仓，与 `semantica/`（fork 镜像仓）互不隶属；
代码不放 `Lucent/deploy/`，理由见 §6.5。计划仍在执行中、未删。）

### 背景

计划 §8.2 把落地切成 S0–S4，本次做 S2 的第一步：把 sidecar 服务立起来。
**不参考同目录的 `semantica-oag-pilot/`** —— 那是一次性可行性验证，
与新项目无继承关系。

### 变更（`semantica-service/`，6 个提交）

| 提交           | 内容                                                                                                                     |
| -------------- | ------------------------------------------------------------------------------------------------------------------------ |
| `chore`        | `uv init --package` 骨架（src 布局）；移除 uv 默认的 `[project.scripts]` 入口（它指向不存在的 `semantica_service:main`） |
| `build(deps)`  | 依赖集 + ruff/mypy/pytest 工具链；semantica 用 `[tool.uv.sources]` 从 fork `main` 装，**不装 PyPI 0.6.8**                |
| `feat(config)` | pydantic-settings 配置：AGE DSN、图名、连接池上下限、`statement_timeout_ms`、推理规模/超时上限                           |
| `feat(graph)`  | `StorePool`：按请求借还的 AGE store 池 + 每连接 `statement_timeout`                                                      |
| `feat(api)`    | FastAPI 应用 + `/health`（AGE 不可达时返回 503）                                                                         |
| `docs`         | README + `.env.example`；`.env` 加入 `.gitignore`                                                                        |

### 关键点

- **所有端点都是同步 `def`**。`psycopg2` / Datalog fixpoint / pyshacl 都是
  阻塞或 CPU-bound；`async def` 会把它们放上事件循环，一慢全停。
  FastAPI 对同步 handler 自动走线程池。
- **池是"store 池"而非"连接池"**：`ApacheAgeStore` 内部持有单个 `self._conn`，
  因此按请求借还一个 store，而不是共享单例（实测单连接并发 16 慢 2.9×）。
- **`statement_timeout` 的传递方式踩了坑并已修正**：`connect()` 接受
  `**options` 但**除 `connection_string` 外全部忽略**（docstring 自己写着
  "currently unused"），直接传参是静默 no-op；而 `statement_timeout` 是服务端
  GUC、不是 libpq 连接选项，只能经 `options=-c statement_timeout=...` 传，且
  该值含空格**必须加引号**，否则 libpq 报
  `invalid dsn: invalid connection option "statement_timeout"`。
  现按 DSN 传并加引号，连接后再 `SHOW statement_timeout` 复核，不符即拒启。
- `/health` **不只看进程存活**：它真借一条连接读图规模，AGE 不可达时返回 503，
  避免负载均衡把流量送到依赖已挂的进程。

### 验证

- `uv sync` 装到的是 **`semantica==0.7.0` from git `42519e65`**（即本日推送的
  fork 提交）；已在装好的包里复核 fork 修复全部到位：`DatalogRule.inequalities`
  存在、`load_from_graph` 抛 `TypeError`、`_resolve_xsd('xsd:string')` 返回
  `xsd:string`、`PostgresStorage` 可导入。
- `uv run ruff check` / `ruff format --check` / `mypy src tests`（strict）全通过；
  `uv run pytest` 17 passed。
- 真实启动 `uvicorn` 验证：AGE 未运行时 `/health` 返回 503 且错误体准确报出
  `Connection refused`（修正 DSN 前报的是 `invalid dsn`）；`/openapi.json`
  正常暴露 `/health`，可供 Lucent 生成客户端。
- mypy 对 `semantica.*` 单独加 `ignore_missing_imports`：该包既无 `py.typed`
  也无 stub，属客观未类型化；我方代码仍在 strict 下。`types-psycopg2` 以
  dev 依赖引入，未放宽规则。

## fix(compose): 数据库镜像归属与命名更正

（接上一条。上一条把 Dockerfile 放在 `semantica-service/`，**该归属有误**，
本条目更正；上文保留为当时的记录，不回改。）

### 归属更正

该镜像服务的是**本仓三环境 compose 里的 `postgres` 服务**，与
semantica-service 是否部署无关。放在那边等于让 Lucent 的部署依赖
semantica-service 的源码——Coolify 的构建上下文也够不到仓外路径。

已移交本仓 `docker/postgres-age/`；`semantica-service/` 侧对应删除
（见该仓 `refactor: 数据库镜像定义移交 Lucent 仓`）。

### 命名规范化

原 `lucent-postgres-age:pg18-age1.7.0` 是把技术栈拼在一起，既长又把
「一个扩展」当成了镜像身份。改为 **`lucent-db:18`**：

- 它**首先是 Lucent 的主库镜像**，AGE 只是额外带的扩展 → 按定位命名，
  将来增删扩展不必改名
- 标签只写 PG major；AGE 版本由构建参数 `AGE_REF` 决定，生产用短 sha
  标签保证可复现（同 `LUCENT_IMAGE` 的做法），故不必把扩展版本拼进标签
- 经 **`${LUCENT_DB_IMAGE}`** 注入：dev 有默认值，staging/prod 必填。
  与既有 `LUCENT_IMAGE` 同法，**仓库不写死 registry**

- dev 建出 `lucent_graph` 并启用 age 后，

### 期间修掉的两个自身缺陷

- **默认 AGE 端口写错**（15433 → 15432）：初版凭印象填，与 dev 实际端口
  不符；改为对齐 `docs/reference/environment-variables.md` 的记录，
  并让自检脚本读服务配置而非硬编码 DSN。

  （`/health` 因此返回 503）。改为解析带单位的时长，`min` 不被误判为 `ms`。
