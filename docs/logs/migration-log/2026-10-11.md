# 2026-10-11

## fix(reports): 事件回顾 facts.arguments 不再下发 null 值

- 现象:手机端「回顾」Tab 加载不出来(先整页骨架、随后错误态),而后端 `/api/v1/user/reports/reviews/current`
  每次都 200、耗时 10ms 上下;访问日志里该端点以 ~6.4s 的固定间隔被反复请求。
- 根因:结构化 facts 的 `arguments` 里带了 JSON `null`(活动事件的 `endedAt`、无触发记录时的
  `reasonRecordTitle`、缺失的 `water`/`sleep` 趋势),而契约把它发布为自由对象,生成的 Dart 客户端
  因此把值类型定为不可空的 `Map<String, Object>`。`checked: true` 的反序列化在遇到 null 时抛
  `type 'Null' is not a subtype of type 'Object'`,客户端在 200 之后失败 → Riverpod 按指数退避(上限
  约 6.4s)无限重试 → 页面停在骨架/错误态。用真实响应在本地跑 `EventReviewData.fromJson` 复现了该异常,
  去掉 null 值后同一份 payload 解析通过。
- 变更:`services/event-review/` 新增 `compactFactArguments()`(缺失键取代 null 值),fact/actions/changes/
  next-step 四个 section builder 共 5 处调用它;`dto/event-review-response.dto.ts` 的 `arguments` 上方
  注明该不变量。消费侧对缺失键与 null 的处理等价(`args[key]` 取值 + 类型判断),因此线上语义不变。
- 变更范围只在服务端:已安装在手机上的旧客户端无需更新即可恢复。
- 验证:新增 `fact-arguments.spec.ts`(null/undefined/假值),facts、changes、review 三个 spec 的
  null 断言改为「键缺失」;`pnpm exec vitest run src/modules/reports` 22 个文件 261 条全绿。
