# 2026-10-27

## DrugBank 多值 JsonB 字段提升为关系表

`DrugbankDrug` 上有 6 个 JsonB 列只是"按药取整块"的实现方式，但它们的真实查询需求是**反查**与**横向筛选**，JsonB 下只能全表扫描 + 逐行解析。本次把其中需要关系语义的字段落成表，并删除对应 JsonB 列（留着会变成不再更新的第二份事实源）。

判断标准沿用「结构由查询方式决定，而不是数据形状」：只要一件事需要「哪些药和 X 有关系」或「哪些药满足某个内部字段条件」，就建表；只做「取一个药、看整块」的保持 JsonB。

### 新增表（9 张，均带 `import_run_id` 外键与 `ON DELETE CASCADE`）

| 表                              | 实测规模（19,842 药样本） | 建表理由                                                                 |
| ------------------------------- | ------------------------- | ------------------------------------------------------------------------ |
| `drugbank_drug_interactions`    | 4,631 药 / 291 万条       | 相互作用对要按药集反查；`interacts_with_id` 不建外键（对方可能不在本库） |
| `drugbank_products`             | 4,465 药 / 47 万条        | 按 NDC、labeller、上市/退市日期筛选                                      |
| `drugbank_synonyms`             | 18,160 药 / 42,961 条     | 按同义词命中且可区分语言 / coder；替代 `search_text` 里被截断的前 20 条  |
| `drugbank_dosages`              | 5,276 药 / 100,085 条     | 剂型与给药途径要能横向筛                                                 |
| `drugbank_external_identifiers` | 17,309 药 / 93,636 条     | 按外部 ID 反查本库药物                                                   |
| `drugbank_classifications`      | 11,195 药                 | 按分类层级名称下钻筛药；每药存一条完整路径                               |
| `drugbank_groups`               | 19,842 药全覆盖           | 撤市/研究性等状态的横向筛选                                              |
| `drugbank_manufacturers`        | 829 药 / 5,669 条         | 按厂商反查                                                               |
| `drugbank_packagers`            | 1,215 药 / 20,355 条      | 同上                                                                     |

删除的 JsonB 列：`drugbank_drugs.groups` / `classification` / `synonyms` / `products` / `drug_interactions` / `external_identifiers`。

### 明确不建表

按覆盖率判断：`snp_effects`（0.4%）、`snp_adverse_drug_reactions`（0.2%）、`sequences`（1.7%，另有独立表）、`carriers`（3.5%，已由 `drugbank_drug_targets.relation_kind` 承载）。`pathways`（3.3%）、`reactions`（5.1%）只做按药取整块，保持 JsonB；`ahfs_codes` 源里全为空。

### 配套改动

- `prisma/migrations/20261027090000_promote_drugbank_jsonb_to_tables`：建表 + 外键 + 删列。
- 新增解析器 8 个（`drugbank_drug_interactions.py` / `products` / `synonyms` / `manufacturers` / `packagers` / `dosages` / `external_identifiers` / `classification`），全部复用 `drugbank_nested.py` 的 `unwrap_list` 处理"单对象 vs 数组"混用。
- 导入注册表新增 9 个命令，并加入 `import:medicine:all` 顺序（都在 `drugbank-drugs` 之后，外键要求）。
- `DrugbankMedicinesService.getDetail` / `search` 改为 include 关系表；`getDetail` 对 interactions 取前 200 条——详情页要的是摘要，完整关系图属于 ego-graph 端点。
- 新增 `DrugDataBase/tools/drugbank_field_coverage.py`：用 duckdb 读 parquet 统计字段覆盖率与嵌套规模，替代流式扫 1.82 GB XML。
- **主键统一**：`drugbank_groups` 初版用 `(drugbank_id, group_name)` 复合主键，与其余八张表的 `id` 主键不一致，改为 `id` + 业务唯一键，与其他表对齐。解析器相应生成 `id`。
- **注释语言**：schema 与迁移的注释曾写中文，但整个 `medicine-knowledge.prisma` 与其余迁移均为英文，已统一改为英文。
- **文档同步**：`src/modules/medicines/README.md`（新增「关系表」一节、更新导入顺序与 DrugBank 源说明）、`docs/howto/run-medicine-import.md`（命令表、对账 SQL、`PYTHON_BIN` 前置条件）。
- **既有表形状补齐**：`drugbank_drug_targets` 增 `import_run_id`（外键 + `ON DELETE SET NULL`）。它是唯一一张被导入器写入却无批次链接的表——CSV 靶点与 XML 动作富化两个命令都写它，此前无法把这些关系追溯到具体那一次导入。不需要改的三张已在模块 README 写明理由：`drugbank_drugs`/`structures`/`fingerprints` 是一对一或主表（业务主键即身份）；`drugbank_passage_chunks` 由 RAG 索引脚本写入，溯源走 `source_version`/`source_hash`。
