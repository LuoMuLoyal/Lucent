## fix(reports): 修复 ClinicSummaryPdfService DI 启动崩溃（OpenAPI export 挂 CI）

09-07 `refactor(reports)` 把 `exportPdf`/`exportSharedPdf` 迁到
`ClinicSummaryPdfService` 时，`pdf.service.ts` 用 `import type` 引用了
`ClinicSummaryService` 作为构造函数参数类型。ESM 下 `import type` 的
`design:paramtypes` 元数据退化为 `[Object]`，Nest 无法解析该依赖，导致
`NestFactory.create(AppModule)` 初始化时抛 `UnknownDependenciesException`
`ClinicSummaryPdfService (?)`。

影响：`pnpm openapi:export` 一启动即崩、静默退出码 1（`logger: false` 吞掉
Nest ExceptionsZone 的报错），E2E/OpenAPI 这一个 CI job 从 09-07 起持续红；
后续 e2e 测试也因此从未执行。

修复：

- `pdf.service.ts`：`ClinicSummaryService` 从 `import type` 拆到运行时
  `import`（`ClinicSummaryOptions` 仍为 `import type`）——ESM 下 class 必须
  运行时导入才能被 DI 元数据解析。

验证：重新 `pnpm build` + `pnpm openapi:export` 成功导出
`docs/reference/generated/openapi.json`（Paths 123 / Schemas 290，
无残留 `naming lookup MISS`）；`pdf.service.spec` 12 tests 全绿。

## fix(reports): 控制器拆分后命名查找表前缀滞后，修复语义化 operationId 回退

09-07 把 clinic-summary / event-review 端点从 `ReportsController` 拆到
`ClinicSummaryController` / `EventReviewController`，但 `plans/_naming-lookup.json`
仍以 `ReportsController_*` 前缀登记。export 时新的控制器键查不到映射，回落成
legacy `ClinicSummaryController_xxx` 形态，operationId 与组件名随之下滑

修复：`plans/_naming-lookup.json` 把 12 条 `ReportsController_*` 键改为
`ClinicSummaryController_*`（9 条）+ `EventReviewController_*`（3 条），
语义 operationId / request 组件名保持不变；重新 `openapi:export` 后
无 `naming lookup MISS`。

验证：重新导出前后 operationId 集合一致（143 = 143，无增无删）；
contract 相关 schema（如 `ReportSummaryStreamResponse`）已含进 artifact。

## fix(config): prisma.service.spec mock 尊重显式 undefined 覆盖（CI 单测红）

`makeConfigService.get()` 用 `values[key] ?? process.env[key]`，CI 的
`ci-unit` job 注入 `DATABASE_URL` 环境变量后，`{ DATABASE_URL: undefined }`
覆盖被 `??` 掩盖成 env 值，`PrismaService` 不再抛
`Missing required environment variable`——「throws when DATABASE_URL is
undefined」用例在 CI 上失败（本地无该 env 所以一直绿）。

修复：`prisma.service.spec.ts` 的 `get` / `getOrThrow` 改用
`Object.hasOwn(values, key)` 判断显式键，key 存在（含显式 `undefined`）时
不回落 `process.env`，否则才读 env——显式覆盖优先语义，与 `getOrThrow` 一致。

验证：设 `DATABASE_URL` env 后重跑 spec，13 tests 全绿；
`prefer-object-has-own` lint 规则下用 `Object.hasOwn` 无告警。
