## feat(assistant): 知识检索组暴露为 MCP server（Streamable HTTP）

### 变更范围

新增 `adapters/mcp/`：

- `server.ts` —— 会话表、`StreamableHTTPServerTransport`、Origin 校验、
  JSON-RPC 错误映射。
- `routes.ts` —— Fastify 路由 `/api/v1/mcp`（`POST`/`GET`/`DELETE`，
  `reply.hijack()` 交出发送权）。
- `tool-schema.ts` —— JSON Schema → zod（入参交给 SDK 校验）。
- `execution.ts` —— 端口 → 既有 `executeMany` 的薄适配。
- `auth.ts` —— bearer 鉴权，常量时间比较。
- `mcp.module.ts` —— Nest 装配，`onModuleInit` 注册路由。

新增 `domain/mcp/exposure.ts`（导出名单 + 命名契约 + 反解）与
`application/ports/mcp.ts`（执行端口 + 调用方身份）。

`app.module.ts` 注册 `McpModule`；`env-keys.enum.ts` 增 `MCP_ENABLED` /
`MCP_API_KEY` / `MCP_ALLOWED_ORIGINS`；依赖加 `@modelcontextprotocol/sdk@^1.32.2`。

### 说明

**只做 Streamable HTTP。** 不做 stdio：stdio 由客户端拉起子进程，而工具执行需要
Nest DI（Prisma、Redis、sidecar 客户端、指标），子进程里没有容器。

**暴露范围是领域决策，用不着过滤器。** `MCP_TOOL_NAMES` 手写 8 个知识检索工具；
不导出用户私有数据（`get_records_*` 等，与 `userId` 强绑定，跨进程只会放大越权面）
与写入提案（`propose_*`，离开 confirm 端点会把状态机劈成两半）。手写而非从
`TOOL_NAMES` 过滤，是因为过滤会在将来加入用户数据工具的那天静默开始导出它。

**安全三条按规范落地**（不是可选项）：校验 `Origin`、只绑回环（部署侧决定）、
所有连接鉴权。`Origin` 缺失时放行——CLI 与其它服务不发这个头，拒绝它们会切断主要
用例。`MCP_API_KEY` 未设置时启动打 `warn`，静默的无鉴权模式正是内网端点被暴露的
方式。

**工具名 `lucent__<rawName>` 是纯函数**，不掺运行时值。反解时前缀存在但工具未导出
仍然拒绝，否则调用方可以自拼前缀绕过名单（`exposure.spec.ts` 钉住）。

**执行走既有 `executeMany`**。提案信封、单工具超时、缓存、指标都在里面；第二份
执行器必然漂移，而漂移的表现是「提案被描述成已执行的写入」。

**两处 lint 规则需要 disable 并说明理由**：`tool-schema.ts` 的两处裸 throw 是工具
定义本身畸形（编程错误，不是 API 失败）；`server.ts` 的静默 catch 是因为该类的
logger 挂在 `options` 上，自定义规则只认字面量 `this.logger.error`，日志就在下一行。
