## fix(config): 默认值上移 zod 校验层，业务消费统一走 ConfigService

上一条「移除 YAML 配置层」把默认值内联进了各 config service 与消费方
（`process.env[EnvKey.X] ?? 默认值`），与「默认值落 zod、消费统一走
ConfigService」的既定架构相悖。本次修正：

- **默认值集中到 `src/config/env/environment.validation.ts`**：为全部非敏感键
  补 `.default()`（`z.string()` / `z.enum()` / `z.coerce.number()`），涵盖
  app（host/port/cors/publicBaseUrl）、observability（log-level/format、
  slow-request 2000 / slow-query 500、metrics）、jwt（ttl/issuer/audience）、
  mail（driver/host/port/from + queue 7 键）、storage（provider `s3`、
  s3 endpoint/region `us-east-1`/expiries、tencent-cos region/expiries）、
  jpush（apns/apiBaseUrl）、ai（embeddingDimension 1536）、meal（5 键）、
  fuzzy（3 键）、verification（5 键）、oauth stateTtl。`ConfigModule.forRoot`
  经 Standard Schema 校验后由 `@nestjs/config` 回填 `process.env`，
  消费方与 `registerAs` 工厂因此总能读到默认值。
- **`registerAs` 工厂删除内联默认值**：app / mail / jwt / llm / s3-storage /
  tencent-cos / jpush 七个工厂改为裸读 `process.env[EnvKey.X]`（值已由 zod
  保证非空）；app 保留 production host 分支，jwt 保留 `parseTtl` 对非法格式
  的兜底参数。
- **业务消费方统一走 ConfigService**：`storage.module.ts` 改为
  `configService.get(STORAGE_PROVIDER)`（删除直读 `process.env` + 默认 `s3`）；
  slow-request interceptor、prisma slow-query、logger 模块、oauth state、
  verification-code、meal matcher、meal grounding、metrics 均删除内联兜底
  字符串，直接 `Number(configService.get(EnvKey.X))`（值由 zod 保证）。
  仅启动早期引导（`main.ts` / `app.module.ts` / `i18n.module.ts` /
  `tracing.ts` / `env-file-paths.ts` / `prisma.config.ts`）保留直读豁免。
- **spec 同步**:消费方 spec 的 mock 改为模拟 zod 默认值回填（未设置时返回
  默认）；config 工厂 spec 删除「无 env 时返回默认值」断言（默认值已不在
  工厂层），改为断言 pass-through / 自定义值解析；删除 jpush/llm 对已移除
  的 `DEFAULT_*` 内联常量的依赖。
- `app-defaults.constants.ts` 保留（仍被 jwt / oauth spec 引用），但不再是
  运行时默认值来源。

附带修正 `docs/reference/environment-variables.md` 一处历史错误：
`STORAGE_PROVIDER` 默认值由 `tencent-cos` 更正为 `s3`（与 zod 及原
default.yaml 一致）。

验证：`pnpm typecheck` / `pnpm lint:check` / `pnpm build` 通过；
全量单测全部通过。
