- **默认值集中到 `src/config/env/environment.validation.ts`**：为全部非敏感键

  fuzzy（3 键）、verification（5 键）、oauth stateTtl。`ConfigModule.forRoot`
  经 Standard Schema 校验后由 `@nestjs/config` 回填 `process.env`，
  消费方与 `registerAs` 工厂因此总能读到默认值。
- **`registerAs` 工厂删除内联默认值**：app / mail / jwt / llm / s3-storage /

## docs(storage): 七牛云 Kodo 接入走 S3 兼容路径（不引入专用 SDK）

评估后发现七牛原生 Node SDK（`qiniu@7.x`）的上传模型是「uploadToken + 表单
POST」，**不支持 presigned PUT URL**，与 `ObjectStorageRuntime.createSignedPutUrl`
现有直传契约不兼容（S3/COS/OSS 均支持 presigned PUT，唯七牛原生没有）。

决策：**不引入专用 SDK，七牛走 S3 兼容接口**（`STORAGE_PROVIDER=s3` + 七牛
S3 兼容 endpoint）。理由：

- 客户端（Flutter）直传契约零改动，继续 PUT presigned URL；
- `.env.production.example` 已预置七牛 S3 端点注释
  （`https://s3.cn-east-1.qiniucs.com`），是既有规划方向；
- 避免大改跨仓契约与 Flutter 上传逻辑。

改动：`docs/reference/environment-variables.md` S3 段补充七牛 endpoint 格式
（`https://s3.<region>.qiniucs.com`）与原生 SDK 不支持 presigned PUT 的说明。

验证：`pnpm docs:verify` 通过（纯文档变更，无代码/测试影响）。

## fix(ci): 修复 dev 分支连续 CI 失败（Docker 构建 / E2E / BullMQ）

排查并修复 dev 分支自 7 月以来连续 CI 失败的全部根因：

**Docker 构建 /config: not found**：Dockerfile 仍 COPY config ./config，
但 ADR-0018（2d4bd04d）已删除该目录，CI checkout 中不存在空目录 → buildx 失败。
修复：删除 COPY config ./config 行。

**BullMQ jobId 含冒号**：uildTodayAnalysisJobId 与 uildRecomputeJobId 使用
: 分隔字段（如 oday-analysis:u1:2026-09-09:7），BullMQ 5.x 的
Job.validateOptions 明确拒绝含冒号的自定义 jobId → Enqueue 抛异常 →
today-analysis 触发失败 + suggestion recompute FK 级联错误。
修复：分隔符改为 -，同步更新 analysis-queue.service.spec 断言。

**E2E 429 限流**：CI workflow e2e job 未配置 TRUST_PROXY=true → Fastify 不读
X-Forwarded-For → 所有请求 IP 为 ::ffff:127.0.0.1 → 验证码客户端限流桶
被全部 e2e 文件共享 → 超 20 次窗口限制 → 429。影响 sessions/auth/account。
修复：lucent-ci.yml e2e job 添加 TRUST_PROXY: 'true'。

**reports e2e pdfBase64 断言失败**：测试假设「CI 无 Redis → 队列未配置 →
同步回退返回 pdfBase64」，但 CI 有 Redis → 队列可用 → 异步返回 { jobId }。
修复：断言改为接受 { jobId } 或 { pdfBase64 }。

**reports e2e afterAll hook 超时 (30s)**：pp.close() 等待 BullMQ worker 关闭，
worker 内有 FK 重试 job（3 次指数退避）超过 30s。
修复：vitest.e2e.config.ts hookTimeout 从 30s 增至 60s。

**legal-documents e2e 缓存污染**：contract.e2e 在 legal-documents.e2e 前运行，
GET /legal-documents 把 migration seed 7 条数据写入 1 小时缓存；
legal-documents.e2e 的 eforeAll 只清 DB 未清缓存 → 首个 GET 返回 7 条。
修复：beforeAll 中清除 legal-documents:list:_ 与 legal-documents:detail:_:\*。
