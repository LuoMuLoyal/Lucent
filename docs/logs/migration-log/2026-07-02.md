# Migration Log - 2026-07-02

## Lucent

- Consolidated duplicated local utility functions into shared common utils:
  - `normalizeNullableText` moved to `src/common/utils/string.utils.ts` and reused across
    meal-analysis worker, vision, and dish-decomposition services.
  - `extractJsonObject` extracted to new `src/common/utils/json.utils.ts` and reused by vision and
    dish-decomposition response parsing.
  - `asNullableString` / `asNullableNumber` replaced with common `normalizeNullableText` and new
    `normalizeNullableNumber` in `src/common/utils/number.utils.ts`.
  - `roundNumber` moved to `src/common/utils/number.utils.ts`.
  - `commonCharacterCount` moved to `src/common/utils/string.utils.ts` and fixed its
    duplicate-counting bug by using character-frequency maps.
- Replaced the hacky `DishTemplatePrismaAccess` type in `MealDishDecompositionService` with the
  proper Prisma-generated payload type.
- Hardened silent `catch { return null; }` blocks in meal-analysis vision and dish-decomposition
  parsers so JSON parse failures are logged with context instead of swallowed.
- Fixed the fuzzy-ingredient query in `MealIngredientGroundingService` to filter candidates with an
  indexed `startsWith` predicate on `normalizedName`/`searchText` instead of scanning the whole
  table.
- Extracted hard-coded meal-analysis thresholds (fuzzy scores, portion grams, nutrition commentary
  thresholds) into named constants with TODO markers for future configuration.
- Updated the meal-ingredient-grounding test mock to distinguish exact and filtered fuzzy queries
  now that both carry `where` clauses.
- Verified the backend with `pnpm typecheck`, `pnpm lint:check`, and the full Jest suite.
- Removed campus-scoped support resources from the public contract: `support-resources` now only
  exposes `help` / `about`, reference-data `updatedAt` was bumped to `2026-07-02T00:00:00.000Z`,
  and the exported OpenAPI/client contract was regenerated to drop the `campus` scope.
- Synced public/current docs with the new runtime boundary: Mine/Settings contract, environment
  contract, and current-state docs now describe campus-service removal and the remaining `help` /
  `about` support-resource scope.
- Recorded the current CN -> DrugBank bridge status in `docs/public/data-sources.md`: the local V2
  workbook snapshot still has 0 populated `drugbank_ids`, so cross-source mapping is not treated
  as solved runtime data.
- Added three assistant medicine lookup tools on top of the existing retrieval stack:
  `search_cn_medicine_products`, `get_cn_medicine_detail`, and `get_drugbank_detail`.
- Wired those new tools into assistant runtime selection heuristics and reused the existing
  medicines source services instead of adding a parallel assistant-only query layer.
- Regenerated `docs/openapi.json` so assistant capabilities/exported tool enums now include the new
  structured medicine lookup tools.
- Added `match_cn_product_to_drugbank_candidates` as a deterministic assistant bridge tool: it
  resolves one CN product safely, normalizes CN ingredient/product-name aliases, queries local
  `drugbank_drugs`, and returns explainable candidates with confidence instead of asserting one
  final mapping.
- Wired the new candidate-match tool into assistant tool metadata, executor dispatch, and runtime
  selection ordering so mapping-style prompts now pull the bridge tool with its CN product
  prerequisites.
- Added focused Jest coverage for single-ingredient match, compound products, ambiguous CN
  resolution, and no-ingredient fallback; re-verified with `pnpm test --
src/modules/assistant/tools/services/assistant-tool-drugbank-candidate-match.service.spec.ts
src/modules/assistant/tools/assistant-tool.service.spec.ts
src/modules/assistant/agent/assistant-runtime.graph.spec.ts`, `pnpm typecheck`, `pnpm
lint:check`, `pnpm export:openapi`, `dart run tool/regenerate_lucent_openapi.dart`, `dart run
tool/verify_lucent_openapi_sync.dart`, and `flutter analyze`.
- Fixed one backend-only bridge semantics bug before close-out: when normalized CN tokens produce
  zero DrugBank candidates, `match_cn_product_to_drugbank_candidates` now returns `coverage.status
= empty` instead of `complete`, and a regression test locks that behavior.
- Product decision rollback on the same day: removed `match_cn_product_to_drugbank_candidates`
  entirely from Lucent because a handwritten alias-maintained CN -> DrugBank bridge is not
  sustainable for this product stage. Assistant runtime returned to source-split search/detail
  only, with no runtime cross-source bridge claim.
- Hardened the post-rollback CN medicine assistant path instead of adding more tools: explicit CN
  product-style questions now prefer `search_cn_medicine_products` -> `get_cn_medicine_detail` ->
  `search_medicine_leaflets`, which keeps first-pass routing on the Chinese source side instead of
  mixing DrugBank / QA into the same selection.
- `AssistantToolService.executeMany()` now carries a safely resolved CN `productId` from
  `get_cn_medicine_detail` into downstream `search_medicine_leaflets` calls by rewriting the
  leaflet payload with `filters.productId`, so leaflet retrieval is product-scoped when one
  structured CN detail record was already resolved.
- Added focused regression coverage for both behaviors and re-verified with `pnpm test --
assistant-runtime.graph.spec.ts assistant-tool.service.spec.ts
assistant-runtime.service.spec.ts` plus `pnpm typecheck`.
