## refactor(reports): event-review 子域四层化，读模型形状归应用层

- 计划 R1。`reports` 里风险最低的子域：5 个 service、无队列、无事件、全部数据
  经 reader port 取得。实测确认它**本来就不直连 Prisma**（只 import Prisma 的枚举
  类型），所以这一子域迁移**不需要补 ACL**，只是目录与形状归属。
  | 原 | 新 |
  | --- | --- |
  | `event-review.controller.ts` | `adapters/http/controllers/event-review.controller.ts` |
  | `dto/event-review-{list-query,response}.dto.ts` | `adapters/http/dto/event-review-{list-query,response}.ts` |
  | `services/event-review/{facts,changes,actions,next-step,review}.service.ts` | `application/read_models/event-review/*.ts` |
  | `services/event-review/fact-arguments.ts` | `application/read_models/event-review/fact-arguments.ts` |
- **新增 `application/ports/event-review.ts`**：读模型要返回 `EventReviewData` 等
  形状，而 `ddd-application-no-infra-or-adapters` 禁止应用层 import 投递层。
  按 `user-settings` 的既有解法，形状归应用层、DTO 反向钉住。
- **新增形状镜像守卫** `adapters/http/dto/event-review-response.spec.ts`（12 条）：
  对 12 个子形状逐一做**双向** `expectTypeOf().toEqualTypeOf()`。单向
  `satisfies` 只能发现「应用层缺字段」，**发现不了「schema 加了字段而读模型从不
  填充」**——那正是最容易发生的漂移方向（改契约先动 schema），且序列化后是
  `undefined`，会让把该字段标注为非空的生成客户端炸掉。
- **守卫抓到一次真实的形状分歧**：初版把 `facts` 写成数组（`facts[]`），编译
  立刻报错——实际是**单个对象**（`section.facts?.arguments` 直接访问即证据）。
  这正是写守卫而不是「目测一致」的价值。
- **接口声明为可变而非 `readonly`**：`z.infer` 产出可变对象类型，加 `readonly`
  会让镜像断言因与契约无关的理由失败。不可变是读模型纪律，不是 wire 形状。
- **`exactOptionalPropertyTypes` 一处**：`EventReviewListQuery` 的可选键显式写
  `| undefined`（`z.infer` 的可选键是 `T | undefined`，不等于裸 `T`），与
  `user-settings` 的 `UpdateUserSettingsCommand` 同一处置。
- 基线 3 条**改名不新增**（174 → 174）：`dto/event-review-list-query.dto.ts`、
  `services/event-review/{actions,changes}.service.ts` 的 `no-magic-numbers`
  随文件移动改路径。先用 `git stash` 跑了一次基线确认这 3 条在移动前就存在，
  再改名，**不是把新债塞进基线**。
- 验证：`typecheck` 0 error、`lint:check` 0 error（2 个既有 style warning 未变）、
  `arch:check` **174 条无新增**、`docs:verify` 与 `docs:links` 通过；
