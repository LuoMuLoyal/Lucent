# 2026-10-31

## feat(layouts): 生成式界面端点 `POST /layouts/:surface/generate`

### 为什么

客户端已落地生成式 UI 的渲染链路（`Luminous` A7a：`genui` + 受限 catalog + 三态渲染），
但没有任何后端端点，`generativeStateProvider` 恒为 `idle`，页面上什么都不出现。
本变更补齐服务端：按用户的自然语言指示，让模型在受限词汇表内拼装 A2UI 树并 SSE 流式返回。

计划：`plans/2026-10-31-generative-surface-endpoint.md`（实施完毕文件已删）。

**推翻布局计划的归属判断**：`2026-10-30-user-interface-layouts.md` §4.5 曾把该端点归入
`assistant` 域。判据应是**产物归属**而非实现手段——产物是一份可持久化的界面文档
（与 `PUT` 存的 `payload` 同性质），不是对话消息；`today-analysis` 同样调 LLM 却自成模块。
故落在 `layouts`，并在旧计划留下转引修订。

### 落地

- **`domain/generative/`**（新聚合目录，与 `domain/layout/` 平级）
  - `generation-request.ts` —— surface 可生成性与 prompt 边界；只返回纯失败形状，
    不调用 `createDomainFailure`（`domain/` 不得 import 值符号）。
  - `surface-policy.ts` —— **安全边界**：领域组件只接受引用键，任何数值一律判违规
    （编造健康数值的直接阻断）；catalog 外组件（`Button` / `TextField` / 表单）拒绝；
    `finding` 只接受 `findingId`，文案属性一律在白名单外。
- **`application/`** —— `generate-surface.ts`（校验 → 可用性 → 生成 → 准入）
  与 `ports/surface-generator.ts`（模型端口）。
- **`infrastructure/llm/`** —— `LlmSurfaceGenerator` 继承 `BaseLlmGeneratorService`
  （熔断 / 重试 / 指标 / OTel span 全部复用）；提示词内联词汇表与语言规则。
- **`adapters/http/`** —— 控制器新增 SSE handler（`operationId: generateLayoutSurface`），
  DTO 与流式响应 schema 带 `describe` + `example`。
- **`common/llm/generators/base-llm-generator.service.ts`** —— 新增可选 `onPartial`
  回调（默认 no-op，既有调用方零影响），供按元素转发的生成器使用。
- **`common/api/problem-catalog.ts`** —— 新增 `GENERATIVE_SURFACE_UNSUPPORTED`(400)、
  `GENERATIVE_PROMPT_EMPTY`(400)、`GENERATIVE_PROMPT_TOO_LONG`(422)、
  `GENERATIVE_OUTPUT_REJECTED`(502)，双语 i18n key 已补。

### 三个设计结论

1. **整次失败而不是剔除坏组件**：剔除等于替模型猜意图；最危险的一类（编造数值）
   被悄悄删掉后，剩余内容会显得像完整结论。
2. **不落库**：生成物是可重生成的展示缓存，为它建表 + 版本号 + 冲突合并，
   是在为缓存付权威副本的代价。
3. **语言跟客户端**：错误文案与**模型生成的展示文字**都由 `Accept-Language` 决定；
   进提示词前归一化（浏览器会发加权串）。「值」与「键」分开——展示文字跟随语言，
   `component` / `kind` / `kinds` / `range` / `findingId` 保持固定 ASCII。
   `finding` 文案来自后端原文，不翻译。

### 实现时发现的一处设计修正

**请求级校验必须在 `prepareSse` 之前。** 初版把 `validateGenerationRequest` 放在流内，
结果「prompt 为空」「surface 不可生成」都退化成 `event: error` 帧——HTTP 状态已经是 200，
只看状态行的客户端或代理会把一个畸形请求当成成功。现在形状校验在开流前跑并抛
`DomainFailureException`（真正的 400/422）；只有生成期失败（模型不可用、产出未过准入）
才留在流内。e2e 已按此断言。

### 顺带修复

`domain/layout/layout.ts` 同样把 `createDomainFailure` 当作值导入，违反
`ddd-domain-purity`；改为返回纯失败形状后 `arch:check` 的既有观察项一并消除。
