# 2026-11-10

## feat(medicines): 新增单药邻域图端点 `GET /medicines/:id/network`

单药分析页（`Luminary/apps/lumine`）的关系网络区块需要后端提供「限流后的邻域图」。
计划见 `Luminary` 仓的单药分析计划（跨仓引用，不走本仓 plans 前缀） §6.1 / §3.4。

### 为什么不用已有的 9 个图关系端点

那 9 个走 Neo4j，给的是**有语义的结论**（机理链、级联、替代药）；这里要的是
**原始邻域图**用于绘制，两者不重复。且 dev 未配置 `NEO4J_*` 时那 9 个一律返回
`status: unavailable`，单药页第一版不能依赖它们。本端点走 Postgres，自给自足。

### 领域：`domain/relations/network.ts`

- `DEFAULT_NEIGHBOUR_LIMIT = 30` / `MAX_NEIGHBOUR_LIMIT = 100`；只支持 `depth = 1`
  （相互作用图深度 2 是平方级，`DB00176` 的 2,249 邻居各展开一次即百万级边）。
- `splitNeighbourBudget`：**靶点优先、相互作用补足余额**。初版把 `limit` 分别下发给
  两条查询，`limit=100` 实际返回 103 个节点（100 + 3 靶点）——契约的上限被静默突破。
- `countTruncated`：截断数 = 真实度数 − 已展示数，不用第二趟查询，也不会出现
  「截断数与总数各算一套」。
- `buildNetworkGraph`：把 `ordering: drugbank_id_asc` 写进响应，如实声明**不是**
  重要性排序。

### 持久层：`infrastructure/persistence/network.ts`

三条规则全部来自实测（dev 库全量数据：19,842 药 / 2,911,156 相互作用 / 34,441 靶点边）：

1. **度数用 `count(*)`**：走 `(drugbank_id, interacts_with_id)` 唯一索引的 Index Only
   Scan，实测 **2.4 ms**。详情接口对相互作用是 `take: 200`，那个长度不是度数。
2. **邻居按索引序截断**：`ORDER BY interacts_with_id LIMIT n` 走 Index Scan 流式取前 n，
   实测 **0.086 ms**。曾按「伙伴自身度数降序」取 Top-N，2,249 个邻居每个都要一次度数
   统计，单条查询 **757 ms**（N+1 的 SQL 形态），已放弃——代价是选择依据变成 id 字典序，
   由 `ordering` 字段对客户端如实交代。
3. **`inCatalogue` 单独查**：`drugbank_drug_interactions.interacts_with_id` 刻意不建
   外键（伙伴可能已被上游下线）。用 JOIN 判断存在性会把这些库外伙伴静默丢掉，
   导致边数与 `degree` 对不上。

### 应用层与契约

- `application/ports/network.ts`（`MedicinesNetworkReader`）：
  `degree` 必须来自 `count(*)`，截断发生在 SQL，`center: null` 表示 404。
- `application/use_cases/read-network.ts`：上限二次钳制；中心不存在 → `RESOURCE_NOT_FOUND`
  （与详情端点同码）。`source=cn` 返回空图但**仍校验药品存在**——对不存在的 id 返回
  200 空图等于宣称「这个药存在且没有关系」。
- `adapters/http/dto/network.ts`：zod 4 Standard Schema，`.strict()`；`truncated` 与
  `ordering` **无默认值**（它们是「这张图是否诚实」的声明，不能省）。
- 控制器挂在 `MedicinesController`（`@Public()`，药物知识是公共只读数据），
  `operationId: getMedicineNetwork`，响应 schema 经 `registerResponseSchema` 登记。

### 验证

- 单测：`domain/relations/network.spec.ts` 15 条（预算分配、截断算术、空图、常量关系）。
- e2e：`test/e2e/medicines/medicine-network.e2e-spec.ts` 7 条（未知 id 404、`limit` 越界
  与 0 为 400、`depth=2` 为 400、未知查询参数 400、`source=cn` 不存在仍 404、非法
  `source` 400）。test 库药品表为空，故 e2e 只验契约与校验，不验图内容。
- 真实数据（dev 库）实测：`DB00176` → 度数 2,249 / 3，`limit=30` 返回 30 个节点
  （3 靶点 + 27 相互作用）、`truncated=2222`；`limit=100` → 100 个、`truncated=2152`；
  `limit=2` → 2 个（靶点优先），符合「总数封顶 + 靶点优先」。
- `pnpm typecheck`、`pnpm lint:check`（0 error）、`pnpm test`、`pnpm export:openapi`
  （Paths 162 / Schemas 422，含 `getMedicineNetwork` 与 `MedicineNetworkResponse`）。
- 契约产物 `docs/reference/generated/openapi.json` 已随代码更新。
