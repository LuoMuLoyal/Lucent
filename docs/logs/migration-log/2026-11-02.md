# 2026-11-02

## fix(admin-console): 异步路由返回 reply，修复管理控制台空白页

### 为什么

`/admin` 首屏 HTML（5693 B）与所有 >4 KiB 的 SPA bundle 在浏览器里都是空响应：
响应头是 `content-encoding: gzip` + `content-length: 0`，`#root` 与 `<script>` 都不存在，
页面纯白。`/metrics`（约 19 KiB）同样返回空 body。

根因是 Fastify v4 起的 promise 卫生规则：`async` handler 只调用 `reply.send()`、
不返回 reply 时，Promise 解析为 `undefined`，Fastify 随后会再 `send(undefined)`。
`wrap-thenable` 只有在 `reply.sent === true`（响应已冲刷）时才忽略这次空发送。
`@fastify/compress` 对 ≤4 KiB 的 payload 走**同步**压缩路径（onSend 同步完成、
`reply.sent` 已置位），所以小响应看起来正常；超过 4 KiB 改走**流式**路径，
`reply.send(stream)` 尚未完成时 handler 的 Promise 先解析，`send(undefined)` 抢先落地，
压缩流被丢弃 —— 于是 4096 B 成了分水岭：3898 B 的 chunk 正常，4100 B 起全部为空。

`src/admin-console/services/console-router.service.ts` 的通配路由与
`src/setup-app.ts` 的 `/metrics` 都是这种「async + 只 send 不 return」写法；
全局压缩（2026-10-16 引入）把这个问题从潜伏变成每次访问必现。

### 落地

- `console-router.service.ts`：通配 handler 的两个分支改为 `return reply...send(...)`，
  并就地注释为什么必须返回（否则后来者很容易又「简化」掉）。
- `setup-app.ts`：`/metrics` 及其两个 401 分支同样改为 `return reply...send(...)`。
- `console-router.service.spec.ts`：新增回归用例，用真实 `fastify` +
  `@fastify/compress` 注入 8 KiB HTML 并带 `accept-encoding: gzip`，断言
  `rawPayload` 非空且 gunzip 后与原文一致。改前该用例必然失败（`content-length: 0`），
  改后通过。

### 验证

- 直接对运行中的 dev server 带 `Accept-Encoding: gzip` 请求：`/admin/` 解压后 5693 B，
  `index-D5XgkHNR.js` 36858 B，`chunk-NAVWDHVN-tci6xKse.js` 475453 B，
  `index-Dv0_Md75.css` 112453 B，`/metrics` 19291 B，均为 `Transfer-Encoding: chunked` 正常压缩。
- 无头 Chrome 打开 `http://127.0.0.1:3000/admin/`：`#root` 已渲染并跳转到
  `/admin/sign-in?redirect=%2F`，登录表单文案可见（改前 DOM 全空、无 script 标签）。
- `pnpm test -- src/admin-console`：22 项通过；`pnpm typecheck` 通过；
  `pnpm build` 0 issues；改动文件 `eslint --max-warnings=0` 与 `oxlint` 均 0 告警。

## fix(admin-web): 修复漏斗面板首屏必现的 500 错误页

### 为什么

打开 `/admin/metrics/funnel` 必定显示管理端自带的 500 错误页（`GeneralError`，
`Oops! Something went wrong`），页面骨架与侧栏全部消失，且网络面板里**看不到**
`GET /api/v1/admin/metrics/funnel` 请求——后端接口本身 200，问题在首屏渲染。

根因是 Refine `useCustom` 的行为：查询解析前 `result.data` 是**空对象**而不是
`undefined`（`data: queryResponse.data?.data || EMPTY_OBJECT`，见
`@refinedev/core` 的 `useCustom` 实现）。漏斗页把 `result.data` 直接当作
`FunnelData`，`{funnel && …}` 对 `{}` 恒真，于是 `funnel.window.dateFrom` 在
**请求发出之前**就抛 `TypeError: Cannot read properties of undefined (reading
'dateFrom')`，被根路由 `errorComponent` 接住，渲染成 500 页。
概览页早已按这个语义处理（其注释即写「Refine hands `result.data` an empty object
until the query resolves」），漏斗页 2026-10-19 落地时没有沿用同样的守卫。

### 落地

- `admin/src/features/metrics-funnel/index.tsx`：`useCustom` 的类型改为
  `Partial<FunnelData>`，新增 `isFunnelData` 类型守卫（`window` / `totals` /
  `optional` 三段齐全才算拿到响应）；`funnel` 在守卫通过前保持 `undefined`，
  与概览页同一口径。骨架屏、错误卡片、小样本抑制提示因此都能正常走各自分支。
- 重建 `admin/dist`（该目录被 `admin/.gitignore` 忽略，不进提交，dev server 直接从
  磁盘读取，必须重建才生效）。

### 验证

- 无头 Chrome 加载 `/admin/metrics/funnel`（真实接口 200）：渲染标题、五个阶段卡片、
  窗口 `2026-10-04 → 2026-11-02`、小样本抑制提示与空日表，控制台 0 error，
  且能观察到 `GET /api/v1/admin/metrics/funnel` 发出并返回 200；改前同一路径渲染的是
  500 页且该请求从未发出。
- 无头 Chrome 把漏斗接口 stub 成 400：页面显示「Unable to load the funnel…」错误卡片，
  不再落到根错误边界，控制台 0 error——错误路径同样不再崩页。

## fix(admin-web): 依赖状态页错误路径不再渲染 500 页

### 为什么

依赖状态页与漏斗页同一根因：Refine `useCustom` 在查询解析前把 `result.data` 填成
**空对象**，`status` 因此恒为真值；接口报错时 `isLoading` 已是 `false`，
`status[dependency.key].enabled` 对 `{}` 取不到值，抛 `TypeError` 后被根路由
`errorComponent` 接住，渲染成 500 页——页面自带的「Unable to load dependency
status.」错误卡片反而永远看不到。

## feat(admin-web): 队列入口自动携带访问令牌完成面板握手

### 为什么

侧栏 `Queues` 是裸外链 `<a href="/admin/queues">`。bull-board 的 UI 与自身 API 都无法
附加 `Authorization`，而管理端登录走 Bearer、不落会话 cookie，于是点进去只能拿到
`401 {"error":"AUTH_REQUIRED"}`。后端 README 记录的 `?access_token=<jwt>` 握手只有
手工拼 URL 时才用得上，控制台自己的入口反而用不了。

### 落地

- `admin/src/components/layout/data/external-links.ts`（新增）：`externalNavHref` 对
  声明了 `externalAuth: 'accessToken'` 的外链条目追加 `?access_token=`，其余条目原样
  返回。
- `admin/src/components/layout/types.ts` / `data/sidebar-data.ts`：`BaseNavItem` 增加
  `externalAuth?: 'accessToken'`，`Queues` 条目声明之。
- `admin/src/components/layout/nav-group.tsx` / `components/command-menu.tsx`：外链
  href 统一经 `externalNavHref` 生成——侧栏与命令面板（`window.open`）走同一入口。
- `admin/README.md`（Screens 段）与 `src/modules/admin/README.md`（队列面板鉴权条）：
  记录这次握手由控制台入口自动完成。
- 重建 `admin/dist`（gitignore，dev server 从磁盘读取）。

已知边界：交付的 token 是控制台内存里的那一个。标签闲置超过 `JWT_ACCESS_TTL` 后再点
队列入口，握手会 401；任意一次控制台页面操作（含刷新）都会换到新 token。不额外做点击前
强制续期，避免为新开标签引入异步等待与弹窗拦截。

### 验证

- 无头 Chrome + 真实 dev server：概览页侧栏 `Queues` 的 href 含 `access_token=`
  （完整长度 407）；按该 href 打开 → 302 到 `/admin/queues`，面板 200、标题
  `Lucent Queues`、队列列表可枚举；控制台 0 error。改前同一入口返回 401 JSON。
- `admin` 侧 `pnpm build`（含 `tsc -b`）通过；`pnpm lint` 0 error；
  `pnpm format:check` 全绿。
