# 2026-11-02

## fix(admin-console): 异步路由返回 reply，修复管理控制台空白页

### 为什么

`/admin` 首屏 HTML（5693 B）与所有 >4 KiB 的 SPA bundle 在浏览器里都是空响应：
响应头是 `content-encoding: gzip` + `content-length: 0`，`#root` 与 `<script>` 都不存在，
页面纯白。`/metrics`（约 19 KiB）同样返回空 body。

根因是 Fastify v4 起的 promise 卫生规则：`async` handler 只调用 `reply.send()`、
不返回 reply 时，Promise 解析为 `undefined`，Fastify 随后会再 `send(undefined)`。
`wrap-thenable` 只有在 `reply.sent === true`（响应已冲刷）时才忽略这次空发送。
`@fastify/compress` 对 ≤4 KiB 的 payload 走**同步**压缩路径（onSend 同步完成、
`reply.sent` 已置位），所以小响应看起来正常；超过 4 KiB 改走**流式**路径，
`reply.send(stream)` 尚未完成时 handler 的 Promise 先解析，`send(undefined)` 抢先落地，
压缩流被丢弃 —— 于是 4096 B 成了分水岭：3898 B 的 chunk 正常，4100 B 起全部为空。

`src/admin-console/services/console-router.service.ts` 的通配路由与
`src/setup-app.ts` 的 `/metrics` 都是这种「async + 只 send 不 return」写法；
全局压缩（2026-10-16 引入）把这个问题从潜伏变成每次访问必现。

### 落地

- `console-router.service.ts`：通配 handler 的两个分支改为 `return reply...send(...)`，
  并就地注释为什么必须返回（否则后来者很容易又「简化」掉）。
- `setup-app.ts`：`/metrics` 及其两个 401 分支同样改为 `return reply...send(...)`。
- `console-router.service.spec.ts`：新增回归用例，用真实 `fastify` +
  `@fastify/compress` 注入 8 KiB HTML 并带 `accept-encoding: gzip`，断言
  `rawPayload` 非空且 gunzip 后与原文一致。改前该用例必然失败（`content-length: 0`），
  改后通过。

### 验证

- 直接对运行中的 dev server 带 `Accept-Encoding: gzip` 请求：`/admin/` 解压后 5693 B，
  `index-D5XgkHNR.js` 36858 B，`chunk-NAVWDHVN-tci6xKse.js` 475453 B，
  `index-Dv0_Md75.css` 112453 B，`/metrics` 19291 B，均为 `Transfer-Encoding: chunked` 正常压缩。
- 无头 Chrome 打开 `http://127.0.0.1:3000/admin/`：`#root` 已渲染并跳转到
  `/admin/sign-in?redirect=%2F`，登录表单文案可见（改前 DOM 全空、无 script 标签）。
- `pnpm test -- src/admin-console`：22 项通过；`pnpm typecheck` 通过；
  `pnpm build` 0 issues；改动文件 `eslint --max-warnings=0` 与 `oxlint` 均 0 告警。
