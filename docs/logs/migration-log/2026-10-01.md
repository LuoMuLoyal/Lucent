# 2026-10-01

## Better Auth 全面移除,身份层回归 Lucent 自持

### 背景

`better-auth` 于 2026-09-21 由 Dependabot 从 1.7.1 升到 1.7.5(`82e3db5b`)。该 patch
在 `@better-auth/prisma-adapter@1.7.5` 中新增了 Prisma schema 自检:启动后调用
`introspectPrismaDataModel(prisma._runtimeDataModel)` 并与期望 schema diff。Prisma 7 的
`prisma-client` generator 把 `_runtimeDataModel` 生成为 `{"models": {}, "enums": {}, "types": {}}`,
自检因此判定所有表缺失,抛 `SchemaMismatchError`("Missing tables User"),导致**整个 auth
域 100% 返回 503**——生产调用点只有 4 处(`signUpEmail` ×1、`signInSocial` ×2、
`verifyEmail` ×1),其中 `verifyEmail` 实际为死路径(客户端从不签发其 token)。

评估结论:引入该库未覆盖 Lucent 已有的 JWT 签发、argon2 哈希、`user_sessions` 会话、
验证码与错误映射;其 `sessions` 表在 `src/` 中零读取方;一个 patch 升级即可打挂全模块。
故整体移除,身份层由 Lucent 自持。用户明确要求不新增 ADR。

### 变更范围

- **schema**:新增 `prisma/models/account.prisma`,以 Lucent 语义重建 `accounts`
  (issuer / providerId / accountId / password / providerUnionId / providerEmail /
  rawProfile 等),`id` 改为数据库侧 `gen_random_uuid()` 默认值;删除
  `prisma/models/better-auth.prisma`(附带 `sessions`、`verifications` 两表)。
- **迁移**:`prisma/migrations/20260930120000_lucent_owned_identity_accounts`
  删除 `sessions` 与 `verifications`,并为 `accounts.id` 补数据库默认值。
- **新增服务**:`services/identity/identity.service.ts`(`AuthIdentityService`,argon2
  哈希与 accounts 读写、本地用户创建/凭据校验)与
  `services/identity/email-verification.service.ts`(验证 token 签发与消费,
  消费采用先删后写,重复提交即失效)。
- **改写调用点**:凭据注册/登录、密码管理(改/重置/设置密码)、敏感操作重验、
  token 撤销、OAuth facade 与 account 自助管理全部改为调用上述自持服务;
  OAuth 社交登录不再走 `signInSocial`,Apple/Google 分别由各自 provider 完成
  identity token 校验(`GoogleOAuthProvider.fetchProfileFromIdToken` 新增,
  签名走 Google JWKS,复用 `@nestjs/jwt`,不引入新依赖)。
- **删除**:`adapters/better-auth.adapter.ts`、`scripts/spike/better-auth*`、
  依赖 `better-auth` 与 `@better-auth/prisma-adapter`(共移除 21 个包)。
- **环境变量**:`BETTER_AUTH_SECRET` / `BETTER_AUTH_URL` 从 `EnvKey`、校验 schema
  与全部 `.env*` 模板移除(已无任何读取方)。
- **文档**:`docs/reference/environment-variables.md`、`docs/howto/deploy.md`、
  `docs/TODO.md`、`src/modules/auth/README.md` 同步改为自持身份层口径。
  历史迁移日志按 append-only 规则不改写。

### 验证结论

- `pnpm typecheck`、`pnpm lint:check` 通过。
- 单元测试 324 文件 3866 例全通过(改写前先复现了 4 处适配器 mock 与
  2 处 schema 断言失败,逐一改为自持服务语义)。
- auth 与 account 域 e2e 共 95 例全通过;其中 auth 域此前 38 例失败(100% 503)
  归零。Apple 回调对不可验证 identity token 由 503 改判 400——属客户端校验失败
  而非依赖不可用,断言随之更新。
- 全量 e2e 仍有 6 例失败,集中在 CORS 预检、medicines 检索与 testing-support,
  相关文件均在 09-03~09-16 定稿且不引用 auth,与本次变更无关,另行跟踪。
- `pnpm docs:verify` 通过。
