# 2026-10-10

## fix(security): HTTPS 专属响应头改为跟随 PUBLIC_BASE_URL 协议

- 现象:生产管理端 `http://122.9.146.162:3000/admin/` 只返回空白页,`<div id="root">` 始终为空,
  标题与 favicon 正常。`/api/docs` 同样受影响。
- 根因:`@fastify/helmet` 默认 CSP 带 `upgrade-insecure-requests`,而部署是公网 IP 上的纯 HTTP。
  浏览器把同源子资源全部改写成 `https://122.9.146.162:3000/admin/assets/*`,该端口无 TLS 监听,
  于是所有 JS/CSS 加载失败;回环地址被视为 potentially trustworthy origin 不受影响,所以本地开发
  从未复现。用 headless Chrome 抓 netlog 可看到资源请求 URL 全部是 `https://`;去掉该指令后
  (HSTS/COOP/OAC 原样保留)同一份线上产物立即渲染出登录页。
- 变更:新增 `src/common/api/security-headers.ts` 的 `resolveHttpsHeaderPolicy(publicBaseUrl)`,
  `setup-app.ts` 按它注册 Helmet,只有 `PUBLIC_BASE_URL` 是 `https://` 时才下发
  `Strict-Transport-Security`，HTTP 部署则用 `null` 移除 `upgrade-insecure-requests`。
  `src/common/index.ts` 增加 barrel 导出,`src/common/README.md` 的 `api/` 条目同步。
- 验证:新增 `security-headers.spec.ts`(4 条)与 `test/e2e/core/app.e2e-spec.ts` 一条响应头断言;
  用仓库内真实 `@fastify/helmet` 跑 `app.inject` 复核两种策略产出的头(HTTP:无 UIR、无 HSTS;
  HTTPS:与改动前逐字节一致)。全量单测、`pnpm typecheck`、变更文件 ESLint/Prettier、
  `app.e2e-spec.ts`(8 条)通过。
- 生产实例仍是旧镜像,需重新构建 arm64 镜像并在主站 `docker compose up -d --force-recreate app`
  后生效;或将 `PUBLIC_BASE_URL` 改为 `https://` 并前置 TLS 终结,两者选一。
