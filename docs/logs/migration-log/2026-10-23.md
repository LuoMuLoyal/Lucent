## refactor(auth): cookie 会话按 ADR-0024 四层落地

- 背景：上一版把 cookie 会话写在 `controllers/` + `dto/` + `strategies/`，
  是模块内的贫血分层；ADR-0024 把 `auth` 列为第二批迁移，本批只做**新增的那条
  垂直切片**，不动 Bearer/OAuth/密码管理（批次内公开 API 零变化）。
- 四层落位：
  - `domain/session/cookie_policy.ts`：`SessionCookiePolicy` 值对象 +
    `resolveSessionCookiePolicy`。属性推导是**安全策略**（`SameSite=None`
    必须配 `Secure`，而本地 HTTP 存不下 `Secure`），属领域知识，不是 HTTP 细节。
    本文件零 import，满足 domain 纯度。
  - `application/use_cases/cookie_session.ts`：编排五个用例。输入是**应用层自己的**
    `LoginCommand` / `RegisterCommand`，不复用 adapters 的 zod 类型——
    `pnpm arch:check` 的 `ddd-application-no-infra-or-adapters` 会拦。
  - `adapters/http/`：`cookie.controller.ts`（只做 HTTP）、`dto/session.ts`（zod 契约）、
    `presenters/session.ts`（决定什么可以出网）、`session_cookies.ts`
    （`Set-Cookie` 序列化）。
  - `infrastructure/`：本切片无需新增实现——cookie 是 HTTP 投递关注点，
    不是持久化或外部系统。
- 顺带去掉 `AccessTokenReader`：轮换后需要「会话属于谁」，而
  `AuthTokenService` 的会话记录里本来就有 `user`。新增 `refreshWithUser()`
  直接返回它，因此不必为了读回 `sub` 去解一次刚签发的 JWT。`refresh()` 保留为
  token-only 视图，Bearer 调用方不受影响。
- 删除 `common/api/session-cookie.ts`：属性归 domain，序列化归 adapters，
  它已无独立职责。`SESSION_COOKIE_NAME` 等常量随之下沉到 domain。
- 契约零变化：`pnpm export:openapi` 后 `openapi.json` **无 diff**（150 paths /
  388 schemas），operationId 仍是 `registerSession` / `loginSession` /
  `refreshCookieSession` / `logoutSession` / `getMe`。`plans/_naming-lookup.json`
  的键随控制器改名同步。
- 验证：`pnpm typecheck`、`pnpm lint:check`、`pnpm arch:check`（205 entries，
  基线未新增）、`pnpm format:check` 全通过；`pnpm test` 4238 passed；
  `test/e2e/{auth,admin}` 144 passed。

## fix(auth): 补全 /auth/me 与 captcha 的 OpenAPI 响应元数据

- 起因：Lumine 改用由 `openapi.json` 生成的类型化客户端后，`/auth/me` 的 200 响应
  在契约里是 `content?: never`——生成的类型因此拿不到用户资料形状。这是**契约缺口**，
  不是客户端问题：`@SerializeOptions({ schema })` 只管出站校验，不会注册响应体。
- `/auth/me` 补 `registerResponseSchema`（componentName `SessionUser`）。
- `captchaSchema` 补 `example` 元数据：`test/contract/openapi-metadata.e2e-spec.ts`
  要求每个 2xx JSON 响应 schema 至少带 `example` 或显式 `nullable`。该用例在本日
  之前一直是红的（存量问题），本次一并通过。
- 契约变化：`openapi.json` +66 行（新增 `SessionUser` 组件、`CaptchaResponse`
  两个字段的 example），paths 仍 150、schemas 388 → 389。
- 验证：`pnpm export:openapi`；`test/contract` 43 passed（此前 1 failed）；
  `pnpm test:e2e:ci` 589 passed（38 files）。
