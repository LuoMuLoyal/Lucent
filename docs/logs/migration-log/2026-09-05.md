# 2026-09-05

## chore(contract): openapi-generator 版本提升到 7.25.0

`openapitools.json` 的 generator-cli version 由 7.22.0 升到 7.25.0。OpenAPI 3.2 双轨方案经实测不可行:dart-dio 生成器对 OAS 3.1/3.2 的 required+nullable 字段有上游已知 bug(openapi-generator #21510/#23866),任一表达(`anyOf [T,null]`、`nullable:true`、数组 type)都会把可空字段生成成非空 Dart 类型,影响面达全量模型;且生成器输入侧仍不支持 `openapi: 3.2.0`(validate 报 attribute openapi is unexpected),bootstrap 侧降级折叠又引入结构漂移。最终决定放弃版本升级,spec 保持 OAS 3.0 直出,export-openapi 维持既有 openApiSchema 3.0 兼容过滤,只交付生成器版本提升与 Luminous 侧 dio 升级。
验证:`pnpm export:openapi` 通过且导出 spec 与升级前零 diff;lint 与 typecheck 通过,单测 54 项通过。客户端再生成与 dio 升级见 Luminous 当日迁移日志。

## refactor(api): OpenAPI 组件名与 operationId 语义化改革 (AIP-190/136)

Lucent OpenAPI 契约命名改革一次性迁移:143 个 operationId 从机械名(`<Controller>_<action>_v1`)改为领域语义 `VerbNoun` camelCase(如 `accountControllerChangeEmailV1` → `changeEmail`、`reportsControllerGenerateSummaryAsyncV1` → `enqueueSummaryGeneration`),全局唯一 0 冲突(operationIdFactory 注入命名查找表 + Set 去重断言)。

- 组件名去机械后缀:响应组件 81 个去 `Dto`(`AccountResponseDto` → `AccountResponse`)、请求体组件 73 个改为 `<MethodName>Request`(`AccountControllerChangeEmailV1Request` → `ChangeEmailRequest`);`ProblemDetailsDto`/`SseProblemDetailsDto` 按 Task 5 决策保留(RFC 9457 稳定错误契约,决策固化于 response-schema.registry.ts 注释)。
- 内联对象提升:export-openapi.ts 的 `promoteInlineObjects` 扩展为结构性自动规则(非白名单)——对象属性内联、顶层数组 items、`oneOf`/`anyOf`/`allOf` 组合分支内对象、嵌套数组 items 全部提升为 `<Parent><Field>` 命名组件(180 处),从根上消除 dart-dio 的 `_inner`/`_one_of_` 派生名;跳过 `additionalProperties` 自由 Map(避免 `$ref` 与 `additionalProperties` 并存的非法 schema)。
- 契约产物:`docs/reference/generated/openapi.json` 现为 123 paths / 337 schemas,0 个 `Controller`/`V1`/`_inner`/`_200_response` 机械名,0 悬空引用。
- 受影响测试同步:`test/contract/contract.e2e-spec.ts`、`today-analysis.contract.spec.ts` 更新为新组件名。

验证:Lucent `pnpm build`、`pnpm test:ci`(314 文件 3670 用例)、`pnpm lint:check`(0 errors)、`pnpm export:openapi` 全部通过。Luminous 侧客户端重生成与调用点迁移见 Luminous 当日迁移日志。
