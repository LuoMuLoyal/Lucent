### 订正：`pred0` 不是 0–1 概率

原 §2.2 写「`pred0` ≥0.9 占 35.6%，<0.5 占 53.8%」并据此论证「不能按 0.5 过滤」。抽样

  两者相关系数 **−0.952**。

因此原结论「保留原始 `pred0` 落库、阈值交给展示层」**改为**：阈值一律走 `pred1`；
`pred0` 只作溯源，并以可空列 `pred0_raw` 落库，避免与真实低分混在一起。§4.2 的
Prisma 模型、§五 第 8 步、§六 风险表、§八「不做什么」同步改写。

### 三个刻意的取舍

1. **没桥就是 404，不是 200 + `[]`。** DrugBank 只有 8.2% 的条目带 RxCUI（配对级

2. **`limit` 越界是 400，不静默钳制。** 与 `/network` 端点同一口径：

3. **不合并同一药物经多个 CUI 的结果为多条。** 一个成分 CUI 可桥到多个 DrugBank 行
   （盐型、复方），一个药也可经多个 CUI 出现。反向查询按**药物**去重，
   `labelCount` 相加、`confidenceMax` 取最大。

## docs(todo): 撤掉 OnSIDES 成分别名表项（实测判定不做）

### 为什么撤

原计划与 TODO 都写「补一张 191 行的成分别名表即可回收 7.38% 未映射配对」。用全量数据
（不是 dev 库的 200 行样量）实测后，这个判断有两处错，结论是**不做**：

1. **OnSIDES 自身数据能救的部分几乎为零。** 直觉上 DrugBank 存的临床药品 CUI 应该
   能经 `vocab_rxnorm_product` + `vocab_rxnorm_ingredient_to_product` 回溯成成分 CUI。
   实测：5,793 个带 RxCUI 的药里只多救回 **8 个**，其余 4,162 个的 CUI 不在 OnSIDES
   的 product 词表内。
2. **缺口不是 191 个成分，是 22 个。** 按配对量计：总计 2,134 万配对，覆盖 91.83%，
   未覆盖 8.16%（174 万）。未覆盖中 **90% 只由 22 个成分贡献**——dasatinib、atorvastatin、
   tacrolimus、lisinopril、azithromycin、valproate、amoxicillin、piperacillin、risedronate、
   docetaxel、clavulanate 等常用药。根因确认是粒度（DrugBank 记 `1546019`，OnSIDES 记
   `475342`），且**两边药名逐字一致**——真要做也该是导入时按名称精确匹配生成映射，
   不是手工维护一张表。

### 不做的理由

这不是「做不到」，是「现在不该做」：三个端点目前**没有任何调用方**（客户端尚未接线），
先给一个尚未被消费的查询补覆盖率，换不到用户可见行为。等客户端接上、确认这个数据源
真的有人用，再按实测结论重启——前提是走名称匹配生成，别手工维护别名表。

### 清理

临时分析脚本（4 个 `onsides_*probe*.py` / `onsides_gap_names.py`）已删，结论留在本条与
TODO。这些脚本读过全量 parquet 与 693 万行 CSV，留在仓库里会变成没人维护的死代码。

### 验证

`docs:verify` / `docs:links` 通过；`scripts/import/medicine/parsers/` 下只剩正式解析器。

## feat(layouts): A2UI 1.0，词汇表由客户端下发并新增交互回合端点

一次生成由「客户端说布局怎么长」变成「客户端说它有哪些组件、agent 现场拼一棵能点的

### 契约

```text
POST /layouts/:surface/generate
  body: { prompt, range?, capabilities? }
POST /layouts/:surface/turn
  body: { messages, document: { messages, dataModel? }, capabilities? }
→ 两者都是 SSE 四帧：chunk / result / error / done
```

| operationId             | 端点                              |
| ----------------------- | --------------------------------- |
| `generateLayoutSurface` | `POST /layouts/:surface/generate` |
| `runLayoutSurfaceTurn`  | `POST /layouts/:surface/turn`     |

### 删掉的东西

- **`domain/generative/surface-policy.ts`** 整份删除。它守着三条 v0.9 时代的规则
  （禁数值、禁写动作、finding 只认 id）。1.0 起客户端 catalog 全量注册，agent 下发的
  Button / TextField 本来就是要点的；那三条规则同时失去依据与执行对象。
- **`test/contract/generative-vocabulary.e2e-spec.ts`** 删除。它守的是「服务端词表 =
  客户端词表」，而服务端现在不存词表。

### 换上的东西

`domain/generative/a2ui-envelope.ts`：只做结构检查 —— 每条消息是对象、`version` 为
`"1.0"`、恰好一个 body key（六个之一）、有 `createSurface`、有 `id == "root"` 的组件。
违规仍让**整次失败**（`GENERATIVE_OUTPUT_REJECTED`，502），理由与旧口径一致：半棵能显示
的树比一块明确的失败更难排查。

### 词汇表：客户端下发

`capabilities` 是 renderer capabilities 文档，提示词的组件段落**由它生成**
（`prompts/surface.ts` 的 `summariseCapabilities`）。服务端只做三条形状检查：是对象、
可序列化、序列化后 ≤ `GENERATIVE_CAPABILITIES_MAX_BYTES`（256 KiB）。**不看组件名，
不看属性。** 客户端没发 capabilities 时提示词只说「按协议用通用布局组件」，不编一份
兜底清单——那会重新变成第二份事实源。

### 交互回合：无状态

`/turn` 每次带完整文档与渲染端产出的消息。服务端不建会话：重启不丢、多设备各自继续、
没有过期与串会话要推理。**`result` 是完整序列而不是增量**，客户端覆盖同一 surface，
丢一帧能自愈。

### 新增错误码

**DTO 的 `messages` 刻意不加 `.min(1)`**：schema 层的下界会把空回合挡成通用的
`VALIDATION_FAILED` 400，客户端就丢失了「这次交互没带操作」这条信息。这条是被 e2e 抓

## feat(assistant): OnSIDES 不良反应查询接入工具与 MCP

把上一轮落地的 OnSIDES 查询接到 assistant 的工具层，并作为知识检索组的一员暴露
给 MCP 客户端。

### 一个工具，三个方向

新增 `search_adverse_reactions`，用**必填** `direction` 区分三个查询方向：

| direction       | 键           | 回答                               |
| --------------- | ------------ | ---------------------------------- |
| `by_drug`       | `drugbankId` | 这个药的说明书声明了哪些不良反应   |
| `by_ingredient` | `rxnormCui`  | 这个成分的说明书声明了哪些不良反应 |
| `by_reaction`   | `meddraId`   | 哪些药的说明书声明了这条反应       |

**为什么不拆成三个工具**：三个近乎同名的兄弟工具会让模型频繁选错，而它们回答的是
同一个问题（「说明书对这项证据怎么说的」）。HTTP 层保留三个端点是对的——它们是三个
不同的资源；工具层的消费者是模型，判据不是资源边界而是「模型能不能读一行描述就选对」。

### 空结果必须说清是哪一种空

`by_drug` 空有**两个完全不同的原因**：要么这个药没有 RxNorm 交叉引用（DrugBank 行
里 91.8% 是这种情况），要么它的成分真没有声明。前者被读成「这药没有不良反应」是这
个工具最危险的误读，所以 envelope 的 `coverage.reason` 直接写出桥接覆盖率，而不是
给一个干净的空列表。这条有测试。

同样，`direction` 给了但键没给，返回的 envelope 会**点名缺哪个键**，而不是静默空结果
——「问错了」和「查不到」是两句话。

### 三层接线（缺一层就静默失效）

| 位置                                                     | 内容                                                                                                          |
| -------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------- |
| `domain/policies/tool-permission.ts`                     | `TOOL_NAMES` / `READ_TOOL_NAMES` / `TOOL_REQUIRED_SOURCES`（空：公共知识，不读用户数据）/ `TOOL_DESCRIPTIONS` |
| `adapters/acl/tools/shared/tool-definitions.ts`          | JSON Schema（模型看的），`limit` 上界读 `medicines` 的 `MAX_REACTION_DRUG_LIMIT`                              |
| `adapters/agent/tool-bridge.ts`                          | zod schema（StructuredTool 用的），同一份常量                                                                 |
| `adapters/mcp/tool-schema.ts` + `domain/mcp/exposure.ts` | MCP 暴露与标题                                                                                                |

工具名进 `TOOL_NAMES` 但漏了 `READ_TOOL_NAMES`，模型永远绑不到它；漏了
`tool-definitions` 的参数声明，模型只能传空对象。两道都不报错，只是不工作。

`KNOWLEDGE_TOOL_NAMES` 也加了它：公共知识、无用户数据，结果按
(tool, locale, query+args) 缓存一小时。
