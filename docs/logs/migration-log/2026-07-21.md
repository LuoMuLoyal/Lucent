# 2026-07-21 迁移日志

## 代码审查修复：安全漏洞与性能风险（来源：plans/Lucent-2026-07-21.md）

### 背景

2026-07-20 增量代码审查报告发现 2 个严重问题和 6 个警告问题，涉及设备注册跨用户劫持、调度器内存溢出风险、Cron 重叠执行、通知竞态条件、Redis 限流容错、数据清理批量加载、DTO 类型安全和删除接口语义。

### 修复

#### 🔴 1. 设备注册跨用户劫持漏洞

- `src/modules/user-devices/services/user-devices.service.ts`：`register()` 从 `upsert`（`where: { pushToken }` + `update: { userId }`）改为 `findUnique` + 条件 `create`/`update`。当 `pushToken` 已属于其他用户时抛出 `ForbiddenException`；同一用户重注册时更新元数据但不覆盖 `userId`。
- `src/modules/user-devices/services/user-devices.service.spec.ts`：重写 `register` 测试覆盖新建、同用户更新、跨用户拒绝三种场景。
- `test/e2e/user-devices/user-devices.e2e-spec.ts`：新增跨用户注册返回 403 的 E2E 测试。

#### 🔴 2. 提醒调度器分页查询

- `src/modules/medicine-reminders/services/scheduler.service.ts`：`findDueReminders()` 增加游标分页（`take: 500` + `cursor`），避免全量加载活跃提醒到内存。同时添加 `deletedAt: null` 过滤。

#### 🟡 3. 调度器 Cron 重叠执行保护

- `src/modules/medicine-reminders/services/scheduler.service.ts`：新增 `isDispatching` 守卫标志，前一次 tick 未完成时跳过本次执行并记录告警日志。
- `src/modules/medicine-reminders/services/scheduler.service.spec.ts`：新增重叠保护测试。

#### 🟡 4. 建议推送通知竞态条件

- `src/modules/today-suggestion/services/notification/escalation.service.ts`：将 `findUnique` + `update` 两步操作替换为原子条件 `updateMany({ where: { id, notificationSentAt: null } })`。当 `count === 0` 时说明已被其他并发请求处理，直接返回 `false`，消除 TOCTOU 竞态。
- `src/modules/today-suggestion/services/notification/escalation.service.spec.ts`：重写测试适配 `updateMany` mock。

#### 🟡 5. Redis 限流存储连接失败容错

- `src/config/throttler.config.ts`：将 Redis 连接包装在 `try/catch` 中，连接失败时降级为内存存储并记录 `WARN` 日志，避免单点故障导致应用启动崩溃。
- `src/config/throttler.config.spec.ts`：新增 Redis 构造异常降级测试。

#### 🟡 6. 数据清理避免批量加载用户 ID

- `src/modules/data-retention/services/data-retention.service.ts`：`cleanupSoftDeletedAccounts()` 从 `findMany` + `deleteMany({ where: { id: { in: [...] } } })` 改为直接 `deleteMany({ where: { deletedAt: { lt: threshold }, status: 'deleted' } })`，避免将全部过期用户 ID 载入内存和超长 `IN` 子句。
- `src/modules/data-retention/services/data-retention.service.spec.ts`：更新测试适配直接 `deleteMany`。

#### 🟡 7. RegisterDeviceDto 类型安全

- `src/modules/user-devices/dto/register-device.dto.ts`：导出 `DevicePlatform` 枚举，将 `platform!: string` 改为 `platform!: DevicePlatform`，使 TypeScript 编译期能校验枚举值。

#### 🟡 8. 删除设备接口语义

- `src/modules/user-devices/services/user-devices.service.ts`：`remove()` 从 `deleteMany({ where: { id, userId } })` + 返回 `boolean` 改为先 `findUnique` 检查存在性和归属，不存在抛 `NotFoundException`（404），跨用户抛 `ForbiddenException`（403），归属正确则 `delete`。
- `test/e2e/user-devices/user-devices.e2e-spec.ts`：更新删除不存在设备预期为 404，跨用户删除预期为 403。

## CI 修复：E2E 测试全量失败与 OpenAPI 契约测试

### 背景

CI 中 27 个 E2E 测试文件全部失败，错误为 `TypeError: Cannot read properties of undefined (reading 'prisma')`。同时契约测试因 `docs/openapi.json` 不存在而报 `ENOENT`。

### 根因

1. **`vitest.e2e.config.ts` 使用 `mergeConfig` 合并基础配置**：`mergeConfig` 会拼接 `include` 数组，导致 E2E 运行时同时包含 `src/**/*.spec.ts`（245 个单元测试）和 `test/**/*.e2e-spec.ts`（28 个 E2E 测试）。在 `singleFork: true` 下，所有文件共享同一进程，单元测试的模块 mock 和环境变更污染了后续 E2E 测试的 `createTestApp()` 调用。
2. **CI 步骤顺序错误**：`pnpm export:openapi`（生成 `docs/openapi.json`）排在 `pnpm test:e2e:ci` 之后，而契约测试在 `beforeAll` 中加载该文件。`docs/openapi.json` 被 `.gitignore` 排除，CI checkout 后不存在。

### 修复

- `vitest.e2e.config.ts`：从 `mergeConfig(baseConfig, ...)` 改为独立 `defineConfig`，显式设置 `include: ['test/**/*.e2e-spec.ts']`，SWC 插件和 `#generated` 别名直接复制到本文件中。
- `.github/workflows/lucent-ci.yml`：将 `Export OpenAPI spec` 步骤移至 `E2E tests` 之前。

### 验证

- 本地运行 `npx vitest run --config ./vitest.e2e.config.ts test/e2e/environment/environment.e2e-spec.ts` 通过。
- 配置仅包含 `test/**/*.e2e-spec.ts`，不再包含 `src/**/*.spec.ts`。
