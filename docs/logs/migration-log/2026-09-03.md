## zod 校验迁移:机制验证与 environment 试点(计划 2026-09-01-nestjs12-upgrade-plan 第三步)

首个模块试点(environment),产出可复制的模块迁移模板与机制结论。

### 机制结论(经验证)

- 参数装饰器 `{ schema }` 元数据由 `StandardSchemaValidationPipe` 消费;已全局注册于 class-validator
  `ValidationPipe` 之后,无 `schema` 元数据的参数为 no-op,两管道可并存过渡,全量 e2e 无回归。
- **OpenAPI zod 直出零配置成立**:Swagger 从参数 schema 元数据自动生成 query/body 参数(schema 级
  type/minimum/maximum/description),移除手工 `@ApiQuery` 后无重复、无缺失。
- 语义映射口径:`.optional()` 对应 `@IsOptional`;`z.coerce.number()` 对应 `@Type(() => Number)` +
  `@IsNumber`(数字字符串可用、非法值报错、空串按 `Number('') === 0`);`.min/.max` 对应 `@Min/@Max`;
  未知键默认 strip(计划默认),拒绝未知键的既有全局语义按端点需要以 `.strict()` 显式保留。
- example 丢失:zod 无原生 example 元数据,description 经 `.describe` 保留;example/nullable 语义补全
  留待 zod-openapi 元数据阶段(见 docs/TODO.md)。

### environment 模块试点

  `@Query({ schema })`,删除重复的 `@ApiQuery` 手写文档。
- e2e 新增 3 个语义用例(非法数字 400、空串 lat 按 0 接受、未知键 400 strict),environment e2e 共 7 例
  通过;模块 unit 25 例通过。
