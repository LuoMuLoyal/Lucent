# 2026-11-28

## feat(monolith): 新增 `THROTTLE_DISABLED` 压测开关

### 背景

压测与故障演练需要把全局限流整个摘掉，而现有两个键做不到：`THROTTLE_TTL_MS` /
`THROTTLE_LIMIT` 只调窗口与配额，`THROTTLE_LIMIT` 的 schema 上限是 **1000**，所以
靠运行时热更新最多把天花板抬到「1000 次/秒/IP」，仍然会在高并发下产出 429。
实测 200 并发打 `/api/v1/health` 时 106/205 是 429，容量结论完全被限流污染。

### 变更范围

新增一个与配额无关的短路开关，把守卫整体跳过：

- `src/config/env/env-keys.enum.ts` — 新增 `THROTTLE_DISABLED`。
- `src/config/env/environment.validation.ts` — `z.enum(['true','false']).default('false')`。
- `src/common/throttler/runtime-throttler.guard.ts` — `canActivate` 首行判定，命中即
  `return true`，既不读快照也不调用 `super`，因此**不产生任何计数**。
- `src/common/throttler/runtime-throttler.guard.spec.ts` — 补 3 条用例：置 true 时
  完全跳过且 `increment` 零调用；显式 false 与未设置时行为不变（仍会 429）。
- `.env.development.example` / `.env.production.example` / `.env.test.example` — 补上
  这一组键。**顺带补了原本就缺的 `THROTTLE_TTL_MS` / `THROTTLE_LIMIT`**：这两项一直
  在代码与文档里存在，但三个模板文件里都没有，属于既存缺口。
- `docs/reference/environment-variables.md` — 补该项说明与白名单行。

### 为什么读 `process.env` 而不是运行时快照

`THROTTLE_TTL_MS` / `THROTTLE_LIMIT` 走 rnacos 运行时文档热更新；本项刻意不走。
压测脚本已经在用 rnacos 调窗口，若这个开关也进快照，脚本就要同时依赖两处状态，
一旦 rnacos 不可达（故障演练会专门停它）开关也会跟着失效。读裸 `process.env`
使它的语义保持「启动期决定、运行期不变」，与 `TRUST_PROXY` 等布尔开关一致。

### 风险与约束

置 `true` 等于摘掉全站限流；本拓扑无反代（`TRUST_PROXY=false`），届时唯一的流量
防线只剩云安全组。因此默认值必须是 `false`，且**只在压测/故障演练环境**打开。
