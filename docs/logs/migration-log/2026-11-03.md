# 2026-11-03

## fix(deploy): 镜像内预置 rnacos 客户端目录属主，避免非 root SDK 崩溃

### 为什么

`compose.yaml` 给 app 挂了 `nacos-client-cache` / `nacos-client-logs` 两个命名卷，
挂载点是 `/home/lucent/nacos` 与 `/home/lucent/logs/nacos`。Docker 创建命名卷时会把
**镜像里该路径的内容连同属主**复制进卷；镜像此前没有这两个目录，于是卷以 `root:root`
初始化，而 app 以 `lucent`(uid 100) 运行。

开启 `RNACOS_ENABLED=true` 后，`nacos-sdk-rust-binding-node` 启动即初始化
`tracing-appender` 的滚动日志文件：

```text
initializing rolling file appender failed: InitError { ... PermissionDenied }
fatal runtime error: failed to initiate panic, ... aborting
```

进程直接 abort，容器崩溃循环——迁移已执行、服务却起不来。2026-11-03 生产更新
（`sha-e962a751`）实测踩到，对两个卷一次性 `chown` 后才恢复健康。

### 落地

- `Dockerfile`（production stage）：`adduser` 之后预建
  `/home/lucent/logs/nacos` 与 `/home/lucent/nacos` 并 `chown -R lucent:lucent
/home/lucent`。目录很小，只是元数据层，不影响镜像体积。
- `compose.yaml`：app 的两个 rnacos 卷挂载点补属主说明，并指向修复命令。
- `docs/reference/deployment.md`：rnacos「持久化」条目补「卷属主」约束与失败形态。
- `docs/howto/deploy.md`：新增「启用 rnacos 前的卷属主修复（存量机器）」，给一次性
  `chown` 命令与验证方式。

### 验证

- 生产实测：未预置目录时容器反复崩溃重启；把两个卷 `chown` 到 `100:101` 后
  `docker compose up -d --force-recreate app` 立即 healthy，`/health/deep` 200。
- 新构建的镜像无需手工干预——命名卷首次创建即继承 `lucent` 属主；**存量卷不会自动
  修复**，按 `docs/howto/deploy.md` 的一次性命令处理。
- 本次改动不改运行时代码与 API 契约，不需要 `pnpm export:openapi`；镜像需下次
  Release 才会带上该修复。

## fix(deploy): 补上主站侧 Neo4j 直连配置（业务图查询）

### 为什么

本版新增的 `/medicines/relations/*` 9 个多跳查询**由 app 直连 Neo4j**（`@neo4j/graphql`

- `neo4j-driver`），与 semantica 的生成式 Cypher/`/reason` 是两条并行路径。这组
  `NEO4J_URI` / `NEO4J_USER` / `NEO4J_PASSWORD` 键在 `environment-variables.md` 里有定义，
  但**主站模板 `.env.production.example` 与部署文档都没写**——按模板部署的新机器永远
  不会启用该能力，9 个端点只会返回 `status: notConfigured`，且没有可循的配置说明。
  2026-11-03 生产外部巡检发现该问题。

### 落地

- `.env.production.example`：在 Semantica 段后补 `NEO4J_URI` / `NEO4J_USER` /
  `NEO4J_PASSWORD` / `NEO4J_DATABASE` / `NEO4J_TX_TIMEOUT_MS`，默认留空（=未启用），
  并注明与 semantica 的关系、跨云填公网地址与 7687 安全组。
- `docs/reference/deployment.md`：「英文侧 OAG」改写为「英文侧 OAG 与业务图查询」，
  明确两条路径；主站 env 键表补 `NEO4J_*`。
- `docs/howto/deploy.md`：§四主站 env 表补一行 `NEO4J_*`（可选、启用条件、未配置表现）。

### 验证

- 生产按新说明补 `NEO4J_URI=bolt://<图库IP>:7687` 后，9 个关系端点从
  `{"status":"notConfigured"}` 变为 `ok`，图查询真正返回数据。
- `pnpm docs:verify` / `pnpm docs:links` 通过。
