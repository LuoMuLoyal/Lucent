# 2026-10-24

## refactor(auth): cookie 会话端点改名，删除 /auth/me，设备清单改走 /auth/devices

- 背景：三处命名问题累积到该处理的程度——`/auth/me` 与 `/account` 是同一份用户资料的
  两个入口；`/auth/session/*`（登录会话）与 `/auth/sessions`（设备清单）只差一个字母，
  operationId `listSessions` 也没体现资源类型；Bearer 与 cookie 两条出口一个单数一个
  复数，看不出是「同一件事的两种投递方式」。
- 路径变更（**破坏性**，Lumine 与 Luminous 需同步重新生成客户端）：
  - `POST /auth/session/{register,login,refresh,logout}` → `POST /auth/sessions/{...}`。
    cookie 会话是**集合上的动作**（refresh 换一个成员、logout 删当前成员），单数读起来像
    「某一个具名会话」。
  - `GET /auth/sessions` → `GET /auth/devices`；`DELETE /auth/sessions/:sessionId` →
    `DELETE /auth/devices/:sessionId`。与登录会话彻底分开，也和运营侧
    `/admin/users/:id/sessions/:sessionId` 分开（用户自助 vs 运营）。
  - **删除 `GET /auth/me`**。账户资料的唯一读入口改为 `GET /account`（account 模块），
    它本来就更全：多 `hasPassword` / `lastLoginAt` / `linkedIdentities`。
- operationId 改为在 `@ApiOperation` 上显式声明，不再靠方法名推导：
  `registerWithCookie` / `loginWithCookie` / `refreshWithCookie` / `logoutWithCookie` /
  `listDevices` / `revokeDevice`。`plans/_naming-lookup.json` 同步（移除已删除的 `getMe`）。
- 响应形状取舍：会话响应里的 `user` 块**保持独立**，不与 `AccountDto` 合并。`hasPassword`
  需要额外查一次 `account` 表（`AuthIdentityService.hasPassword`），登录响应不该为一个
  布尔位多打一次库。两者字段交集一致，会话侧额外有 `emailVerified` 布尔位供登录态直接判断。
- 删除 `CookieSessionUseCase.currentUser()`：唯一调用方是已删除的 `/auth/me`。
- `SessionController.listSessions`/`revokeSession` 改名 `listDevices`/`revokeDevice`
  （控制器方法名跟随端点）；`AuthTokenService.listSessions` **保持不变**——那是仓储层
  概念，与 HTTP 资源名解耦。
- 契约变化：`openapi.json` paths 150→149，schemas 388 不变。Luminous 生成客户端新增
  `SessionResponse` / `SessionResponseUser` / `LoginWithCookieRequest` /
  `RegisterWithCookieRequest` 四个模型。
- 测试：`test/e2e/auth/session-cookie.e2e-spec.ts` 路径常量与断言同步（原 `/auth/me`
  用例改读 `/account`，并断言 `hasPassword`）；`test/security/authorization.e2e-spec.ts`
  的设备端点路径同步。
- 验证：`pnpm typecheck`、`pnpm lint:check`（0 error）、`pnpm arch:check`（205 entries，
  基线未新增）通过；`pnpm test` 全绿，`src/modules/auth` 406 passed；
  `pnpm export:openapi` 重生成（149 paths / 388 schemas）。

## feat(auth): `users.email` 改为可空，允许无邮箱的 OAuth 账号

- 背景：契约一直宣称 `AccountDto.email` 可为 null（注释「OAuth-only accounts may not
  have one」），但 `users.email` 是 `String @unique` 非空，且
  `AuthOAuthService.createOAuthUser` 对无邮箱的 profile 直接抛 `VALIDATION_FAILED`。
  **契约描述了一个 schema 禁止的能力**——微信等提供商不总是返回邮箱，这条路径从来
  走不通。本次让 schema 与契约一致。
- 模型：`prisma/models/user.prisma` 的 `email` 改为 `String?`，`@unique` 保留。
  PostgreSQL 的唯一索引把 NULL 视为互不相等，因此任意多个无邮箱账号可以共存，
  真实地址仍然唯一。迁移 `20261024160000_user_email_nullable` 只做
  `ALTER COLUMN email DROP NOT NULL`，无需回填（存量行都有邮箱）。
- OAuth：`createOAuthUser` 去掉「必须提供邮箱」的拒绝分支，改为 `...($profile.email != null && { email })`
  ——**省略字段**而不是写 null，让 Prisma 不产生列值。
- 查询陷阱（已写进 prisma 注释与迁移注释）：Prisma 的
  `where: { email: undefined }` 会**丢掉过滤条件**、`where: { email: null }` 会匹配
  任意无邮箱行。按邮箱查必须先用非空类型/守卫挡住 null。现有
  `AuthIdentityService.createLocalUser` 的入参是 `email: string`，类型层面已安全；
  `PasswordManagementService` 已有 `if (!user.email)` 守卫。
- 管理员侧取「必须有邮箱」的设计决定，不是数据问题：
  - `AdminAdminsService.toSummary` 遇到无邮箱的受让人抛
    `RESOURCE_CONFLICT`（无法投递、无法审计的管理员不应存在）；
  - `AdminAccessService.getIdentity` 把「无邮箱的管理员」视为无身份（返回 null →
    403），因为这道门在写入时已经拦过，走到这里说明是带外写入。
- 契约：`sessionUserSchema.email` 同步改为可空（它此前是 `z.string()`，与数据库及
  `AccountDto` 都不一致）。`openapi.json` paths 149 不变，schemas 388 不变。
- 测试：新增 `should create a user without an email when the provider discloses none`，
  钉住「省略 email 字段」而非写 null；e2e `sessions.e2e-spec.ts` 的设备端点路径上一批
  漏改，本次一并修正（此前 7 例因 `/auth/sessions` → `/auth/devices` 而红）。
- 验证：`pnpm db:migrate:all` 应用到 dev 与 test 库；`pnpm typecheck`、`pnpm lint:check`
  （0 error）、`pnpm arch:check`（205 entries）、`pnpm docs:verify` 通过；
  `pnpm test` 全绿，`src/modules/auth` 407 passed；`pnpm test:e2e:ci` 592 passed。

## refactor(naming): DDD 层文件分隔符统一为 kebab-case

- 背景：仓库里有 **359 个 kebab 文件、35 个 snake 文件**，而 35 个 snake 文件**全部**
  落在 DDD 四层（`domain` / `application` / `adapters` / `infrastructure`），四层内
  kebab 数为 0。也就是「分隔符取决于你在哪个目录」——一条没有任何工具强制的约定
  自己裂成了两套。起因是 `AGENTS.md` 第 9 条的示例写的是 `account_registered.ts` /
  `on_<event>.ts`，实现时照着示例写成了 `risk_scoring.ts`。
- 变更：`git mv` 重命名 35 个文件（`_` → `-`），全部 import 路径跟随；
  代码注释与模块 README 中引用的文件名同步更正。
  - **不动的**：类名（`PrismaAccounts`）、DI token（`MEDICINES_CACHE_MAINTENANCE`）、
    审计 action 字符串（`admin.content.safety_tip.create`，属线格式）。
  - **不动的**：目录名（`use_cases/`、`read_models/`）——本次只统一**文件**分隔符。
- 规则落地（否则下一个人还会写一个 `_` 文件）：
  - `AGENTS.md` File Naming Rules 新增第 10 条：分隔符一律 kebab，四层不例外；
    第 9 条的示例同步改为 kebab。
  - `AGENTS.md` 的 ADR 规则放开「措辞更正」：新决策仍须新建 ADR，但示例写错、
    与实作不一致这类**措辞**问题允许就地改，前提是在同一条决策下注明修订日期与原因。
  - ADR-0024 §5 补一条说明：记录分隔符统一决定的由来，并标注「2026-10-24 修订」。
- `arch:check` 基线：观察条目按文件路径记录，重命名会让 5 条基线失配。按既定流程跑
  `pnpm arch:baseline:update`，**条目数仍为 205**（只换路径，未新增违规）。
- 验证：`pnpm typecheck`、`pnpm lint:check`（0 error）、`pnpm arch:check`（205 entries，
  基线未新增）、`pnpm docs:verify`、`pnpm docs:links`（84 个 md、47 个文件路径核对）
  通过；`pnpm test` 4244 passed；`pnpm test:e2e:ci` 592 passed。
