## feat(openapi): 用 zod 4 原生 `.meta()` 补全响应/请求元数据并加契约门禁

`plans/2026-10-16-backend-engineering-capabilities.md` §二。原计划拟引入
`@asteasolutions/zod-to-openapi` 的 `.openapi()` 存元数据，实测其存于自有 registry，
响应侧 `z.toJSONSchema(..., { target: 'openapi-3.0' })` 与请求侧 NestJS
`StandardSchemaOpenApiConverter`（`~standard.jsonSchema.input(...)`）**都不读**；
而 zod 4.6.5 原生 `.meta({ example })` / `.meta({ examples })` 两条管道都读、`.nullable()`
直出 `nullable: true`。故**不引入该依赖**（已装又卸载，`package.json`/lockfile 无残留），
改用原生 `.meta()`；原计划的 extension point 与「dto 禁裸 import zod」lint 门禁随之取消。

- 响应侧：给此前 27 个缺元数据的组件 schema 补 `.meta({ example })`（admin、auth、
  notifications、product-events、reports、today-suggestion、today-analysis、
  medicine-reminders、legal-documents、medicines/risk、daily-records、assistant）。
- 请求侧：给 `user-health-context`、`daily-records`、`medicines`、`assistant` 的
  query/body schema 字段补 `.meta({ example })`。
- 均为纯元数据追加：`openapi.json` 剥离 `example`/`examples` 后与旧文件逐字相同
  （路径/类型/required/pattern 未变）。`pnpm export:openapi` 通过（Paths 132、Schemas 370）。
- 契约门禁：新增 `test/contract/openapi-metadata.e2e-spec.ts`（纯文件校验、无需 DB），
  遍历所有 2xx JSON 响应 schema，递归跟随 `$ref` 断言子树至少含一个 `example`/`examples`
  或 `nullable: true`，防止新 DTO 绕过。
- `docs/TODO.md` 删除「OpenAPI example/nullable 语义元数据补全」条目。
- 验证：`pnpm lint:check`、`pnpm typecheck`、`pnpm export:openapi`、
  `vitest run test/contract/openapi-metadata.e2e-spec.ts` 全绿。
