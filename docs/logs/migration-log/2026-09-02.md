## 计划外发现与修复：scripts/ 目录 CJS 脚本运行时全面断裂

背景：本轮执行 `pnpm export:openapi` 时 `fix-generated-prisma-internal.ts` 抛 `ReferenceError: require is not defined in ES module scope`，顺藤排查发现 09-01 a58eb6a 引入的 `scripts/package.json {"type":"module"}` 使 Node 以 ESM 运行 scripts/ 下全部 .ts（type stripping），而目录内 16 个 CJS 风格脚本（require/\_\_dirname/module.exports）运行时全部断裂。该断裂未被发现的原因与 W-2 同根：typecheck 因 @types/node 全局 require 声明而不报错；test:tools 只匹配 scripts/\*_/_.spec.ts 且当时未并入 test:ci；09-01 的验证从未实际执行任何脚本入口。

修复方式：与已 ESM 化的 docs 脚本保持同一模式，16 个脚本全部转 ESM：具名/默认 node: 导入；`fileURLToPath(import.meta.url)` 派生 thisDir 替代 \_\_dirname；`export {}` 替代 module.exports；相对导入补 .ts 扩展名；`require.main === module` 换 argv[1] basename 守卫（与 check-ast-conventions.ts 口径一致）；redisStoreFromUrl 内惰性 require 改 `await import`（保留惰性加载语义）。涉及：scripts/dev/{up-local-stack,start-test-runtime,stop-test-runtime,fix-generated-prisma-internal}.ts、scripts/contract/export-openapi.ts、scripts/shared/{env,chunking,stable-id,db-upsert}.ts、scripts/import/food/import-food-composition.ts、scripts/import/medicine/{import-medicine-datasets,import-medicine-knowledge,import-medical-qa,rebuild-drugbank-rag-index,rebuild-leaflet-index}.ts。

顺带修复（ESM 静态导入使 typecheck:tools 首次真正类型检查这些文件，暴露三处此前被 require/any 掩盖的类型错误）：import-medical-qa.ts 两处 `ReturnType<typeof Client.prototype>` 改 `Client`；import-medicine-knowledge.ts `store.del()` 在 cache-manager-ioredis-yet 类型上不存在（其 .d.ts extends cache-manager 7 的 Store，运行时对象仍是 v5 API），改走 `store.client.del()`，并补 `uniqueStrings`/`listMedicineCacheKeys` 类型标注。

测试盲区同类闭合：scripts/import/medicine/import-medicine-knowledge.test.ts（node:test 风格）此前无任何 CI 任务执行，转为 vitest spec（import-medicine-knowledge.spec.ts）并入 test:tools，断言语义不变。

已知残留（有意不处理）：从 scripts ESM 链引用 src/ 文件时 Node 输出 MODULE_TYPELESS_PACKAGE_JSON 性能警告——根 package.json 刻意保持 CJS（NestJS 构建产物形态），不能加 type:module；警告仅影响脚本冷启动开销。
