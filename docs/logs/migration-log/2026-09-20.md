## fix(graph): ATC 类名决策落定（不导入），图侧数据缺口核实

### 背景

计划 D1 是决策项：1,467 个 `ATCClass` 节点只有 `code`/`level`，没有类名。
三个候选里默认 ②（不导入，产品层只呈现 code）。落决策前先在源库核实名称是否
真的不存在，避免把"导入漏了字段"误判成"数据本来就没有"。

### 结论

源库侧确认名称在整条链路上都不存在：

- `drugbank_drugs.atc_codes` 是 JSON 数组且只含代码（如 `["B01AB07"]`，3,257 行有值）；
- `information_schema` 中没有任何名称含 `atc` 的列，也没有任何 ATC 名称表；
- 图侧 `ATCClass` 的 `name`/`title`/`description` 计数均为 0。

即这是数据源本身没有，而非导入丢字段。故维持选项 ②：只呈现 code，类名交给
模型/UI 解释；若产品明确要求类名，需单独立项导入公开 ATC 索引并先确认许可与来源。

## R3：规则推理接入 Lucent，评测集扩到 11 题（11/11）

### 变更范围

**Lucent 新增工具 `reason_over_rules`**（`src/modules/assistant/tools/ontology/rule-reasoning.service.ts`）。
与 `reason_over_ontology` 的分工是**断言与推导**，不是"另一个端点"：前者读图上写了
的边，后者按规则推出图上没写的边——依据不在任何一个三元组里，而在两个三元组的
**连接**上（"A 抑制的酶恰好是 B 的代谢酶"）。

硬约束落地方式：让推导与断言在**类型上**就分开。新增 `SemanticaReasonOutcome` /
`SemanticaDerivedConclusion`，与断言的 `SemanticaQueryOutcome` 各自独立；envelope
里 `cypher` 换成 `rule` + `query` + `derivedNote`（明确告诉模型"这是推出来的，
要这么说，不要把断言说成事实"）。同名同形会让下游按名字取值时把规则当成查询。

入参 `intent` + `query` + **必填**范围 + `limit`。范围必填的理由是代价：推导随
子图规模超线性增长，不给范围就是把分钟级计算塞进秒级工具调用，而超时会被读成
"图上没有"。全变量模式（`potential_ddi(?A, ?B)`）同样在边界拒绝——那不是提问，
是让工具把子图的全部推导倒进上下文（单药范围实测 20,116 条）。

`limit` 走独立的 `SEMANTICA_REASON_DEFAULT_LIMIT`（2000 边）/ `_MAX_LIMIT`
（20000 边），刻意不复用 `SEMANTICA_MAX_LIMIT`（25/100 **行**）：一个是"喂进
不动点引擎的边数"，一个是"返回给模型的行数"，当一个数就会在两头都错。

**sidecar 修掉两个叠在一起的静默缺陷**（`semantica-service`）：

1. `conclusions` 完全无视 `query`。请求 `potential_ddi(db00682, ?B)` 时返回规则推出
   的**每一对**——单药范围实测 20,116 条，而该查询只命中 67 条。响应的两半在回答
   不同的问题。修复中踩到第二个坑：绑定行**只含变量**（`[{B: 'db04951'}, ...]`，
   常量 `db00682` 不在行里），所以常量必须从查询模式取、自由变量从绑定行取。
2. 前提恢复的上限作用在收窄**之前**。`premises_for_conclusion` 对全部 20,116 条排序
   取前 500，而查询真正问的 67 条排得靠后——**一条引用都没有**，倒是 500 条无关的
   拿到了引用。改为收窄在前、上限在后：67 条结论、67 条全部带引用、
   `conclusions_complete: true`。

还修了一处**本层的静默降级**，由真机验证当场抓出：sidecar 的 422
`scope_matched_nothing` 被 `parseErrorDetail` 丢成 `null`（它只认 `/query` 那一组
kind），于是信封说成 "Rule reasoning is unavailable"。这是把"你的药名写错了、
换个名字再问"报成"推理坏了"，模型对后者的反应是放弃这条推理路径。现在两个端点
各有词表，并按 kind 分流：可修正的输入问题走独立信封（明说 blame the scope），
基础设施故障才走 unavailable；反向用例（连不上的 sidecar 不得被说成范围问题）
也在验证里。
