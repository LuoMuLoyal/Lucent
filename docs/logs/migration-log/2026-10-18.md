- 动机:管理面板需覆盖用户状态/会话/分享与管理员角色。此前 `UserStatus.suspended`
  无写入口，管理员角色只能靠 `pnpm admin:seed` CLI 授予。计划:
  `plans/2026-10-18-admin-management-expansion.md`(active，本次完成 Phase 1，后续阶段未实施)。
- 权限:`constants/permissions.ts` 新增 `users:write`(用户状态/会话/分享写)，
  授予 `SUPER_ADMIN` 与 `ADMIN`;`EDITOR`/`VIEWER` 不变;`admin:manage` 仍仅 `SUPER_ADMIN`。
  同步 `constants/permissions.spec.ts`。

  `AuthSessionAdminService`(包装 `AuthTokenService.revokeAll`/`revokeById`)。两者 barrel 导出。

  `DELETE /admin/users/:id/sessions/:sessionId`、`DELETE /admin/users/:id/shares/:shareId`、
  `GET/PUT/DELETE /admin/admins[/:userId]`。守卫:不得操作自身账号、不得改 `SUPER_ADMIN`
  目标的用户态;RBAC 不得改自身角色、不得撤销最后一个 `SUPER_ADMIN`(防御性——当前
  经 `admin:manage` 门禁不可达)。审计记 actor/target 与前后态。
- ADR-0009 受控例外:撤销 clinic share 在 `admin/services/shares.service.ts` 直写
  `user_clinic_summary_share.revokedAt`，不经 `reports` owner service——`reports`→
  `product-events`→`admin` 已构成模块环，`AdminModule` 再 import `ReportsModule` 会成环;
  直写同时刻意不发用户遥测事件。
- 契约:重导出 `docs/reference/generated/openapi.json`，新增 5 条路径与 7 个 operationId
  (`updateAdminUserStatus`/`deleteAdminUser`/`revokeAdminUserSession`/`revokeAdminUserShare`/
  `listAdminGrants`/`setAdminRole`/`removeAdminGrant`)，已在 `plans/_naming-lookup.json` 登记。
  Luminous client 未重生成(经确认暂缓——该仓有在途的 assistant 改动，避免与其交互)，留待 Phase 4。
- 文档:更新 `src/modules/{admin,user,auth}/README.md`。

  `plans/2026-10-18-admin-management-expansion.md`(active，本次完成 Phase 2a，
  后续阶段 2b/2c 未实施)。
- 注册表:`src/modules/admin/constants/resource-registry.ts` 显式声明全表矩阵
  (kebab-case 键、Prisma 模型名、`idField`、软删/只读标志与 search/filter/omit/writable 列表)。
  Prisma 7 无运行时 DMMF，故必须显式维护;null 语义等价直写 Prisma delegate。
- 权限:`constants/permissions.ts` 新增 `data:read`/`data:write`;`SUPER_ADMIN` 兼有，
  `ADMIN`/`VIEWER` 仅 `data:read`，`EDITOR` 不变。同步 `constants/permissions.spec.ts`。
- 新端点:`GET/POST/PUT/DELETE /api/v1/admin/data/:resource[/:id]`，`data.controller.ts` +
  `data.service.ts` 按注册表驱动。列表 `page`/`limit`(≤100)/`q`(仅 searchFields 且大小写不敏感)/
  `userId`(仅 filterFields 含 userId 时)/`sort`(限 filter+createdAt+idField)/`order`。
  行径 `omitFields` 剔除敏感列(`accounts` 凭据、`user-sessions.refreshTokenHash`、

  `pickWritable` 白名单(未声明/敏感/空 → 400)，软删表 `DELETE` 落 `deletedAt`，
  唯一冲突 409、缺行 404。审计 `admin.data.{create,update,delete}` 只记字段名。

  `AdminResourceRow` 响应组件，已在 `plans/_naming-lookup.json` 登记。Luminous client 未重生成
