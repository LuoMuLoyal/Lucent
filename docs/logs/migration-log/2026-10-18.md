## feat(admin): 用户生命周期与管理员角色管理 API（管理面扩展 Phase 1）

- 动机:管理面板需覆盖用户状态/会话/分享与管理员角色。此前 `UserStatus.suspended`
  无写入口，管理员角色只能靠 `pnpm admin:seed` CLI 授予。计划:
  `plans/2026-10-18-admin-management-expansion.md`(active，本次完成 Phase 1，后续阶段未实施)。
- 权限:`constants/permissions.ts` 新增 `users:write`(用户状态/会话/分享写)，
  授予 `SUPER_ADMIN` 与 `ADMIN`;`EDITOR`/`VIEWER` 不变;`admin:manage` 仍仅 `SUPER_ADMIN`。
  同步 `constants/permissions.spec.ts`。
- owner 写:`user` 新增 `UserAdminService`(`setStatus`/`softDelete`);`auth` 新增
  `AuthSessionAdminService`(包装 `AuthTokenService.revokeAll`/`revokeById`)。两者 barrel 导出。
- admin 新端点:`PATCH /admin/users/:id/status`、`DELETE /admin/users/:id`、
  `DELETE /admin/users/:id/sessions/:sessionId`、`DELETE /admin/users/:id/shares/:shareId`、
  `GET/PUT/DELETE /admin/admins[/:userId]`。守卫:不得操作自身账号、不得改 `SUPER_ADMIN`
  目标的用户态;RBAC 不得改自身角色、不得撤销最后一个 `SUPER_ADMIN`(防御性——当前
  经 `admin:manage` 门禁不可达)。审计记 actor/target 与前后态。

  `product-events`→`admin` 已构成模块环，`AdminModule` 再 import `ReportsModule` 会成环;
  直写同时刻意不发用户遥测事件。
