## F-5b 重新生成/重新发送(后端:Time Travel 重生)

依据 `Luminous/plans/2026-08-16-assistant-remediation-plan.md` 的 F-5b(实施完毕文件已删):第一版仅重生当前会话最后一条助手消息,从 `respond` 前 checkpoint 重放,旧答案保留为修订;持久化 message→checkpoint 映射与幂等键,不开放任意历史消息分支。

### 方案:采用 LangGraph time travel(实验验证后落地)

实现前用 MemorySaver + 假模型跑通两个场景验证 API 语义:①simple_chat 流与②read_subgraph+agent+tools 流下,`getStateHistory` 返回的 `StateSnapshot` 含 `next` 与 `config.configurable.checkpoint_id`;对 respond 前 checkpoint(「next 含 respond、messages 以 assistant 结尾」)执行 `updateState({configurable:{thread_id, checkpoint_id, checkpoint_ns:''}}, {finalContent:null, stopReason:null})` 后,最新 checkpoint 的 `next` 保持 `['respond']`,`graph.invoke(null, config)` 仅重跑 respond 节点(只新增一次 LLM 调用,不重放 prepare_context/agent/tools),onText 流式输出新答案;随后用 `updateState(config, {messages:[新AIMessage]})` 将新回答 append 进线程(respond 本身只写 finalContent),append 后 `next` 仍为 `[]`,后续正常对话不受影响、旧回答与修订并存。

关键实现细节:**`updateState` 必须不带 `asNode` 参数**(让库推断最后运行节点)。显式传 `'respond'` 时其 writer 不写条件分支渠道,fork 后 `next=[]`、invoke 空转;推断节点(子图/agent)的 writer 含分支写入,fork 才能从 respond 恢复。`checkpoint_ns: ''` 必须显式传入,否则 MemorySaver/PostgresSaver 的 putWrites 校验失败。
