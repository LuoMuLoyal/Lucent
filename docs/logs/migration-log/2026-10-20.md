## refactor(assistant): 检索客户端改为每次调用读取运行时快照

- 动机:检索家族的预算键已进入配置中心白名单,但消费方仍在构造时把 `enabled`/`baseUrl`/
  超时抄进字段,发布新文档后要重启进程才生效。快照的语义是"读它不发网络请求",因此正确
  做法是每次调用现读,而不是缓存整份值。

- `LightragClientService`:删除四个字段缓存,新增 `readSettings()` 按
  **快照 > `ConfigService` > `sidecar-defaults`** 分级取值;`apiKey` 只从 `.env` 读
  (白名单外),缺 key 的一次性告警移进 `isEnabled()`,避免每次请求刷日志。`request()`
  增加 `baseUrl` 选项,`query()`/`health()` 各读一次设置,同一请求内的 URL 与超时来自
  同一版本。

- `AssistantToolKnowledgeRetrievalService`:workspace 映射、`LIGHTRAG_GRAPH_SOURCES`、
  `LIGHTRAG_MAX_LIMIT` 改为 `readSettings()` 现读;`parseArguments`/`parseMode`/
  `normalizeLimit` 接收本次设置,图模式校验按发布值判断"图建没建"。快照里的
  `graphSources` 经 `isLightragSource` 收窄(类型层面是 `string[]`),非法来源被丢弃,
  不会落到任一 workspace。

- 单测:两处构造函数新增可选 `RuntimeConfigPort`,`@Optional` 注入让未接线的既有用例继续
  走 env 回退。新增 6 条:发布 `LIGHTRAG_ENABLED=false` 压过 env、发布 baseUrl 进入请求
  URL、发布超时进入 `resolveTimeoutMs` 与失败原因、limit 夹紧、workspace 映射、图覆盖
  校验。

- 验证:`pnpm typecheck` 绿;`vitest run src/modules/assistant/tools/retrieval` 24 文件
  通过。

## feat(assistant): 工具预算与参数 schema 随运行时配置生成

- 动机:参数 schema 里的 `maximum` 与执行侧的 `normalizeLimit` 必须来自同一个值。此前
  两者都是模块常量,只改执行侧会让模型按旧上限请求、服务端静默夹紧。

- `tool-definitions.ts`:新增 `ToolLimitBudgets` 与 `CODE_TOOL_LIMIT_BUDGETS`,三个参数
  构建器改为接收 budgets;`buildToolParameters(names, budgets)`、
  `buildToolDefinitions(names, budgets = CODE_TOOL_LIMIT_BUDGETS)`。schema 因此每次构建,
  单测断言 `maximum` 与描述里的 `(1-N)` 同时变化。

- `AssistantToolService`:`TOOL_TIMEOUT_OVERRIDES` 改为 `{ key, fallback }`,键类型收窄为
  `ToolTimeoutKey`(三个预算键的联合),新增 `resolveToolTimeoutMs(toolName)` 读快照;
  `values[key]` 保持 number,避免 `number | undefined` 在超时比较里散开。

- 传递链:`AssistantGraphDeps` 增 `toolBudgets?()` 与 `nodeTimeoutMs?()`;`createAgentNode`
  用 `deps.toolBudgets?.()` 构建定义,节点超时用 `deps.nodeTimeoutMs?.() ??
ASSISTANT_NODE_TIMEOUT_MS`;`read`/`write`/`knowledge` 子图的 `Pick` 同步加 `'toolBudgets'`;
  `AssistantRuntimeService` 新增 `readToolLimitBudgets()` 与 `readNodeTimeoutMs()`,两处
  `buildAssistantRuntimeGraph` 调用都传入。

- `retrieval.schema.ts`:`ASSISTANT_NODE_TIMEOUT_MS` 默认 75s → **80s**。75s 小于
  「模型 10s + 最大工具预算 65s」,会在最坏情况先取消工具、把工具级信封变成节点级失败;
  80s 留 5s 余量。`docs/reference/runtime-config.example.txt` 同步为 80000 并注明与工具
  预算的联动。计划里把它列为"新建"是偏差:该 schema 在 Task 1 已随家族一起建立,本任务
  只做消费侧与默认值修正。

- 单测:新增 5 条(预算进入 schema 与描述、缺省回落到代码基线、发布 5s 工具超时后挂起
  工具 5s 即超时),`vitest run src/modules/assistant` 通过。
