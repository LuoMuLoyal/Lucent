## feat(storage): 对象存储换成自建 RustFS

### 变更范围

- `compose.dev.yaml`：`seaweedfs` 服务与 `seaweedfs-data` 卷移除，替换为 `rustfs`
  （`rustfs/rustfs:1.0.6`，S3 API `127.0.0.1:9000`、Console `127.0.0.1:9001`，
  卷 `rustfs-data`），healthcheck 打 S3 API 的未鉴权 `/health`。
- `compose.yaml`：新增同一份 `rustfs` 服务定义（与 app 同网络，端口 9000/9001），
  `RUSTFS_ACCESS_KEY` / `RUSTFS_SECRET_KEY` 直接取 `STORAGE_S3_ACCESS_KEY` /
  `STORAGE_S3_SECRET_KEY`，不另存一份凭据；新增卷 `rustfs-data`。app **不**depends_on
  RustFS —— 存储不可用时 app 仍要能起并报 `DEPENDENCY_UNAVAILABLE`。
- `scripts/dev/up-local-stack.ts`：默认服务列表 `seaweedfs` → `rustfs`。
- `.env.development.example`：dev 端点改 `127.0.0.1:9000`，凭据与 bucket 落成可直用的值。
- `.env.production.example`：S3 段改写为自建 RustFS 的三种受众端点（服务端 `rustfs:9000`、
  客户端与外部受众 `<公网IP>:9000`），并登记 `RUSTFS_VOLUMES` / `RUSTFS_REGION`。
- 文档：`docs/reference/environment-variables.md`（本地基线与 S3 段）、
  `docs/reference/runtime-config.example.txt`、`README.md`、`THIRD_PARTY_NOTICES.md`
  （SeaweedFS → RustFS）；ADR-0014 / ADR-0019 只做措辞更正并注明修订。
- 代码注释：`s3.runtime.ts`、`config/runtime/schema/storage.schema.ts` 的 provider 指向说明。
- `docs/TODO.md`：登记两条自建后的遗留（无域名/TLS；单盘无真实冗余）。

### 说明

`S3StorageRuntime` 一行未改：它本就固定 `forcePathStyle: true`，而 RustFS 未配
`RUSTFS_SERVER_DOMAINS` 时只支持路径式寻址，正好吻合。存量对象不迁移，切换后从空桶开始。

**实测修正了两处原本写错的地方**（初版按七牛/S3 的常识写，跑起来才发现不适用于 RustFS）：

1. `RUSTFS_VOLUMES` 初版给的是 `/data/rustfs{0...3}`，容器**启动即 FATAL 并崩溃循环**：
   `local erasure endpoints must use distinct physical disks`。RustFS 会校验每个卷的
   物理设备 id，同盘多卷是硬错误而不是"无冗余"的软降级。单盘部署只有单卷 `/data` 能起，
   dev 与生产都已改正。
2. 区域串不参与校验。实测用 `z2` / `cn-north-1` / 任意乱串签 presigned GET/PUT 都返回
   200，说明 RustFS **不校验** SigV4 的 region scope，只校验凭据与签名本身（另用一个
   全零签名验证过，服务端如实返回 `SignatureDoesNotMatch`）。这与接七牛 Kodo 时
   "区域错配即静默 403" 的行为不同，`RUSTFS_REGION` 相关注释与文档已按实测改写。
