# 2026-09-12

## fix(deps): 依赖安全审计整改——升级至最新稳定版并消除高危漏洞链

背景:对 Lucent 全量依赖做安全与合规审计(见 2026-09-12 审计结论),发现 cos
SDK 引入的 `request`(SSRF critical 链)、多个弃用包(`@langchain/community`、
`prom-client`、`cache-manager-ioredis-yet`)及部分直接依赖的旧版本。本轮按
「升级到最新稳定版,破坏性变更跟进适配」执行。

### 依赖变更(均在 package.json / pnpm-lock.yaml)

- `@fastify/static` `^9.0.0` → `^10.1.3`(安装 10.1.3)。v10 破坏性变更:
  `setHeaders` 回调签名由 Response 改为 FastifyReply;Lucent 源码不直接使用
  `@fastify/static`(经 `@nestjs/platform-fastify` 消费),无适配需求。
  升级后反而满足 `@nestjs/platform-fastify@12.0.1` 的 peer 要求(`^10.1.2`)。
- `nodemailer` `^8.0.9` → `^10.0.8`。v10 要求 Node ≥20(项目 engines ≥24.15
  满足)并迁移至 TS 构建;代码仅用 `createTransport` / `sendMail`,API 兼容。
- `cos-nodejs-sdk-v5` `^2.15.4` → `^3.0.0`。v3 不再依赖
  `request` / `form-data` / `fast-xml-parser`(改用自研 `cos-request` /
  `cos-fast-xml-parser`),**消除 request SSRF critical 链**。`getObjectUrl` /
  `putObject` 签名与 v2 兼容(单元测试验证)。
- 移除弃用包 `@langchain/community`(官方弃用,langchain-ai/langchainjs-community
  #61)、`prom-client`(官方继任 `@prometheus-io/client`,原维护者迁移)、
  `cache-manager-ioredis-yet`(未维护)。
- 新增 `@langchain/pgvector@0.1.0`(仅 peer `@langchain/core@^1.0.0`,满足)。
- 新增 `@prometheus-io/client@0.16.1`。
- 新增 `@keyv/redis@5.1.6`(NestJS cache-manager 官方文档推荐 `createKeyv`,
  底层 node-redis v4;与项目 ioredis 客户端互不冲突)。

### 代码适配

- `src/common/metrics/metrics.service.ts`:`prom-client` → `@prometheus-io/client`。
  label 泛型需显式标注(属性声明 + 构造),去掉 `as const`;
  `registry.metrics()` 返回 Promise 已适配。
- `src/config/services/cache.config.ts`:`cache-manager-ioredis-yet` →
  `@keyv/redis` 的 `createKeyv(redisUrl)`;`createCacheOptions` 由 async 改为
  同步返回(接口允许 `Promise<...> | CacheOptions`,消除 eslint require-await)。
- `src/modules/assistant/tools/vector/vector-store.factory.ts` 与
  `src/modules/assistant/tools/leaflet/read.service.ts`:
  `@langchain/community/vectorstores/pgvector` → `@langchain/pgvector`。
- 4 个 spec 的 `vi.mock` 路径同步替换。
- `src/common/storage/tencent-cos.runtime.ts`:未改(v3 签名兼容,测试验证)。
