## fix(medicine-import): 靶点 XML 动作按名称+物种匹配,消除跨物种错挂

（来源：2026-09-16 审查报告 W1，报告 `plans/Lucent-review-09-16.md` 保留中。）

### 背景

`applyXmlTargetActions` 此前用 `name → targetId` 的 last-one-wins Map 解析 XML
靶点。`drugbank_targets` 中 306 个名字对应多个物种（细菌株共用蛋白名，如
「2-c-methyl-d-erythritol 2,4-cyclodiphosphate synthase」同时属于 Shigella /
Thermus / Shewanella / 大肠杆菌 / 分枝杆菌），last-one-wins 会把 XML 的作用类型
挂到任意一行上，详情页于是显示同名但错误的物种与 PDB 条目。

### 变更

- `scripts/import/medicine/import-medicine-knowledge.ts`：把 name-only Map 升级为
  `(name, organism)` 复合键 Map；名字命中多行且物种对不上时不猜，单独计入
  `ambiguous` 计数（旧口径会静默错挂）。返回对象新增 `ambiguous` 字段，导入日志
  输出形如 `[xml-targets] applied N relation(s), M unresolved name(s), K ambiguous
(name matched several species)`。
- `scripts/import/medicine/parsers/common.py`（docstring 侧已说明 keyed by
  name + organism，导入侧此前只用了 name，本次对齐）。

### 验证

- 重跑 `import-medicine-datasets.ts --command drugbank-drugs`（全量 XML，
  raw 1014340 行）成功，输出 `applied 32032 relation(s), 2467 unresolved, 432
ambiguous`——432 个此前会被静默错挂的跨物种同名靶点现正确归入 ambiguous。
- 抽查 DB00537（DNA gyrase subunit A 挂到 XML 声明的 Bacillus / E. coli /
  H. influenzae / S. aureus 四个物种行）、DB08231（Genome polyprotein 挂到 14 个
  病毒物种行），物种均与 XML `<organism>` 精确一致。
- 12 个 narrative 字段残留标记（未闭合 `[CODE`、"label, 裸编号"、任意 `[CODE`）
  全表计数均为 0。

## fix(medicine-import): 重写参考标记清洗正则,清除残留裸文本

（来源：2026-09-16 审查报告 W3，报告 `plans/Lucent-review-09-16.md` 保留中。）

### 背景

旧 `_REFERENCE_MARKER` 只覆盖 `[L6616]` / `[label,L6616]` 两种形态，`[L45859,A4393]`
（多编号）与 `[FDA label, A31973, A31976]`（带标签多编号）不命中，落到
`_INLINE_LINK` 被解包成裸文本；源 XML 缺右括号的未闭合标记残留 `[L#####`。入库
实测 4 行残留未闭合 `[L#####`、8 行残留「label, 裸编号」。

### 变更

- `scripts/import/medicine/parsers/common.py`：
  - 重写 `_REFERENCE_MARKER`：支持「标签前缀 + 多个逗号分隔编号 + 闭合括号」；
  - 新增 `_UNTERMINATED_MARKER`：仅在句末标点后生效的未闭合标记规则（`[` 后
    Lookahead 无 `]` 才删），并限制编号必须带字母前缀 `[A-Z]{1,5}\d{2,}`，
    避免误伤 `[100 mg]` / `[P450 enzymes]` 等真实散文括号；
  - 保留 `_INLINE_LINK` 解包剩余括号链接（`[aspirin]` → `aspirin`）。
- `scripts/import/medicine/drugbank-narrative-cleaning.spec.ts`：新增
  `clean_narrative_text marker handling` 套件，覆盖真实语料形态（含多编号、
  缺右括号、句末、字段末尾）与必须保留的散文括号（`[Homo sapiens]`、
  `[P450 enzymes]`、`[100 mg]`、`[vitamin K]`、`ATPase [Actin]`）。

### 验证

- `pnpm exec vitest run --config ./vitest.tools.config.ts` 全绿（82 tests），
  其中 narrative cleaning 23 tests。
- 重跑 `drugbank-drugs` 导入后全库核查：12 个 narrative 字段中未闭合标记、
  「label, 裸编号」、任意 `[CODE` 残留计数均为 0。

## 复核结论（W2 / S4 不成立,未按报告改动）

- W2「旁路字段会静默送到 SQL 直到 PG 报 column not found」不成立：
  `scripts/shared/db-upsert.ts` 绑参是 `spec.columns.map(col => record[col])`，
  只读声明过的列，多余键根本不会被读取。真实风险相反：解析器键名写错成不在
  columns 里的名字会静默写 NULL，属另一议题。
- S4 归属错误：`git show c5a1d66a~1` 里 `shouldBypassCache` 已存在，是既有代码；
  且 `Access-Control-Allow-Origin: 'true'` 与 `MEDICINES_BYPASS_CACHE_HEADER` 是
  两个不同的 header，不会互相误判。

## feat(medicine-import): 接入 V3 去重数据源,默认导入切换到 DrugEntityDedup

### 背景

V3（`DrugDataBase/DrugEntityDedup/`）在 V2 基础上做了产品/说明书去重、保健食品
删除、名称冲突修正，并把条码聚合为组内并集。此前 Lucent 只读 V2 xlsx。

### 变更

- 新增三个 parser（读 Parquet，pyarrow）：
  - `scripts/import/medicine/parsers/cn_v3_products.py` — V3 产品表 → `cn_medicine_products`
  - `scripts/import/medicine/parsers/cn_v3_leaflets.py` — V3 说明书表 → `cn_medicine_leaflets`
  - `scripts/import/medicine/parsers/cn_v3_links.py` — V3 链接表 → `cn_medicine_product_leaflet_links`
- `import-medicine-knowledge.ts`：新增 `cn-v3-products` / `cn-v3-leaflets` /
  `cn-v3-product-leaflet-links` 三命令（源键 `cn_v3_*`），V2 命令保留不删。
- `import-medicine-datasets.ts`：`all` 默认顺序切换为 cn-v3-\*；V2 命令仍可
  `--command cn-products` 单独指定。
- `requirements.txt` 增加 pyarrow。
- `src/modules/medicines/README.md`：导入策略更新为 V3 优先、V2 兼容。

### 关键映射

- 产品主键 = V3 `entity_id`（`cn_v3_products.py` 直接作为 `id` upsert 冲突键）；
  产品侧 V3 已删的正文字段落 NULL，正文只在说明书表。
- V3 列重命名（`source_url`→`title_url`、`approval_text`→`approval_raw`、
  `category`→`drug_category`、`regulatory_class`→`drug_nature`、
  `appearance`→`properties`、`manufacturer_clean`→`manufacturer_normalized`）在
  parser 内完成，DB schema 未动。
- 链接表 `product_entity_id` / `leaflet_entity_id` 即两表的 `id`，直接映射；
  `match_score`（1.0/0.9/0.6 置信度）映射到 DB 的 Int 分档（100/90/60）。

### 验证

- 三个 parser 冒烟：`--limit 2` 输出 NDJSON 正确（产品 id 为 V3 entity_id、
  条码为并集）。
- `pnpm typecheck`、`pnpm build`（593 files）、`pnpm lint:check` 全绿；
  `pnpm test` 全量 320 文件 / 3778 用例通过。
- 未实际连库重导（需 dev 栈）；导入脚本行为经 parser 冒烟 + 编译验证。

## feat(medicine-schema): align DB schema with V3 data model

**日期**: 2026-09-17
**变更范围**: DB schema migration + Prisma models + runtime queries + parsers

### 变更摘要

DB schema 对齐 V3（DrugEntityDedup）数据模型，消除 V2→V3 的列名映射层：

- **产品表** (`cn_medicine_products`): 删除 15 个正文字段（ingredients..validity*period）和
  14 个匹配内部字段（best*_/top*candidate*_/match*quality*\*），以及 `image_url_cleaned`/
  `drugbank_ids`；`manufacturer_normalized` 重命名为 `manufacturer_clean`。
  产品表现在是纯目录表，不含正文文本。
- **说明书表** (`cn_medicine_leaflets`): 删除 V3 已裁字段（source_file/title/number_raw/
  summary/pinyin/approval_conflict/merge_notes/dropped_reason）；6 列重命名到 V3
  名称（`title_url→source_url`、`approval_raw→approval_text`、`drug_category→category`、
  `drug_nature→regulatory_class`、`properties→appearance`、`manufacturer_normalized→manufacturer_clean`）。
- **链接表** (`cn_medicine_product_leaflet_links`): 删除 `approval_code`；新增 `match_key`；
  `match_type`/`match_score`/`is_best_match` 保留。

### 运行时适配

- `cn.service.ts`: `getDetail` 改为产品→链接→说明书 join 取正文（1:1 关系，取 `take:1`）；
  搜索摘要改用产品目录字段（`mainCategory`/`subcategory`/`drugType`），不再依赖已删的正文字段。
- 三个 V3 parser 列名直接对齐新 schema（无重命名层）；V2 parser 已从 COMMANDS 注册表移除
  （schema 删列后 V2 列不存在，无法工作）。
- `admin.constants.ts`: 产品 `showProperties` 去除已删列，补入 `overdose`/`barcode`/`nationalDrugCode`。
- `cn.service.spec.ts`: mock 数据结构对齐新 schema，详情断言改为通过 `CnMedicineDetailDto` 收窄类型。

### 验证

- `pnpm typecheck`、`pnpm build`（593 files）、`pnpm lint:check` 全绿；
  `pnpm test` 全量 320 文件 / 3778 用例通过；
  `pnpm docs:verify`、`pnpm docs:links` 通过。
- 三个 V3 parser 冒烟输出与新 schema 列名完全一致。
