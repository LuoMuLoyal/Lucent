# 2026-10-30

## feat(layouts): 界面布局的后端权威存储

客户端把「每个 tab 挂哪些组件、顺序、尺寸」做成用户可编辑的表面布局，此前只存设备本地。
本日落地后端副本，解锁多设备一致与换机不丢。

### 新资源

```text
GET  /layouts              → { surfaces: { <surface>: LayoutDoc } }
GET  /layouts/:surface     → LayoutDoc | 404
PUT  /layouts/:surface     → 200 | 409{errors.current} | 422

LayoutDoc = { surface, version, schemaVersion, payload, updatedAt }
```

`surface`：`today` / `record` / `medicine` / `review` / `mine` / `tab_chrome`。
operationId：`listLayouts` / `getLayout` / `saveLayout`。

### 设计要点

- **服务端不解释 `payload`**。组件 id、顺序、尺寸、tab 自定义文本全由客户端定义；
  服务端只守信封——`schemaVersion` 区间与 `version` 单调。这样布局格式演进不需要
  后端发版。
- **`payload` 类型是 `unknown` 而非对象**：页面布局是对象，`tab_chrome` 是数组。
  收窄会强迫服务端知道「哪个 surface 是哪种形状」，与上一条冲突。
- **不做冲突合并**。布局是有序列表，两个不同顺序没有「正确的合并结果」；
  409 以服务端为准并带回当前文档（放在 Problem Details 的 `errors.current`），
  客户端据此覆写缓存并提示。
- **`ifVersion: null` 表示无条件写**，用于首次保存与离线队列重放——后者重连后
  无法知道当前版本，拒绝会把离线编辑永久卡住。
- **`tab_chrome` 与页面布局共用资源**：两者都是「一个有序配置文档」，只差 payload 结构。

### 表

新表 `layouts`，唯一约束 `(user_id, surface)`。

表名用 `layouts` 而非 `user_layouts`：**表就是资源**，与端点 `/layouts` 对齐。
`user_id` 列本身已经表达「按用户隔离」，`user_` 前缀不增加信息，且全仓 64 张表里
43 张无此前缀。初稿曾写成 `user_layouts`，与端点「独立资源线」的判断自相矛盾，
已修正。

`surface` 是无外键的纯字符串：surface 是客户端概念，新增一个不应要求迁移，
校验放在请求 schema。

### 实现中踩到的两个坑

1. **`updatedAt` 必须返回 ISO 字符串**。NestJS 12 的 `@SerializeOptions({ schema })`
   会用 zod schema 解析返回值，`z.string()` 拒绝 `Date`。列表与单条都要过 `toWire`；
   只转一处时另一处运行时抛 `Serialization failed: expected string, received Date`。
2. **`payload` 不能声明 `z.record`**。`tab_chrome` 是数组，会被当 400 拒掉。

### 新增错误码

`LAYOUT_SURFACE_UNKNOWN`(400) / `LAYOUT_SCHEMA_VERSION_UNSUPPORTED`(422) /
`LAYOUT_VERSION_CONFLICT`(409)，均带 zh-CN 与 en 双语 key。

### 迁移说明

`prisma/migrations/20261030210000_add_layouts` 为**手写**的仅本表 DDL。
原因：dev 库存在与迁移历史不一致的对象（LangGraph `checkpoint_*`、
`drugbank_passage_embeddings` 由脚本/外部创建），`prisma migrate dev` 会要求
重置整个 schema 才能继续。重置会丢数据，故未采用；改为用 `migrate diff` 取出
本表相关 SQL 手工落迁移，并确认 checkpoint 等对象未被删除。

> 该漂移本身是待处理问题，记录在计划 `plans/2026-10-30-database-schema-consolidation.md`。
