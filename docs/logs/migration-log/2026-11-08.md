# 2026-11-08

## refactor(queue): 队列适配层收敛为端口，移除空转的 `@nestjs/event-emitter`

### 为什么

队列适配器此前有三处（`medicine-reminders`、`medicines`、`reports`）直接注入
`BullmqQueueFactory`，而 `today-analysis`、`daily-records`、`data-export` 早已各自
声明了 `application/ports/` 下的队列端口。同一层抽象存在两种写法，意味着换传输
层（微服务化时走向消息总线或独立调度进程）需要逐个改适配器，而不是只换绑定。

`@nestjs/event-emitter` 是历史遗留：`app.module.ts` 里 `EventEmitterModule.forRoot()`
是它在本仓库的**唯一引用**，全项目没有任何 `@OnEvent` 订阅者或 `EventEmitter2`
注入点。ADR-0025 已把跨上下文事件统一到 outbox + 队列投递，进程内同步派发不再
是合法路径，因此这个依赖实际在空转。

### 落地

- 新增三个端口（Symbol 令牌 + 接口，沿用既有 `TODAY_ANALYSIS_QUEUE_PORT` 约定）：
  - `src/modules/reports/application/ports/cache-invalidation-events.ts`
    —— `ReportsCacheInvalidationPort.invalidate(userId)`
  - `src/modules/medicines/application/ports/risk-refresh-queue.ts`
    —— `MedicineRiskRefreshQueuePort.schedule(userId)`
  - `src/modules/medicine-reminders/application/ports/reminder-dispatch-scheduler.ts`
    —— `ReminderDispatchSchedulerPort.registerSchedule()`
- 三个适配器改为 `implements` 对应端口，模块里用 `useExisting` 把令牌绑到实现；
  原有事件消费路径（`invalidateFromEvent` / `refreshForEvent`）保留，内部改为调用
  端口方法，语义不变。
- `ReminderDispatchQueue.onModuleInit` 委托给 `registerSchedule()`，并补了幂等判断：
  重复调用只更新已存在的任务定义，不产生第二条节奏。
- `MedicineRiskRefreshQueueService.enqueueRefresh` 不再透传原始事件载荷——worker
  只需要 `userId`，因此 `schedule()` 从非事件路径调用时也能构造出合法载荷。
- 移除 `@nestjs/event-emitter` 依赖与 `app.module.ts` 中的 `EventEmitterModule.forRoot()`。
