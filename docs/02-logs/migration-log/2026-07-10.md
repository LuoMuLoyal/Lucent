## 架构升级 (LUC-2026-0710-02)

### 背景

- 基于架构审查分析，对 Lucent 后端进行五项架构升级：AI 管道、LLM 重试、队列基础设施、Repository 抽象、JSONB Zod 校验。

### 改动内容

#### AI 管道：LangGraph 重构为真正的 tool-loop

- **旧图结构**：`START → prepare_context → respond → END`（空转图，LLM 不参与工具决策，keyword 路由）
- **新图结构**：`START → prepare_context → agent ↔ tools → respond → END`
  - `prepare_context`：根据 enabledContextSources 设置 allowedTools，构建初始 messages（SystemMessage + HumanMessage）
  - `agent`：调用 LLM（`model.bindTools()` + `invoke()`），LLM 通过 function calling 决定工具调用
  - `tools`：执行 LLM 请求的工具，添加 ToolMessages，递增 loopCount
  - 条件边：`pendingToolCalls > 0 && loopCount < MAX_TOOL_LOOPS` → `tools`，否则 → `respond`
- 新增 `tool-definitions.ts`：22 个工具的 LangChain function-calling 定义
- `runtime.service.ts` 新增 `runConversation()` 方法：运行完整 tool-loop，返回 toolResults + finalContent
- `core.service.ts` 更新：调用 `runConversation()` 替代旧的 `planConversation() + executeMany()` 两步流程
- 如果图产生了 `finalContent`，通过 `streamPreGeneratedContent()` 分块流式输出；否则回退到 `generateStream()` 做独立流式调用
- 图节点名从 `['prepare_context', 'respond']` 变为 `['prepare_context', 'agent', 'tools', 'respond']`

#### LLM 调用重试 + 指数退避

- 新增 `common/llm/llm-retry.helper.ts`：
  - `isRetryableLlmError(error)` — 区分可重试错误（429、5xx、timeout、network）和不可重试错误（400、401）
  - `withLlmRetry(operation, options)` — 3 次尝试，800ms 基础延迟，指数退避
- `BaseLlmGeneratorService`：`generate()` 和 `generateStream()` 的 LLM 调用包裹 `withLlmRetry`
- `AssistantRuntimeService`：`generateStream()` 的 LLM 调用包裹 `withLlmRetry`
- 常量 `maxRetries: 0` 保留在 MODEL_OPTIONS 中（LangChain 内置重试关闭），重试由 `withLlmRetry` 统一管理

#### 队列基础设施统一

- 新增 `common/queue/queue.factory.ts`：
  - `BullmqQueueFactory` — 全局可注入服务，统一管理 Redis 连接、Queue/Worker 创建、错误处理、生命周期
  - `createQueue<TData, TResult>(options)` — 返回 `{ queue, worker }`，Redis 不可用时返回 `{ null, null }`
  - `onModuleDestroy()` — 自动关闭所有管理的 Worker 和 Queue
- 新增 `common/queue/queue.module.ts`：`@Global()` 模块，注册到 `AppModule`
- 三个队列服务重构为使用工厂：
  - `MailQueueService`：保留 mail 配置驱动的 `defaultJobOptions` 和 `workerConcurrency`
  - `MealAnalysisQueueService`：保留 jobId 去重逻辑
  - `DataExportQueueService`：保留自定义 retry 选项

#### Repository 抽象（三模块全量迁移）

- **daily-records**：
  - `daily-record.repository.ts`：`DailyRecordRepositoryPort`（`findManyWithAttachments`、`findByIdWithAttachments`、`findManyByDateWithAttachments`、`findOwnershipData`、`create`、`update`、`softDelete`、`transaction`）+ `DailyRecordRepository`（Prisma 实现）
  - `DailyRecordsService` 和 `DailyRecordsOwnershipService` 全量迁移到 Port，不再直接注入 `PrismaService`
  - `daily-records.module.ts`：注册 Repository，导出 Port 供其他模块注入

  - `ConversationService` 和 `HistoricalAiSummaryService` 迁移到 Port
  - `assistant.module.ts`：注册两个 Repository Port
- **auth**：
  - `repositories/session.repository.ts`：`AuthSessionRepositoryPort`（`createSession`、`findSessionByRefreshToken`、`updateSessionContext`、`deleteSession`、`deleteAllUserSessions`、`findSessionsByUser`）+ `AuthSessionRepository`
