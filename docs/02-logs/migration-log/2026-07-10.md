# 2026-07-10 迁移日志

## 审查报告问题修复 (LUC-2026-0710-01)

### 背景

- 根据三份审查报告（增量审查、全仓库审查、回查纠正）确定的问题，对 Lucent 后端进行集中修复。
- 回查纠正后确认的有效问题：P0×4、P1×5。

### 改动内容

#### P0: 反馈记录操作无事务包裹 — `feedback.service.ts`

- `recordFeedback` 方法中的「创建反馈记录 + 更新建议状态」两个操作现在包裹在 `prisma.$transaction` 中，确保原子性。
- 同时修复 `updateData as never` 类型断言：改用 `Prisma.UserSuggestionUpdateManyMutationInput` 类型 + `SuggestionLifecycleState.DISMISSED` 枚举值。
- 更新 `feedback.service.spec.ts`：mock `$transaction` 方法。

#### P0: 建议生命周期无定时刷新 — `lifecycle.service.ts`

- 新增 `lifecycle.constants.ts`：定义 `SUGGESTION_ACTIVE_DURATION_MS`（8h）、`SUGGESTION_FADING_DURATION_MS`（4h）、`LIFECYCLE_REFRESH_CRON`（每 5 分钟）。
- `LifecycleService` 新增 `refreshLifecycleStates()` 方法，使用 `@Cron` 装饰器定时执行：
  - ACTIVE → FADING：`activatedAt` 超过 8 小时的建议自动转为 FADING。
  - FADING → EXPIRED：`activatedAt` 超过 12 小时的建议自动转为 EXPIRED。
- `app.module.ts` 注册 `ScheduleModule.forRoot()`。

#### P0: JWT validate 未检查用户状态 — `jwt-access.strategy.ts`

- `UserPayload` 接口新增可选 `status` 字段。
- `AuthTokenService.generateTokenPair` 签发时嵌入 `user.status`。
- `JwtAccessStrategy.validate` 检查 `status`：非 `active` 的用户（suspended/deleted）的 token 被拒绝。旧版 token（无 status 字段）兼容通过。

#### P0: 软删除全局过滤缺失 — `pin.service.ts` + `medicine-dose-logs.service.ts`

- `SecurityPinService.loadSecurityPinUser`：`findUnique` → `findFirst` + `deletedAt: null`，防止查询到已软删除的用户。
- `MedicineDoseLogsService.ensureOwned`：`userMedicineDoseLog.findUnique` → `findFirst` + `deletedAt: null`。
- `MedicineDoseLogsService.resolveReminderSlot`：`userMedicineReminder.findUnique` → `findFirst` + `deletedAt: null`。
- 同步更新对应测试文件的 mock（`findUnique` → `findFirst`）。

#### P1: 通知与持久化非原子 — `escalation.service.ts`

- 调整 `escalateIfNeeded` 中的操作顺序：先 `prisma.userSuggestion.update`（标记已通知），再 `notificationsService.createOrReplaceScoped`（发送通知）。
- 如果通知发送失败，建议已被标记为已通知，防止下一轮生成时重复发送通知。
- 更新 `escalation.service.spec.ts`：通知失败时 `updateMock` 仍被调用一次。

#### P1: /explain 和 /feedback 端点无限流 — `today-suggestion.controller.ts`

- `app.module.ts` 注册 `ThrottlerModule`（全局 100 req/min）+ `ThrottlerGuard` 作为全局 Guard。
- `POST /today/suggestions/:id/feedback`：`@Throttle({ default: { ttl: 60_000, limit: 20 } })`（20 次/分钟）。
- `POST /today/suggestions/:id/explain`：`@Throttle({ default: { ttl: 60_000, limit: 5 } })`（5 次/分钟，防止 LLM 成本失控）。

#### P1: `$queryRawUnsafe` 替换 — `app.service.ts`

- 健康检查中的 `prisma.$queryRawUnsafe('SELECT 1')` 替换为 `prisma.$queryRaw\`SELECT 1\``，获得编译时类型安全。
- 更新 `app.service.spec.ts`：mock `$queryRaw` 替代 `$queryRawUnsafe`。

### 影响

- 安全性提升：JWT 现在拒绝非 active 用户的 token；软删除用户/记录不会被 `findUnique` 查询返回。
- 数据一致性：反馈记录操作原子化；通知发送前先持久化状态。
- 可用性：建议生命周期状态不再依赖用户请求触发，定时任务每 5 分钟自动刷新。
- 成本控制：LLM 解释端点限流 5 次/分钟，反馈端点限流 20 次/分钟。
