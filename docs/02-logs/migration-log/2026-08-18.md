## H-10:事件专属建议升级通知 + suggestion topic 补全

依据 `Luminous/plans/2026-08-16-health-event-remediation-plan.md` 的改造项 3(H-10,实施完毕,计划改造项 3 小节已删):后端新增事件专属信号与规则,前端 Today 建议卡监听 `DataChangeTopic.healthEvents` 刷新。不涉及 API 契约变化、不涉及 Prisma schema 变更、未新增依赖。

### 变更

- `src/modules/today-suggestion/types/signal.types.ts`:`SignalSource` 新增 `'health_event'`。
- `src/modules/today-suggestion/services/collectors/health-event.service.ts`:新增 `HealthEventCollectorService`,经 `HealthEventsOwnershipService`(ADR-0009)读取 active 事件与 check-in 序列,并经 `DailyRecordReaderPort.countFactsInRange` 统计事件期内 symptom 记录数,生成 `event_check_in_trend` 信号。

  - 最近 3 天(含当天)存在连续 2 次 `outcome === 'worsened'` 的 check-in;
  - 事件期内存在 symptom 记录(无论 check-in 结果如何)。
  - 候选 `priorityScore = 750`、`confidence = HIGH`、`notificationEligible = true`、`triggerType = EVENT`,满足 `EscalationService` 升级阈值(≥700),主动作路由 `/report/review/:eventId`;check-in 在进入匹配前按日期升序显式排序,降低对仓库返回顺序的耦合;copy 参数不包含用户事件标题,避免进入跨用户共享的 copy cache。
- `src/modules/today-suggestion/today-suggestion.module.ts`:`imports` 加入 `HealthEventsModule`(`health-events.module` 直接导入,避免 barrel 循环);`providers` 注册 `HealthEventCollectorService` 与 `EventCheckInTrendRuleService`;`onModuleInit` rules 数组注册新规则。
- `src/modules/today-suggestion/services/pipeline.service.ts`:`run()` 的 `Promise.all` 中加入 `healthEventCollector.collect`,信号合并入总信号集。
- `src/modules/today-suggestion/constants/copy-templates.ts` 与 `constants/copy-fallback.ts`:新增 `health_event.check_in_trend` 模板、action key `review_event` 与中英 fallback 文案。
