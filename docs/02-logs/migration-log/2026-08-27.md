# 2026-08-27

## 代码审查修复 — 08-26 审查报告

基于 08-26 审查报告（`plans/Lucent-review-08-26.md`）中的 Critical、Warning 和 Suggestion 项，执行修复。

### C-1：unlinkIdentity 事务内 hasPassword 静默吞错

- `src/modules/account/services/account.service.ts`：
  - 事务内 `hasPassword` 调用从 `.then((r) => r.isOk())`（将 Err 折成 false）改为显式 `isErr()` 检查，Err 时抛 `DomainFailureException` 触发事务 rollback。
  - 区分 `Ok(false)`（用户无密码）和 `Err`（Prisma 抖动），消除正确性漏洞。
- `src/modules/account/services/account.service.spec.ts`：
  - 新增 "should propagate the hasPassword Err path inside the transaction (C-1)" 测试，覆盖事务内 `hasPassword` 返回 Err 的场景。

### C-2：eslint error-handling ChainExpression 识别不完整

- `eslint-plugins/error-handling.ts`：
  - `calleeToText` 入口统一 `unwrapChain(callee)`，`MemberExpression` 分支递归处理 `callee.object` 为 `ChainExpression` 的情况。
  - 现在 `obj?.foo.bar()`、`service?.logger.warn()`、`this?.logger?.warn()` 等中段可选链均能正确识别。
- `eslint-plugins/error-handling.spec.ts`：新增 9 个 fixture 测试，覆盖简单标识符、成员表达式、可选链（顶层/中段/多层）等场景。
- `eslint-plugins/calleeToTextInternal` 导出供测试引用。
- `vitest.eslint-plugins.config.ts`：独立 vitest 配置，使 `eslint-plugins/` 目录下的测试可以在 `src` root 之外运行。

### W-1：VictoriaLogs warn 监听器 console.error → 注入 Logger

- `src/common/logger/logger.config.ts`：
  - `LoggerOptionsInput` 新增 `fallbackLogger?: (msg: string) => void` 字段。
  - VictoriaLogs transport `on('warn')` 回调从 `console.error` 改为调用 `input.fallbackLogger`；无注入时回退到 `console.error`。
- `src/common/logger/logger.module.ts`：
  - `useFactory` 中创建 `new Logger('VictoriaLogsTransport')`，通过 `fallbackLogger` 注入。
