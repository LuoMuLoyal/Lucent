- 评估结论：保持现状不变。`new Logger('VictoriaLogsTransport')` 在 `WinstonModule.forRootAsync` 的 factory 闭包中，是 DI 工厂模式的标准用法，不依赖 DI 容器生命周期。项目中统一模式是类字段 `private readonly logger = new Logger(...)`，此 factory 非类，无法用类字段。抽成 `VictoriaLogsTransportFactory` provider 会增加间接层但无实际收益（NestJS `Logger` 是全局内置 class，`inject(Logger)` 没有意义）。审查文档亦标注"优先级低"、"保持现状亦可"。

## fix(build): git hooks 避免触发 pnpm 隐式依赖安装导致 Windows 文件锁

### 问题

`git commit` 触发 pre-commit hook 时，`pnpm lint-staged` 会导致 pnpm 12 隐式触发依赖安装（`node_modules/.bin` 缺失时 pnpm 会自动修复），而 VSCode 的 TypeScript/ESLint 语言服务正在读取 `node_modules` 中的文件，导致 Windows 文件锁错误（`os error 32`）。

### 修复

- `package.json` 中 `simple-git-hooks` 配置：
  - `pre-commit`：`pnpm lint-staged` → `npx --no-install lint-staged`
  - `commit-msg`：`pnpm exec commitlint` → `npx --no-install commitlint`
  - `pre-push`：`pnpm typecheck` → `npx --no-install tsc -p tsconfig.typecheck.json --noEmit`
- `--no-install` 标志确保 npx 不会触发隐式依赖安装，直接使用 `node_modules/.bin` 中已有的二进制文件。
- 删除并重新安装 `node_modules`（`pnpm install`）修复了 `.bin` 目录缺失问题。
