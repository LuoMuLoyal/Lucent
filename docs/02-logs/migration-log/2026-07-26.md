## locale 归一化修复与旧记录回填

### 问题

Report 页在英文状态下仍出现中文建议历史。原因有二：

1. 旧记录 `locale` 为 `null`，`getHistory` 的 `OR: [{ locale: normalizedLocale }, { locale: null }]` 会把所有无 locale 记录都带出来，不论其实际语言。
2. `persistActive` 直接写入原始 `locale`（如 `en-US`），而 `getHistory` 用 `normalizeLocale` 把 `en-US` 归一为 `en`，导致新写入的英文记录匹配不上。

### 修复

- `src/modules/today-suggestion/services/lifecycle/service.ts`：
  - `persistActive` 写入 `this.normalizeLocale(locale)`，保证存储与查询使用同一套值（`zh-CN` / `en`）。
  - `getHistory` 移除 `locale = null` 回退，只返回目标语言的记录。
- 运行一次性回填脚本：
  - 查询 `user_suggestions` 中 `locale IS NULL` 的记录；
  - 按 `title + reason` 是否含中文字符判定：`zh-CN` 或 `en`；
  - 在 development 数据库（`127.0.0.1:15432`）上回填了 8 条记录（4 条中文，4 条英文）。

### 验证

- `pnpm lint:check` 通过
- `pnpm test -- --testPathPattern="today-suggestion" --no-coverage` 通过
- 后端缓存 `suggestion:history` TTL 为 2 分钟，刷新页面或等待 2 分钟后中英文混排应消失。
