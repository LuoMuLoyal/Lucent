## 审查报告修复（来源：plans/Lucent-2026-07-19.md）

### 1. AssistantRuntimeService.runConversation 集成熔断器

#### 问题

`runConversation`（LangGraph 聊天路径）通过 `graph.invoke()` 执行 agent↔tools 循环图，内部 `agent` 节点调用 `boundModel.invoke(state.messages)` 进行 LLM 推理。但此方法没有调用 `circuitBreaker.acquire()`，也未在失败时调用 `recordFailure()`。

同类的 `generateStream` 方法已正确集成熔断器。遗漏导致 assistant 聊天场景的 LLM 调用在下游服务不可用时不会快速失败，仍然会把请求发到故障的 LLM provider，加剧过载。

#### 修复

- `src/modules/assistant/agent/runtime.service.ts`：
  - 在 `graph.invoke()` 前调用 `this.circuitBreaker.acquire()`。
  - 图执行成功后调用 `this.circuitBreaker.recordSuccess()`。
  - 图执行失败时在 catch 块中调用 `this.circuitBreaker.recordFailure()`。
  - LangGraph 的 agent↔tools 循环可能多次调用 LLM，整个 `graph.invoke()` 作为一次熔断器保护单元——任何内部 LLM 调用失败都会导致图抛出异常，从而触发 `recordFailure()`，避免双重计数。

### 2. generateStream 中 recordSuccess 推迟到流处理完毕后调用

#### 问题

`base-llm-generator.service.ts` 和 `runtime.service.ts` 两处 `generateStream` 实现中，`recordSuccess()` 在 `withLlmRetry()` 成功返回 stream 后立即调用。但后续 `for await` 循环处理流内容时，如果发生以下情况会抛出 Error，却不会调用 `recordFailure()`：

- stream 为空（`accumulated === undefined`）
- JSON 解析失败或 schema 验证失败
- 流在传输过程中连接中断

这意味着熔断器只统计"连接建立失败"，不统计"流处理失败"。当 LLM 服务处于"半可用"状态时，熔断器不会 trip。

#### 修复

- `src/common/llm/base-llm-generator.service.ts`：
  - `acquire()` 移出 try 块，避免 `LlmCircuitOpenError` 触发 `recordFailure()`。
  - 移除 stream 建立后的 `recordSuccess()`。
  - 将整个流处理阶段（`for await` 循环 + 空流检查 + `parseResult` + `schema.parse`）包裹在 try-catch 中。
  - `recordSuccess()` 推迟到 `schema.parse(result)` 成功后调用。
  - 流处理 catch 块中调用 `recordFailure()`。
- `src/modules/assistant/agent/runtime.service.ts`：
  - 同样的模式：`acquire()` 移出 try 块，`recordSuccess()` 推迟到 `finalContent` 非空后，流处理 catch 块中调用 `recordFailure()`。

### 3. recordFailure 在 open 状态下提前返回

#### 问题

`recordFailure()` 在 `closed` 分支前没有 `open` 状态保护。当熔断器已经是 `open` 状态时，`recordFailure()` 会进入 `closed` 分支并增加 `consecutiveFailures`。虽然 `trip()` 内部有 `if (this.state === 'open') return;` 保护，但 `consecutiveFailures` 计数器会持续累加，导致 `snapshot()` 返回的计数不准确，可能误导监控面板。

#### 修复

- `src/common/llm/llm-circuit-breaker.service.ts`：
  - `recordFailure()` 开头新增 `if (state === 'open') return;` 保护。
  - 更新方法文档注释，说明 `open` 状态下是 no-op。
