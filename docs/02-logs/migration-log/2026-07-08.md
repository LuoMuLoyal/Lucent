## Lucent — OpenAPI 合同修复（Flutter 客户端 P0 崩溃 + P1 类型丢失）

修复后端 Swagger/OpenAPI 定义中因 `nullable: true` 未显式标注 `type` 而导致 Flutter 生成客户端出现的问题：

- **P0 运行时崩溃**：`page` 等 `int` 字段在生成代码中调用 `.toJson()`，导致 `int.toJson is not a function` 崩溃。
- **P1 类型丢失**：大量可空字段在 OpenAPI 导出后变为 `dynamic`，丢失类型安全。

### 修复内容

1. **medicine-query.dto.ts**：`page` / `pageSize` 的 `@ApiPropertyOptional` 补充 `type: Number`，消除 P0 崩溃。
2. **assistant.controller.ts**：SSE 流端点补充 `content: { 'text/event-stream': { schema: { type: 'string' } } }` 标注；`/clear` 端点提取具名 DTO `AssistantClearResultResponseDto`。
3. **批量 DTO 修复（16 个文件，87 处）**：所有 `nullable: true` 字段补充 `type: String` 或 `type: Number`，覆盖 medicines、medicine-dose-logs、medicine-reminders、daily-records、user-health-context、reports、today-analysis、assistant 等模块。
4. **openapi.json 重新导出**：`pnpm export:openapi` 后 OpenAPI spec 中 `dynamic` 字段从 129 个降至 7 个（剩余均为合理泛型/对象类型）。
5. **Flutter 客户端重新生成并验证**：`dart run openapi_retrofit_generator` + `dart run build_runner build` 后 `flutter analyze` 零错误零警告。
