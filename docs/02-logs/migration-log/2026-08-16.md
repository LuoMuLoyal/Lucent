## 代码审查修复：回执日期校验收紧与调度器兜底强化

针对提交 a36483d2（提醒投递三通道落库与本地回执接口）的代码审查意见修复：

- **回执 DTO**：`ReminderDeliveryReceiptDto.scheduledDate` 校验由 `@IsDateString()` 收紧为 `@Matches(/^\d{4}-\d{2}-\d{2}$/)`（带 message，与 `scheduledTime` 风格一致）——完整 ISO 时间戳此前能通过 `IsDateString` 却使 `wallClockToScheduledFor` 得到 NaN（RangeError → 500），现非法输入直接 400。
- **调度器**：`readLocalCapability` 捕获缓存读取异常并 warn 一次后按 `unconfirmed` 继续走 JPush 兜底，不再让缓存故障把整条 dispatch 拖进 catch（此前 in_app 行已写、下一 tick 去重跳过，push 兜底静默丢失）。
- **PushDeliveryService**：未配置分支返回 `{ sent: false, errorMessage: 'push_not_configured' }`（替代 errorMessage 缺失），审计行可区分「未配置」与「真失败」。
- **测试**：补非法 scheduledDate 校验用例（unit + e2e）、local 行 findFirst `channel:'local'` 断言、缓存异常回退按 unconfirmed 发 push、push 未配置落 failed 行（`errorMessage='push_not_configured'`）、并发 double-report 幂等返回同一行；同步更新受影响断言。
- **F-4 小节修正**：Luminous 仓库的计划文件（路径见 F-4 小节）仍然存在——F-4 仅完成 Lucent 后端部分，F-3 部署 / F-4 客户端 / F-6 / F-7 未完成，后续由 Luminous 侧完成各小节后删除；此前「实施完毕文件已删」表述失实，已如实更正。
