## 提醒投递记录三通道落库与本地回执接口（F-4）

依据 2026-08-16 平台通知横切改造计划（Luminous 仓库，实施完毕文件已删）的 F-4 项实施 Lucent 侧后端：提醒投递审计从单一 `in_app` 通道扩展为 in_app / local / push 三通道，并新增本地回执与本地调度能力上报接口（ADR-0013；修订 ADR-0011 唯一约束部分）。

### 变更范围

- **Prisma**：`UserReminderDelivery` 唯一约束由 `(userId, reminderId, scheduledFor)` 改为 `(userId, reminderId, scheduledFor, channel)`（同一事件三通道各一行）。migration `20260816120000_reminder_delivery_channel_unique` 因 dev 库存在既有 drift（langgraph checkpoint 等表不在迁移历史内）改用 schema-datamodel diff 生成并手工落盘，`pnpm db:migrate:all` 已应用到 dev + test；历史行 channel 全为 in_app 且旧约束保证无重复，无需清理。
- **调度器**：`dispatchSingle` 新流程——in_app 去重（channel 过滤）→ 站内通知 → in_app 行 → local 行检查（存在则跳过 push）→ 本地能力门控（`reminder:local-capability:{userId}` 缓存，TTL 14 天；active/disabled 不发 push，unconfirmed/unavailable 才发）→ push 发送 → 按 `{ sent, errorMessage? }` 落 delivered/failed 行（skipDuplicates 幂等）。「先发通知、后写记录」与失败重试语义不变。
- **PushDeliveryService**：`sendToUser` 返回 `Promise<PushSendResult>`（永不 reject；未配置返回 `{ sent: false }`）。
- **新接口**：`POST /api/v1/user/reminder-deliveries/receipts`（本地回执，墙钟时间按 profile 时区换算 UTC 截断分钟，归属 404 校验，幂等 upsert）与 `PUT /api/v1/user/reminder-deliveries/local-capability`（能力上报，class-validator 枚举校验）。
- **时区工具**：`services/delivery-moment.ts` 抽出 `DEFAULT_TIMEZONE` / `formatLocalDate` / `wallClockToScheduledFor`（Intl offset 方式），scheduler 与回执服务共用，调度器行为不变。
- **文档**：新增 ADR-0013（并回注 ADR-0011 与 ADR README 索引）；更新 `reminder-contract.md`（三通道模型与新接口、Phase H）、`code-quality.md`（双通道→三通道描述 + 本次条目）；`docs/00-current/TODO.md` 无投递相关待办，无删除项。
