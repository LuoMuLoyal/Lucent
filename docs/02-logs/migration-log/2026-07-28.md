## Medicines — 风险检查健壮性修复

### 修复 1：MedicineRiskCheckListener 实现 OnModuleDestroy

- **文件**: `src/modules/medicines/services/medicine-risk-check.listener.ts`
- **变更**: 实现 `OnModuleDestroy` 接口，`onModuleDestroy()` 清理所有 pending debounce timer
- **原因**: 应用 graceful shutdown 时未触发的 5s timer 会在 Prisma 连接断开后执行 `runStaticCheck()`

### 修复 2：evaluateStaticCheck 和 buildLlmContext 并行化药品详情查询

- **文件**: `src/modules/medicines/services/medicine-risk-check.service.ts`
- **变更**: 将两处串行 `for` 循环改为 `Promise.allSettled` 并行调用
- **原因**: N+1 串行查询导致 API 响应时间随药品数量线性增长
- **实现**: 使用 `flatMap` 替代 `filter` + `!` 断言，在 filter 阶段提取 `source` 和 `sourceRefId` 避免非空断言

### 修复 3：persistRecord 和 markStale 缓存删除容错

- **文件**: `src/modules/medicines/services/medicine-risk-check.service.ts`
- **变更**: `cache.del()` 包裹 try-catch，失败时 warn 日志降级
- **原因**: Redis 瞬断导致缓存删除失败会使整个 API 调用失败，但 DB 已写入正确数据，TTL 兜底

## Support Resources — help-feedback 动态激活

- **文件**: `src/modules/support-resources/services/resources.service.ts`
- **变更**: `getResources()` 返回前遍历 items，当 `id === 'help-feedback'` 且 `appInfo.supportEmail` 非空时，动态注入 `actionUrl: mailto:{email}?subject=...`、`actionType: 'url'`、`available: true`
- **原因**: 原静态条目 `available: false`，Help 页始终显示空态。配置了 `SUPPORT_EMAIL` 后应自动激活
- **实现**: 使用显式属性拷贝而非 spread operator（避免 `@typescript-eslint/no-misused-spread` 警告）

## Data Export — GET /latest 移除安全提权要求

- **文件**: `src/modules/data-export/data-export.controller.ts`
- **变更**: 移除 `GET /data-export-requests/latest` 上的 `@RequireSecurityElevation()` 装饰器
- **原因**: `GET /latest` 是只读状态查询，用户已通过 JWT 认证。前端在报告页 UI 中展示导出状态时不需要每次输入 PIN。真正敏感的 `POST /data-export-requests`（创建导出）仍保留提权要求
- **测试**: `test/security/elevation-and-idor.e2e-spec.ts` 中 "should reject data-export GET/latest without elevation token" 改为 "should accept data-export GET/latest without elevation token"，期望 200 而非 403
- **文档**: `docs/00-current/Auth_Security_PIN.md` 同步更新
