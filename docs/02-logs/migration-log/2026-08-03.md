### 追踪启动环境加载路径稳健性

- `src/tracing.ts`
  - `loadTracingEnvironment()` 由 `join(process.cwd(), envFilePath)` 改为 `join(__dirname, '..', envFilePath)`：`__dirname` 在 dev（`src/`）与 `nest build` 产物（`dist/`）下均指向项目根的子目录，单级 `'..'` 即定位到项目根，规避 PM2 / systemd / Docker 下工作目录非项目根导致 `.env.<NODE_ENV>` 无法定位、OTel 无声失效的问题（与 08-02 已修复的 Scalar 路由同一模式）。
- `src/tracing.spec.ts`
  - 测试 mock 内由直接赋值 `process.env['OTEL_ENABLED'] = 'true'` 改为 `vi.stubEnv('OTEL_ENABLED', 'true')`：`vi.unstubAllEnvs()` 现在能完整清理，避免环境变量残留导致后续测试非确定性行为（`OTEL_ENABLED=true` 意外启动 OTel SDK）。

### Scalar bundle 缓存版本化

- `src/setup-app.ts`
  - `/scalar/standalone.js` 的 `cdn` 路径改为嵌入 `@scalar/api-reference` 解析版本号（`?v=<version>`，去掉 `^`/`~` 前缀）：依赖升级后 URL 变化，浏览器 `immutable` 缓存自然失效，不再长期缓存旧 bundle。读取失败时回退无版本 URL。
  - 路由路径不变（query string 不参与 Fastify 路由匹配），`Cache-Control: public, max-age=31536000, immutable` 头保持。
