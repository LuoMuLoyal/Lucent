# 2026-08-24

## Better Auth 用户表合并与 NestJS Adapter（Task 2）

完成 Better Auth 核心 user schema 与 Lucent 既有 `User` 模型的合并，并创建生产可用的 NestJS adapter。

### Schema 变更

- `prisma/models/user.prisma`：
  - `User.email` 由 `String?` 改为 `String`（必填，`@unique` 保留）。
  - 新增 `User.emailVerified Boolean @default(false) @map("email_verified") @db.Boolean`。
  - 原 `sessions UserSession[]` 关系重命名为 `lucentSessions UserSession[]`（并指定关系名 `lucentSessions`）；新增 Better Auth 的 `sessions Session[]` 与 `accounts Account[]` 关系。
- `prisma/models/better-auth.prisma`：
  - 删除独立的 `BAUser` 模型。
  - `Session.user` / `Account.user` 外键与关系指向 `User`（`onDelete: Cascade`）。
  - `Verification` 模型保持不变。
- 运行 `pnpm prisma:generate` 与 `NODE_ENV=test pnpm exec prisma db push --accept-data-loss`，测试库 schema 已同步。

### NestJS Adapter

- 新建 `src/modules/auth/adapters/better-auth.adapter.ts`：
  - `@Injectable()` service `AuthBetterAuthAdapter`，注入 `PrismaService` 与 `ConfigService`。
  - 通过 `prismaAdapter(prisma, { provider: 'postgresql' })` 使用注入的 Prisma client。
  - `secret` 取自 `BETTER_AUTH_SECRET`，缺失时抛错；`baseURL` 依次取 `BETTER_AUTH_URL`、`PUBLIC_BASE_URL`、默认 `http://localhost:3000`。
  - `user.modelName: 'User'`，字段映射 `name -> nickname`、`image -> avatar`。
  - `emailAndPassword.enabled: true`，password hash/verify 复用既有 `argon2` 与 `ARGON2_OPTIONS`。
  - 公开 `readonly auth` 属性，供后续任务调用 `auth.api.signUpEmail` 等。
- `src/modules/auth/auth.module.ts`：注册 `AuthBetterAuthAdapter` 并 export，不删除/替换现有 auth provider/controller/service。
- `src/config/env/environment.validation.ts`：
  - `BETTER_AUTH_SECRET` 改为 `z.string().min(32)` 必填。
  - 加入 `assertProductionEnvironment` 必填列表。
  - `BETTER_AUTH_URL` 保持可选 URL。
- `src/config/env/environment.validation.spec.ts`：所有 `validateEnvironment` 调用补充 `BETTER_AUTH_SECRET`。

### 业务代码与测试适配

- `src/modules/user/services/user.service.ts`：`CreateOAuthUserInput.email` 改为必填；`createOAuthUser` 始终写入 `email`。
- `src/modules/auth/services/oauth/oauth.service.ts`：`createOAuthUser` 在 `profile.email` 缺失/为空时返回 `VALIDATION_FAILED` 业务失败，不构造占位邮箱；已提前返回的邮箱在 identity 中直接 `normalizeEmail(profile.email)`。
- `test/helpers/e2e-helpers.ts`：`user.email ?? userEmail` 改为 `user.email`（必填后不再可能为 null）。
- spec mock 统一补充 `emailVerified` 字段：`auth.service.spec.ts`、`credential.service.spec.ts`、`oauth.service.spec.ts`、`health-context.service.spec.ts`、`user.service.spec.ts`。
- `credential.service.spec.ts`：移除/改写「用户无 email」的 `setPassword` 测试（email 必填后该分支不可达），改为验证「dto 提供 email 时验证码发送到该邮箱」。

### 已知影响与 Task 3 建议

- 破坏性变更：`User.email` 必填、`User.emailVerified` 新增、`User.sessions` 关系改名为 `lucentSessions`；已全量修复 src/test 中受影响 mock。
- OAuth-only 注册现在强制要求邮箱，否则返回 `VALIDATION_FAILED`；若后续需要支持无邮箱 OAuth，需与产品确认并设计独立流程（如强制绑定邮箱）。
- Better Auth `signUpEmail` 默认要求 `name` 字段，映射到可选的 `nickname` 后，注册请求仍需客户端提供 name；Task 3 暴露注册接口时须注意前端是否已发送 name，或在调用层补充默认值。
- Task 3 建议：
  1. 用 `AuthBetterAuthAdapter.auth.api.signUpEmail` 替代现有 credential register 写路径，逐步废弃 `CredentialAuthService.register` 中的手写密码 hash。
  2. 保留 `User.password_hash` 与现有 login 路径并行，直到 Task 3/4 完成切换与数据迁移。
  3. 确认是否需要将旧 `email_verified_at` 与 Better Auth 的 `email_verified` 同步（目前两个字段并存，可互补）。
  4. 任务 3 暴露 HTTP 路由前，需确保 `BETTER_AUTH_SECRET` 在生产环境已配置且长度 >= 32。
