# Migration Log — 2026-08-13

## Review Experience — Task 1 event review read model

- reports 模块新增 event review 读模型骨架：`EventReviewDataDto`（event identity/status/window/outcome、四段 section `whatHappened/keyChanges/completedActions/nextStep`、coverage summary、source timestamps、available actions）与 `EventReviewListQueryDto`（status/cursor/limit，时间范围不作为首屏必选项）。
- 每个 section 使用 `state: available|unknown`；unknown 只返回固定 reason code（`no_observations`、`no_completed_actions`），不返回编造 copy；available 返回结构化 `code/arguments` 基础事实，供 Task 2 逐段替换计算而不改 DTO 形状。
- `EventReviewService` 提供 `buildForEvent`（foreign/不存在事件经 ownership 服务返回 not found）、`buildCurrent`（active 优先，否则最近 ended，无事件返回 null）与 `list`（status + cursor 分页）；只读 health-events 所有权门面、daily-record/dose-log reader port，不复制 dashboard/suggestion 的聚合口径。
- `HealthEventsOwnershipService` 增加只读方法 `findActive`、`findMostRecentEnded`、`findTodayCheckIn`、`findCheckInCoverage`、`findManyByUser`，并随 barrel 导出 `HealthEventRecord` 等只读类型；软删除事件与记录由 repository 的 `deletedAt: null` 过滤与 reader port 的 `nonDeleted` 保证不参与回顾。
- 覆盖 active、ended、稀疏数据、无事件、foreign event 五种场景的 service spec 8 tests 通过；`pnpm typecheck`、`pnpm lint:check --max-warnings=0` 与全量 294 files / 3080 tests 通过。Review Experience 计划继续执行 Task 2（四段 section 子服务），controller/endpoint 留待 Task 3。

## Review Experience — Task 1 代码质量复审修复

- cursor 分页改为复合 cursor（`startedAt ISO|id`）编码/解析，过滤使用 `startedAt < cs OR (startedAt = cs AND id < ci)`，同 startedAt 事件不再在页边界被静默跳过；DTO cursor 改为不透明字符串并说明格式，malformed cursor 返回 bad request。spec 新增同 startedAt 跨页回归用例与 malformed cursor 用例。
- 新增 `ownership.service.spec.ts`：覆盖无 profile 时区回退 `DEFAULT_USER_TIMEZONE` 的"今天"解析、按 profile 时区解析、`findMostRecentEnded` 依赖 repository `startedAt desc` 排序取最新 ended（含仅 active 时返回 null）、`findCheckInCoverage` 空/非空形状以及 `findActive`/`findManyByUser` 委托。
- review service 对缺失 `event.kind` 改为显式抛错，不再静默回退 `symptom`；`reasonCode` 收紧为 `'no_observations' | 'no_completed_actions'` 字面量联合，Task 2 可继续扩展。
- 跟进项（Task 2/3）：reader port `MAX_READER_FACTS=500` 截断使 `observedCount` 与 `sourceTimestamps` 成为 capped 摘要，应改为 count/latest 专用查询；`list()` 内存过滤/分页、`findMostRecentEnded` 全量拉取、`buildCurrent` 双重读取三处简化应下推到 repository 或收敛为内部 assembler。

## Review Experience — Task 2 四段 section 子服务

- 新增四个 section 子服务替换 review.service 的私有骨架 builder，DTO 形状不变：`facts`（code `health_event`：kind/title/startedAt/endedAt/medicineIds/symptomRecordCount/checkInCount，无自由文本 note）、`changes`（code `observed_changes`：check-in 首末 outcome 趋势 + water/sleep 单维趋势，维度不足为 null；未知返回 `no_observations`/`insufficient_coverage`，不输出因果断言文案）、`actions`（code `completed_actions`：按 reminder 槽位统计 confirmed/skipped/unconfirmed，planned/missed 归为 unconfirmed 不算失败，并列出已完成的 check-in）、`next-step`（code `active_check_in`/`event_ended` 固定规则 + 复用药物风险静态检查的 `severeAllergy`/`informationGap` red flag 结构化规则，无 LLM、无自由文案）。`EventReviewSectionReasonCode` 扩展 `insufficient_coverage`。
- reader port 新增专用查询，coverage 计数与 sourceTimestamps 最新值不再由 `MAX_READER_FACTS=500` 截断列表推导：daily-records `countFactsInRange`/`findLatestCreatedAtInRange`，medicine-dose-logs `countFactsInRange`/`findLatestScheduledForInRange`。health-events repository 新增 `findCheckIns`（date asc 序列）与 `findMostRecentEndedByUserId`（status=ended + startedAt desc 定向查询），ownership 门面同步暴露，`findMostRecentEnded` 不再全量拉取。
- `MedicineRiskCheckService` 随 MedicinesModule 导出；review 的 next-step 读取持久化静态检查 redFlags 并映射为结构化 `rule/medicineName/relatedLabel`，读取失败降级为空列表，不阻断回顾。
- 验证：四个 section spec 26 tests + review service spec 13 tests + ownership/repository/reader port 定向测试通过；全量 `pnpm test`（299 files / 3128 tests）、`pnpm typecheck`、`pnpm lint:check --max-warnings=0` 通过。controller/endpoint 尚未接入，OpenAPI 暂无新增 path。list 内存分页下推与 `buildCurrent` 双重读取收敛仍为 Task 3 跟进项。
