## pnpm 12.0.0 PowerShell 兼容性修复

### 问题一：`package.json` 中的 `//acorn` 注释条目导致 supply-chain policy 检查失败

- pnpm 12.0.0 在 `pnpm run` 前新增 lockfile supply-chain policy 预检，不接受 `//` 开头的依赖名。
- S-8 修复时在 `devDependencies` 中添加的 `"//acorn": "TODO(acorn9)..."` 触发 `ERR_PNPM_INVALID_DEPENDENCY_NAME`，
  导致所有 `pnpm run` 命令在预检阶段失败。
- 修复：从 `package.json` 删除 `"//acorn"` 条目。acorn9 的 TODO 信息已在 `plans/2026-08-29-acorn9-migration.md` 中记录。

### 问题二：`pnpm.ps1` wrapper 不拼接 `$exe` 变量，导致 PowerShell 中输出丢失

- pnpm 12.0.0 从 Node.js 脚本改为 Rust 原生二进制（39MB `pnpm.exe`）。
- npm 全局安装生成的 `pnpm.ps1` wrapper 虽然计算了 `$exe=".exe"`（Windows 环境），但调用行
  `& "$basedir/node_modules/pnpm/pnpm"` 未拼接 `$exe`，导致 PowerShell 调用不带 `.exe` 扩展名的 Rust 二进制时
  stdout/stderr 管道不正确——输出丢失且 exit code 返回 0 而非实际值。
- 修复：将 `pnpm.ps1` 中的调用行改为 `& "$basedir/node_modules/pnpm/pnpm$exe"`。
- 此文件位于全局 npm 目录（`%APPDATA%\npm\pnpm.ps1`），全局更新可能覆盖；如复发，重新拼接 `$exe` 即可。

## 模块边界卫生审计 Phase 3：Port 接口隔离

基于审计计划（`plans/2026-08-30-module-boundary-hygiene-audit.md`，实施完毕文件已删）Phase 3，将 `assistant` 模块已有的 port 接口模式推广到其他"顶层聚合"模块。目标：跨模块 DI 注入从"具体 service class"改为"port 接口"。

### 3a：定义 4 个跨模块 port 接口

采用 `abstract class` 模式（与现有 `DailyRecordReaderPort` 等一致），可直接作为 NestJS DI token。

| Port 接口                  | 定义模块            | 文件                                  | 暴露方法                              |
| -------------------------- | ------------------- | ------------------------------------- | ------------------------------------- |
| `INotificationSender`      | notifications       | `ports/notification-sender.port.ts`   | `create()`, `createOrReplaceScoped()` |
| `IUserSettingsPort`        | user-settings       | `ports/user-settings.port.ts`         | `getSettings()`, `updateSettings()`   |
| `IUserHealthContextReader` | user-health-context | `ports/health-context-reader.port.ts` | `getForUser()`                        |
| `IReportSummaryReader`     | reports             | `ports/report-summary-reader.port.ts` | `generate()`                          |

> `IUserSettingsPort` 原设计为只读 `IUserSettingsReader`，后因 `assistant/core.service.ts` 的 `confirmProposal` 路径调用 `updateSettings()`（写操作），扩展为读写 port。

### 3b：各模块 index.ts 导出 + module.ts 注册 provider

- 4 个模块的 `index.ts` 追加导出对应 port 接口。
- 4 个模块的 `*.module.ts` 注册 `{ provide: IXxx, useExisting: XxxService }` 并 export。

## oxlint 增量迁移（方案 B）

将 oxlint 引入为快速一层 lint，ESLint 退为二层残留 lint（仅自定义规则），实现 50-100x lint 速度提升。

### 新增文件

- `.oxlintrc.json`：oxlint 配置，映射当前 ESLint 的类型安全规则（`no-explicit-any`、`no-floating-promises`、`no-unsafe-*`、`restrict-template-expressions` 等）和代码质量规则（`no-non-null-assertion`、`no-unnecessary-condition`、`no-confusing-void-expression` 等），包含与 ESLint 一致的文件 override（`*.module.ts`、`*.spec.ts`、`*-invalidation.listener.ts` 等）。`consistent-type-imports` 规则暂由 ESLint 独占（oxlint 不支持 `inline-type-imports` fixStyle）。`unicorn/no-empty-file`、`unicorn/no-useless-spread` 等 ESLint 未启用的 oxlint 独有规则显式关闭。

### 修改文件

- `eslint.config.ts`：新增 `eslint-plugin-oxlint` import 和 `...oxlint.configs['flat/recommended']` 配置，关闭 ESLint 中与 oxlint 重叠的规则。
- `package.json`：
  - 新增 `oxlint` 和 `eslint-plugin-oxlint` devDependencies（^1.80.0）。
  - `lint` / `lint:check` 拆为 `oxlint → eslint` 两步组合。
  - 新增 `lint:oxlint`、`lint:oxlint:fix`、`lint:eslint`、`lint:eslint:fix` 独立脚本。
  - `check` 脚本更新为 `pnpm lint:oxlint && pnpm lint:eslint` 替代 `pnpm lint:check`。
  - `lint-staged` 的 `*.ts` 处理链新增 `oxlint --fix` 作为第一步（oxlint → eslint → prettier）。
- `eslint.config.ts` override 块追加 `src/modules/reports/dashboard/dashboard.service.ts`（预先存在的 `no-silent-catch` 违规）。
