### 单 slot 停机部署（#1/#2/#3，含 ADR-0004 修订）

砍掉蓝绿双 slot，改单 slot 停机部署（决策见 ADR-0004 的 2026-07-17 修订）：

- `deploy/deploy.ts` 全面重写为 12 步单 slot 流程：
  1. 前置检查 + 补齐目录 + 运行 `render-configs.sh`（失败仅警告）
  2. 读取当前 `LUCENT_IMAGE` 作为回滚目标
  3. `.env` → `.env.previous` 快照移到**任何修改之前**（修复旧蓝绿流程回滚拿到新版本的 bug）
  4. 启动 postgres + redis 并等健康
  5. 部署前 `pg_dump | gzip` 快照（`data/backups/pre-deploy-*`，保留 10 份；失败即中止发布，app 未停、零影响）
  6. `docker compose stop app`（停机窗口开始，15~45s）
  7. 新镜像独立容器跑 `prisma migrate deploy`（失败则重启旧 app）
  8. 行级更新 `.env` 的 `LUCENT_IMAGE`（保留注释格式，`chmod 600`）
  9. 启动 app + 健康门禁（轮询容器健康状态 ~150s，失败打印 200 行日志并自动恢复上一镜像）
  10. `nginx -s reload`（重解析 upstream 缓存的容器 IP，否则全站 502）
  11. smoke test（失败同样自动恢复）
  12. 完成
- `deploy/compose.yml`：`app-blue`/`app-green` 双服务合并为单 `app` 服务（`lucent-app`）
- `deploy/nginx/nginx.conf`：upstream 简化为单后端 `app:3000`，注释说明 reload 必要性
- `deploy/smoke.ts`：移除双 slot 判定，固定容器名 `lucent-app`，required services 加 `app`
- 回滚：`node deploy.ts --rollback` 从 `.env.previous` 取上一镜像 tag 重部；**schema 不回退**，文档已明确
- Migration 纪律写入 deployment.md：stop → migrate → start；migration 计入停机窗口；破坏性变更建议 expand-contract（降级为优化项）；CI 有破坏性 migration 检测（见下）
