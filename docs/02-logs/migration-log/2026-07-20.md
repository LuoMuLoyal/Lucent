## 补充审查修复：`generate()` 中 `acquire()` 位置缺陷（来源：plans/Lucent-2026-07-20.md 第 6 节）

### 问题

`base-llm-generator.service.ts` 的 `generate()` 方法中 `this.circuitBreaker.acquire()` 位于 try 块内（第 67 行），而同文件的 `generateStream()` 和 `runtime.service.ts` 的两个方法均已将 `acquire()` 移至 try 块外。

当熔断器处于 `halfOpen` 状态且探针已耗尽时：

1. `acquire()` 抛出 `LlmCircuitOpenError`（未递增 `halfOpenInFlight`）
2. catch 块调用 `recordFailure()`
3. `recordFailure()` 看到 `halfOpen` 状态 → 递减 `halfOpenInFlight`（计数器被破坏）→ 调用 `trip()` → 熔断器重新打开

这导致未实际调用 LLM 的请求会错误地将熔断器从 `halfOpen` 打回 `open`，并且 `halfOpenInFlight` 计数器被错误递减，可能导致额外探针泄漏。

### 修复

- `src/common/llm/base-llm-generator.service.ts`：将 `generate()` 中 `this.circuitBreaker.acquire()` 从 try 块内移至 try 块前，与 `generateStream()` 保持一致。
- `src/common/llm/base-llm-generator.service.spec.ts`：
  - 更新原有 `open` 状态测试的名称和注释（`recordFailure()` 不再被调用）。
  - 新增 `halfOpen` 探针耗尽回归测试，使用 `vi.useFakeTimers()` 控制时间推进，验证 `generate()` 抛出 `LlmCircuitOpenError` 后熔断器仍保持 `halfOpen` 状态。

### 验证

- `pnpm test -- src/common/llm/ src/modules/assistant/agent/`：8 文件 / 154 测试全部通过。
- `pnpm lint:check`（变更文件）：零问题。

## 新增：药品提醒调度器（ReminderSchedulerService）

### 背景

发版前审计（`plans/2026-07-20-pre-release-audit.md` P0 项 A2）发现：`UserMedicineReminder` 模型和 `MedicineRemindersService` CRUD 完整，但无 `@Cron` 调度器扫描到期提醒，`UserReminderDelivery` 表永远为空——用户设置的药品提醒永远不会触发。

### 变更

- `src/modules/medicine-reminders/services/scheduler.service.ts`（新增）：`ReminderSchedulerService`，`@Cron('* * * * *')` 每分钟扫描所有活跃、未删除的提醒，按用户时区（`UserProfile.timezone`，默认 `Asia/Shanghai`）计算本地时间，匹配 `scheduledHour:scheduledMinute` + `daysOfWeek` + `startDate/endDate` 窗口。匹配后创建 `UserReminderDelivery` 记录（channel=`in_app`, status=`delivered`）并调用 `NotificationsService.createOrReplaceScoped` 发送站内通知（type=`medicine_reminder`）。投递记录按 `(reminderId, scheduledFor)` 去重。
- `src/modules/medicine-reminders/services/scheduler.service.spec.ts`（新增）：15 个单元测试覆盖空查询、时间不匹配、daysOfWeek 过滤、日期窗口、去重、多提醒、时区匹配、查询失败容错、单条投递失败容错等场景。
- `src/modules/medicine-reminders/services/index.ts`：导出 `scheduler.service`。
- `src/modules/medicine-reminders/medicine-reminders.module.ts`：导入 `NotificationsModule`，注册 `ReminderSchedulerService` 为 provider。

### 验证

- `npx eslint`（变更文件）：零问题。
