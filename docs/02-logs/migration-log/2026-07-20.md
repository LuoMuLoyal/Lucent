# 2026-07-20 迁移日志

## 补充审查修复：`generate()` 中 `acquire()` 位置缺陷（来源：plans/Lucent-2026-07-20.md 第 6 节）

### 问题

`base-llm-generator.service.ts` 的 `generate()` 方法中 `this.circuitBreaker.acquire()` 位于 try 块内（第 67 行），而同文件的 `generateStream()` 和 `runtime.service.ts` 的两个方法均已将 `acquire()` 移至 try 块外。

当熔断器处于 `halfOpen` 状态且探针已耗尽时：

1. `acquire()` 抛出 `LlmCircuitOpenError`（未递增 `halfOpenInFlight`）
2. catch 块调用 `recordFailure()`
3. `recordFailure()` 看到 `halfOpen` 状态 → 递减 `halfOpenInFlight`（计数器被破坏）→ 调用 `trip()` → 熔断器重新打开

这导致未实际调用 LLM 的请求会错误地将熔断器从 `halfOpen` 打回 `open`，并且 `halfOpenInFlight` 计数器被错误递减，可能导致额外探针泄漏。

### 修复

- `src/common/llm/base-llm-generator.service.ts`：将 `generate()` 中 `this.circuitBreaker.acquire()` 从 try 块内移至 try 块前，与 `generateStream()` 保持一致。
- `src/common/llm/base-llm-generator.service.spec.ts`：
  - 更新原有 `open` 状态测试的名称和注释（`recordFailure()` 不再被调用）。
  - 新增 `halfOpen` 探针耗尽回归测试，使用 `vi.useFakeTimers()` 控制时间推进，验证 `generate()` 抛出 `LlmCircuitOpenError` 后熔断器仍保持 `halfOpen` 状态。
