## 错误处理基础设施层扫尾 — P1 裸 throw 收口

将基础设施层四处裸 `throw new Error` 改为抛 `DomainFailureException`，使 `ApiExceptionFilter` 能正确
映射 HTTP status（503 `DEPENDENCY_UNAVAILABLE` 或 500 `INTERNAL_ERROR`），而非无差别 500。

### P1-1：domain-failure.ts 裸 throw

- `src/common/result/domain-failure.ts`：`createDomainFailure` 校验失败时，由裸 `throw new Error`
  改为 `throw new DomainFailureException({ _tag, kind: 'internal', code: 'INTERNAL_ERROR', ... })`。
  避免递归调用 `createDomainFailure`，直接构造字面量对象。

### P1-2：domain-failure.mapper.ts 裸 throw

- `src/common/result/domain-failure.mapper.ts`：`toProblemDetails` 校验失败时，由裸 `throw new Error`
  改为 `throw new DomainFailureException`，携带 `INTERNAL_ERROR` DomainFailure。

### P1-3：RedisService.atomicIncrement 裸 throw

- `src/common/redis/redis.service.ts`：Redis 不可用时由裸 `throw new Error('Redis is not available')`
  改为 `throw new DomainFailureException(createDomainFailure({ kind: 'dependency', code: 'DEPENDENCY_UNAVAILABLE', retryable: true }))`。
  调用方 `VerificationCodeService` 和 `AuthRateLimitService` 通过 `lift` 包装后，
  `DomainFailureException` 被 `mapUnknownToDependencyFailure` 正确识别为 503 而非 500。

### P1-4：S3StorageRuntime.createSignedGetUrl 裸 throw

- `src/common/storage/s3.runtime.ts`：外部端点未配置时由裸 `throw new Error` 改为
  `throw new DomainFailureException(createDomainFailure({ kind: 'dependency', code: 'DEPENDENCY_UNAVAILABLE' }))`。

### 测试

- `domain-failure.spec.ts`：kind/code 拒绝测试改为验证抛出 `DomainFailureException` 类型。
- `domain-failure.mapper.spec.ts`：mapper 拒绝测试改为验证抛出 `DomainFailureException` 类型。
- `redis.service.spec.ts`：`atomicIncrement` 不可用测试改为验证抛出 `DomainFailureException`。
- `verification-code.service.spec.ts`：17 个测试全部通过，调用方不受影响。
- 共 37 个测试通过，lint 和 typecheck 通过。

### P1 提交结构

- P1-1/P1-2（domain-failure + mapper）与 P1-3/P1-4（Redis + S3）分两批原子化提交。

### 业务代码裸 throw 收口

### ESLint 自定义规则 — 错误处理预防机制

新增两条 ESLint 自定义规则，从源头预防 ADR-0012 违规：

- `eslint-plugins/error-handling.ts`：本地 ESLint 插件，定义两条规则：
  - `no-bare-throw-error`：禁止非 spec 文件中使用 `throw new Error(...)`，
    强制使用 `DomainFailureException` 或 NestJS `HttpException` 子类。
  - `no-silent-catch`：禁止空 catch 块或无日志/无 re-throw 的 catch 块。

  - 新增 override 块：20 个现有违规文件暂时关闭规则，每修复一个文件就从
    列表中删除对应条目。TODO 注释标记清理完毕后删除整个 override 块。
  - `eslint-plugins/` 目录加入 ignores 列表。
- 已修复文件添加 `// eslint-disable-next-line` 豁免注释：
  - `prisma.service.ts`（构造函数 env 校验）
  - `registry.service.ts`（启动阶段不变式）
  - `worker.service.ts`（4 处控制流异常 + 1 处延迟 catch）
  - `processor.service.ts`（BullMQ worker re-throw）

### AGENTS.md 错误处理规则

- `AGENTS.md`：新增 "Error Handling Rules (ADR-0012)" 章节，明确四条规则：
  1. 禁止裸 `throw new Error()`（构造函数/init 阶段豁免）
  2. 禁止静默 catch（延迟 catch 需豁免注释）
  3. 缓存调用必须有 try-catch 保护
  4. 控制流异常应重构为判别联合返回
