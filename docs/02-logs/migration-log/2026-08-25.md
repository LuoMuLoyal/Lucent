# 2026-08-25

## 错误处理基础设施层扫尾 — P0 修复

基于三轮代码审查报告（08-23、08-24、08-25）的根因分析，启动错误处理重构遗漏的基础设施层修复。
计划文档：[`plans/2026-08-25-error-boundary-infra-sweep.md`](../../plans/2026-08-25-error-boundary-infra-sweep.md)

### P0-1：RedisService.onModuleDestroy 静默吞错修复

- `src/common/redis/redis.service.ts`：
  - `onModuleDestroy` 中 `.catch(() => undefined)` 改为 `.catch(error => this.logger.warn(...))`。
  - graceful shutdown 时 Redis quit 失败不再被静默吞掉，运维可感知关闭失败。
- `src/common/redis/redis.service.spec.ts`：
  - 新增测试：quit 失败时输出 warn 日志且不抛出。

### P0-2：AssistantToolService 缓存错误保护

- `src/modules/assistant/tools/tool.service.ts`：
  - 新增 `cacheGet<T>(key)` 包装器：Redis 故障时降级为 cache miss（返回 `undefined`），记录 warn 日志。
  - 新增 `cacheSet(key, value, ttl)` 包装器：Redis 故障时记录 warn 日志，不影响结果返回。
  - `executeOne` 中裸 `this.cache.get` / `this.cache.set` 调用改为 `this.cacheGet` / `this.cacheSet`。
  - 降级策略与 `SuggestionCacheService`（catch 后 rethrow）不同——AssistantToolService 的缓存是纯加速（miss 直接走 `executeUncached`），所以降级为无缓存执行更合理。
- `src/modules/assistant/tools/tool.service.spec.ts`：
  - 新增测试：cache get 失败时降级为无缓存执行，调用底层服务并返回结果。
  - 新增测试：cache set 失败时不影响结果返回。
