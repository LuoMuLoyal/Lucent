## 预存 E2E 失败项修复

修复 Fastify 迁移前已存在的 8 个 E2E 失败项（非迁移引入）。

### Security Elevation Guard（4 项）

- **根因**：`SecurityElevationGuard` 在缺少/无效 elevation token 时抛出 `UnauthorizedException`（401），但测试期望 `ForbiddenException`（403）；`verifyElevationToken` 抛出 JWT 错误时导致 500；测试发送了无效的 `kind: 'daily_records'`（DTO 仅允许 `hospital | monthly | print`）
- **修复**：
  - `elevation.guard.ts`：缺失 token 和 `verifyElevationToken` 异常均改为抛 `ForbiddenException`（403），语义更准确（用户已认证但缺少提权）
  - `elevation-and-idor.e2e-spec.ts`：3 处 `kind: 'daily_records'` → `kind: 'hospital'`，`format: 'json'` → `format: 'pdf'`
- **单元测试**：`elevation.guard.spec.ts` 更新为期望 `ForbiddenException`，新增 `verifyElevationToken` 抛异常的覆盖测试

### Mass Assignment Protection（2 项）

- **根因**：`ValidationPipe` 配置 `forbidNonWhitelisted: true` 会拒绝未知字段（返回 400），但测试期望未知字段被忽略（返回 200）
- **修复**：更新测试期望为 400 拒绝（`forbidNonWhitelisted` 是更安全的行为），断言 `ResultCode.VALIDATION_FAILED`

### Daily Records Candidate Generation（1 项）

- **根因**：controller 调用 `generate(user.sub, dto, language)` 传 3 个参数，但测试断言只期望 2 个参数（缺少 `user.id`）
- **修复**：`daily-records.e2e-spec.ts` 断言更新为 3 参数 `[user.id, { text, occurredAt }, 'zh-CN']`

### Medicines Safety Tips（1 项）

- **根因**：安全提示查询结果被缓存（`getOrSetSafetyTips`，TTL 30 分钟），测试删除 DB 记录后缓存仍返回旧数据
- **修复**：测试中先 `cache.del('medicines:safety-tips:all')` 清除缓存，再查询

### Authorization Notifications（1 项）

- **根因**：`authorization.e2e-spec.ts` 通知创建使用 `type: 'system_announcement'`，已被 `USER_CREATABLE_NOTIFICATION_TYPES` 排除
- **修复**：改为 `type: 'medicine_reminder'`

### Dose Log 创建（附带修复）

- **根因**：`elevation-and-idor.e2e-spec.ts` 中 dose log 创建发送 `occurredAt`（不存在于 `CreateDoseLogDto`），且缺少必填字段 `scheduledFor`
- **修复**：`occurredAt: '2026-07-12T08:00:00.000Z'` → `scheduledFor: '2026-07-12'`
