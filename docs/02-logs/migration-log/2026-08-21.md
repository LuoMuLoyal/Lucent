# Migration Log — 2026-08-21

## fix(storage): S3 ensureBucket 竞态条件修复

- `S3StorageRuntime.ensureBucket()` 改用 Promise 锁模式（`bucketEnsurePromise`），
  将检查与设置原子化，避免并发调用同时进入 `CreateBucket` 逻辑。

## fix(assistant): 工具超时异常不再静默吞掉

- `AssistantToolService.executeWithTimeout` 的 `execution.catch` 改为使用
  `Logger.warn` 记录超时后的底层错误信息和堆栈，生产环境可追踪工具间歇性不可用的根因。

## fix(today-suggestion): 日期解析校验与 route eventId 编码

- `EventCheckInTrendRuleService.buildLookbackWindow` 入口处增加
  `/^\d{4}-\d{2}-\d{2}$/` 正则校验和 `Number.isNaN` 守卫，
  非法日期返回空窗口而非抛出 `RangeError: Invalid time value`。
- `primaryAction.route` 的 `eventId` 改用 `encodeURIComponent` 编码，
  防御特殊字符导致前端路由解析异常。

## fix(storage): StorageModule 裸 throw 改为结构化异常

- `StorageModule` 工厂函数中不支持的 `STORAGE_PROVIDER` 从裸 `throw new Error`
  改为 `ServiceUnavailableException`，附带 `ResultCode.EXTERNAL_SERVICE_ERROR` 错误码。
- 同步更新 `storage.module.spec.ts` 中的工厂函数内联副本。

## fix(storage): COS audience 参数行为明确化

- `TencentCosStorageRuntime.createSignedGetUrl` 在 `audience='external'` 时
  增加 `Logger.warn` 警告，明确告知 COS 不支持 audience 区分。
- 类文档注释补充 audience 行为说明，与 `S3StorageRuntime` 的行为差异标注清晰。

## refactor(storage): 提取公共对象键与 publicUrl 工具函数

- 新增 `src/common/storage/object-key.utils.ts`，提取
  `createDatePartitionedObjectKey`、`createFlatObjectKey`、`encodeObjectKey`、
  `buildPublicUrl` 四个公共工具函数。
- `image-upload.service.ts`、`data-export/storage.service.ts`、`files.service.ts`
  三个服务的对象键生成和 publicUrl 构造逻辑统一改用公共工具函数。
- `files.service.ts` 的 `publicUrl` 构造补上 `encodeObjectKey` 编码，
  与 `image-upload.service.ts` 保持一致。
- `data-export/storage.service.ts` 的 `assertConfigured` 风格统一为否定提前返回形式。

## fix(config): S3 和 COS 配置服务对 env 值做 trim()

- `s3-storage.config.ts` 和 `tencent-cos.config.ts` 中所有字符串类型的
  `process.env` 值增加 `.trim()` 调用，防止复制粘贴导致的空格问题。

## fix(assistant): assistant_memories 添加 source_conversation_id 外键

- Prisma `AssistantMemory` 模型新增 `sourceConversation` 关系字段，
  `AssistantConversation` 模型新增反向 `sourceMemories` 关系字段。
- `onDelete: SetNull` 策略确保会话删除后 memory 行保留。
- 新增 migration `20260821100000_add_assistant_memory_fk` 添加外键约束和索引。

## fix(assistant): findWithMessages / findWithMessagesById 过滤 deleted 状态

- `conversation.repository.ts` 的 `findWithMessages` 和 `findWithMessagesById`
  在 `where` 子句中增加 `status: { not: 'deleted' }` 过滤，
  阻止向已删除会话追加消息。
- 同步更新 `conversation.repository.spec.ts` 测试断言。

## fix(infra): prisma.config.ts 数据库 URL 空字符串回退

- `prisma.config.ts` 在 `defineConfig` 之前显式校验 `DATABASE_URL`，
  缺失或空字符串时抛出带有明确上下文的错误信息。
