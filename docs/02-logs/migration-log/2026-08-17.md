### 🔴 严重问题 1：裸 throw 替换为结构化 HTTP 异常

将各模块中 `throw new Error(...)` 和 `throw error`（裸 re-throw）替换为项目已有的 `badRequest`/`unauthorized`/`conflict` helper 或 `InternalServerErrorException`/`ServiceUnavailableException`，使全局异常过滤器能正确映射 HTTP 状态码和 `ResultCode`：

- **`setup-app.ts`**：Scalar 静态文件路由的 `throw err` 改为 `reply.status(500).send(...)` + `Logger.warn` 结构化日志。

- **`analysis.service.ts`**：`throw new Error('TODAY_ANALYSIS_${status}')` 改为 `conflict()`（409）；`throw new Error('TODAY_ANALYSIS_CLAIM_FENCE_MISSING')` 改为 `InternalServerErrorException`（500）。
- **`today-analysis.controller.ts`**：`throw new Error('TODAY_ANALYSIS_${status}')` 改为 `conflict()`（409）。
- **`store.service.ts`**：`throw new Error('TODAY_ANALYSIS_TRANSACTION_RETRY_EXHAUSTED')` 改为 `InternalServerErrorException`（500）。
- **`prisma-event.repository.ts`**：`throw new Error('Created health event could not be read back.')` 改为 `InternalServerErrorException`（500）。
- **`records.service.ts`**：`throw new Error('Expected one meal attachment after length check.')` 改为 `InternalServerErrorException`（500）。
- **`token.service.ts`**：`throw new Error('REFRESH_TOKEN_INVALID')` 改为 `unauthorized(this.i18n.t('auth.refresh_token_invalid'))`（401）；JWT 签名失败 catch 中的 `throw error` 改为 `InternalServerErrorException`（500）。

## feat(today-analysis): F-6 摘要卡接物化结果 + F-7 事件驱动扩展与通知执行器

### 背景

Today Analysis 此前只提供生成接口，首屏从不读取物化结果；全空上下文时仍走 LLM/fallback 产生无意义文案；每次生成创建两条通知造成打扰；普通生活记录（饮水/餐食/睡眠/心情）不触发物化。

### 变更

- **DTO 与 Schema**
  - `TodayAnalysisDataDto` 新增 `aiGenerated: boolean`，用于区分 LLM 输出与模板兜底。
  - `prisma/schema.prisma` 的 `AssistantSummaryHistory` 新增 `ai_generated` 字段（默认 `false`）；新增 migration `20260817000000_add_ai_generated_to_assistant_summary_history`。

- **共享 LLM 层**
  - `BaseLlmSummaryService.generate` / `generateStream` 在模型输出安全可用时标记 `aiGenerated: true`，模型未配置/策略拒绝/生成失败回退到 `copyService.buildFallback` 时标记 `aiGenerated: false`。
  - `AssistantSummaryRepository` 保存与读取 today summary 时透传 `aiGenerated`。

- **Today Analysis 服务**
  - `TodayAnalysisService.generateForVersion` / `generateStreamForVersion` / `readCurrent` 增加空上下文守卫：当用户当日没有任何用药、过敏、饮水、餐食、睡眠、心情、症状记录时，直接返回 `status: 'empty'`，不进入 LLM、不持久化、不创建通知。
  - `readCurrent` 在持久化摘要与物化版本匹配时返回 `analysis.aiGenerated`。
  - `afterPersist` 不再同时创建 `ai_today_summary` + `ai_proactive_suggestion` 两条通知，改为只创建一条 `ai_today_summary`，并通过 `NotificationsService.createOrReplaceScoped` 按 `{ source: 'today-analysis', date }` 幂等替换，同一用户同一天多次生成只保留最新一条。
  - 通知创建后仍通过 `PushDeliveryService` 做 JPush 尽力投递（本地通知优先策略在 Luminous 端实现）。

- **触发边界扩展**
  - `TodayAnalysisTriggerListener` 对 `DAILY_RECORD_CHANGED` 中 `water` / `meal` / `sleep` / `mood` 四类记录增加处理分支。
  - `TodayAnalysisContextService.shouldTriggerForDimension` 实现维度平级门控：近 7 天该维度有效记录 >= 3 条，或今日值较 prior 7 天基线变化 >= 50% 时才允许入队；基线不存在或为零时保守返回 false，避免首次记录即触发。
  - 所有触发源仍受 `TODAY_ANALYSIS_MAX_GENERATIONS_PER_DATE`（每日 3 次）统一预算约束。

- **Controller / Queue**
  - `TodayAnalysisQueueService` 与 `today-analysis.controller.ts` 的返回类型适配 `TodayAnalysisDataDto | TodayAnalysisReadDataDto`，以承载 `empty` 状态响应。

- **测试**
  - `analysis.service.spec.ts` 覆盖 `aiGenerated: true/false`、空上下文返回 `empty`、单条 scoped 通知与 Push 投递。
  - `context.service.spec.ts` 覆盖维度门控的覆盖率通过、变化幅度通过、双不满足时拒绝。
  - `trigger.listener.spec.ts` 覆盖 water/meal/sleep/mood 触发与门控失败时的静默。
  - `today-analysis.controller.spec.ts` 的 `makeAnalysis` helper 补全 `aiGenerated`。

### 验证

- `pnpm typecheck`、`pnpm lint:check`、`pnpm build` 通过。
- `pnpm test today-analysis` 通过（136 tests）。
- `pnpm test assistant reports common/llm` 中与本变更相关的测试通过；`common/llm/base-llm-generator.service.spec.ts` 存在 3 个 circuit breaker 断言与当前实现不符的 pre-existing 失败，与本次变更无关。
- `pnpm export:openapi` 已执行，`docs/openapi.json` 已更新。
