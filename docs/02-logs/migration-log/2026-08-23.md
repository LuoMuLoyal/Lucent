## 验证码与认证限流 Result 边界（Task 3）

将验证码服务与登录限流服务迁移到 `ResultAsync<T, DomainFailure>`：

- `VerificationCodeService.send` / `assertClientRateLimit` 改为 `ResultAsync<void, DomainFailure>`：冷却返回 `AUTH_VERIFICATION_CODE_COOLDOWN`（带 `retryAfter`），客户端窗口超限（Redis atomic 路径与 cache 回退路径）返回 `AUTH_VERIFICATION_CODE_RATE_LIMITED`，均标记 `retryable: true`。
- `VerificationCodeService.verify` 改为 `ResultAsync<boolean, DomainFailure>`：成功返回 `ok(true)` 并一次性删除，过期返回 `AUTH_VERIFICATION_CODE_EXPIRED`，不匹配返回 `AUTH_VERIFICATION_CODE_MISMATCH`。
- `AuthRateLimitService.checkLoginRateLimit` / `recordLoginFailure` / `clearLoginFailures` 改为 `ResultAsync<void, DomainFailure>`：锁定窗口返回 `AUTH_LOGIN_RATE_LIMITED`（携带 `retryAfter` 与 `args.minutes`），窗口过期或缓存格式损坏时删除旧桶并放行。
- 服务不再自行拼装 i18n message，`I18nService` 从两个服务构造函数中移除；`title`/`detail` 由 ProblemCatalog 统一输出。
- 缓存/Redis/邮件等非 Prisma IO 未使用 `fromPrismaResult`：通过 `fromPromise` 提升并以 `throw error` 保留原始异常向边界抛出，不把基础设施故障伪装成业务失败或验证码不匹配。
- **临时 shim**：`credential.service.ts` 与 `auth/services/account.service.ts` 尚未迁移（Task 4），其中对 `verify`/`send`/`assertClientRateLimit`/`checkLoginRateLimit`/`recordLoginFailure`/`clearLoginFailures` 的调用临时以 `unwrapResult(...)` 折叠（带 `TODO(error)` 标注），保持编译与行为不变；Task 4 完成时应移除。
- 测试更新：两个服务 spec 改为 `okAsync`/`errAsync` 语义断言（成功 `ok`、业务失败断言 code/kind/retryAfter/args），新增缓存/Redis 故障必须 rethrow 的行为测试；credential/auth account spec 的 mock 改为 `okAsync`/`errAsync` 返回值。

## 注册、登录与密码生命周期 Result 边界（Task 4）

将注册、登录、密码/邮箱生命周期与账户删除迁移到 `ResultAsync<T, DomainFailure>`：

- `CredentialAuthService` 全部方法改为 `ResultAsync`：`register`、`login`、`changePassword`、`setPassword`、`changeEmail`、`sendVerificationCode`、`verifyEmail`、`forgotPassword`、`resetPassword`。移除对 `VerificationCodeService`/`AuthRateLimitService` 的全部临时 `unwrapResult(...)` shim（原 `TODO(error): Task 4`），改为 `andThen`/`orElse`/`fromPromise` 组合。
- `AuthService` 的凭证委托方法返回 `ResultAsync`（非 `async` 直返，避免 `Promise<ResultAsync>`）；`refresh` 移除 broad catch——只有 token 服务以 401 `UnauthorizedException` 表达的无效/过期/已消费 refresh token 才映射为 `AUTH_REFRESH_TOKEN_INVALID`，数据库/签名/配置故障保持原始异常向边界抛出。
- `AuthAccountService.getActiveUser`/`deleteAccount` 迁移为 `ResultAsync`：删除账户的密码校验失败、验证码失败分别映射 `AUTH_WRONG_PASSWORD` 与验证码 code；缺邮箱/缺凭证映射 `VALIDATION_FAILED`；`I18nService` 从构造函数移除。
- `LocalController`、`AccountController`、`SessionController.refresh` 统一用 `unwrapResult` 折叠；204 仍无 body，成功资源直接返回，不增加 envelope。

**保留/使用的 code（未新增）：** 登录失败（用户不存在、密码错误、密码+验证码互斥、OAuth 用户无密码）统一 `AUTH_WRONG_PASSWORD`；注册邮箱已存在也返回同一 code（anti-enumeration）；`AUTH_REFRESH_TOKEN_INVALID`、`RESOURCE_CONFLICT`、`RESOURCE_NOT_FOUND`、`VALIDATION_FAILED`、`AUTH_LOGIN_RATE_LIMITED`、验证码系列 code 均沿用。

**Anti-enumeration 说明：** 注册流程先校验验证码再做邮箱存在性检查（测试断言调用顺序），已注册邮箱与错误验证码对外不可区分；登录失败路径先调用 `AuthRateLimitService.recordLoginFailure` 再返回统一 code；`forgotPassword` 无论用户是否存在均返回相同成功提示。`argon2.verify` 返回 `false`（密码不匹配）记为错误凭证并计入登录失败次数；`argon2.verify` 抛错（损坏/畸形 hash、原生绑定失败、模块/配置故障）经 `fromPromise` rethrow，保留为依赖/内部错误边界（500），不折叠成 `AUTH_WRONG_PASSWORD` 也不计入失败次数；DB/缓存/邮件/签名等基础设施故障同样 rethrow，不伪装成业务失败。

测试：spec 全部改为 `okAsync`/`errAsync` 与 `collectResult` 折叠断言；新增 anti-enumeration（注册顺序、登录统一 code、forgotPassword 同响应）、基础设施异常不混淆（DB 断连、签名失败、argon2 抛错）、通知 best-effort 保留等用例。
