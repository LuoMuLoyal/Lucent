# 2026-08-23

## SSE 关闭连接失败增加可观测性

修复 `SseConnectionRegistry.closeAll` 在 graceful shutdown 时完全静默吞掉连接写入/结束异常的问题。单个损坏的连接仍不中断整体关闭流程，但现在会记录 `warn` 日志并携带错误消息，便于运维排查连接泄漏或 shutdown 阶段的写入失败。同步补充单元测试断言日志输出。

验证：`src/common/api/sse/sse-connection-registry.service.spec.ts` 通过；Lucent 全量 spec 通过。

## Result 基础边界固化

在 `src/common/result` 中固化 DomainFailure 与 Problem Details 基础契约：

- `DomainFailure` / `CreateDomainFailureInput` 新增受限 `args`，仅允许 `string | number` 值，供 i18n 动态文案（如验证码冷却分钟数）使用。
- 增加 `DOMAIN_FAILURE_KIND_BY_CODE` 映射，`createDomainFailure` 拒绝 kind/code 不一致或 transport-only code，防止业务码被放到错误的语义分类。
- `toProblemDetails` 将 `args` 透传给 `ProblemCatalog.build`，`cause` 仍不进入响应体。
- 从 `src/common/result/index.ts` 移除 `DomainFailureException` 公开导出，保留其为 filter 内部桥接。
- 补充/更新 `domain-failure`、`domain-failure.mapper`、`unwrap-result`、`api-exception.target`、`problem-catalog` 相关测试。

验证：`src/common/result`、`src/common/filters`、`src/common/api/problem-catalog.spec.ts` 范围 vitest 全部通过；`pnpm typecheck`、`pnpm format:check`、`pnpm docs:check` 通过。

## User/Account 核心 Result 边界

完成账户领域 ResultAsync 迁移：

- `UserService.update` / `unlinkIdentity` 返回 `ResultAsync<T, DomainFailure>`，通过 `fromPrismaResult` 将 Prisma `P2002` 映射为 `RESOURCE_CONFLICT`、`P2025` 映射为 `RESOURCE_NOT_FOUND`，未知数据库/连接错误仍作为异常抛出。
- `AuthAccountRepository.softDeleteUser` 同样返回 `ResultAsync`，处理目标用户不存在的 `P2025`。
- `AccountService` 删除 `preserveThrow`，改为真实的 `ResultAsync` 链：`getActiveAccountUser` 显式将 `findByIdWithIdentities` 的 `null` 转换为 `RESOURCE_NOT_FOUND`；`updateAccount` 与 `unlinkIdentity` 组合 UserService 的 Result。
- 账户 controller 继续使用 `unwrapResult` 折叠结果。
- 为保持本次提交可独立编译验证，`credential.service.ts`、`oauth.service.ts` 与 `auth/services/account.service.ts` 中对 `UserService.update` 的调用临时使用 `unwrapResult`，将在后续对应任务中彻底迁移。
