## 用药、设置与通知偏好 Result 迁移（Task 8.2）

将 medicine-reminders、medicine-dose-logs、user-settings、notification-preferences 四个用户可见同步 CRUD 模块迁移到 `ResultAsync<T, DomainFailure>`。顺序：先 repository port/impl，再 application service（含 ownership service），最后 controller 与测试。计划文件列出的范围外文件（mapper.service、delivery-moment、scheduler 等）未改动。

### 失败映射（全部复用现有 code，未新增）

- **资源不存在 → `RESOURCE_NOT_FOUND`（404）**：提醒不存在、current medicine 不存在（含他人所有，保持原 404 反枚举语义）、dose log 不存在、dose log 关联的 reminder/medicine 不存在、race 下 update/delete 的 P2025。
- **owner 不匹配 → `FORBIDDEN`（403）**：提醒按 id 查到但 `userId` 属于他人（原实现统一 404，本次按 Task 8.1 既有约定区分；current medicine 查询按 `(id, userId, isCurrent)` 限定无法区分，仍为 404）。
- **输入/非法状态冲突 → `VALIDATION_FAILED`（400）**：空 slots、重复 slot id、mark 缺 slot 标识（无 reminderId 且（无 currentMedicineId 或无 scheduledTime））、mark/create 的 currentMedicineId 与 reminder 不一致、sleep 分钟数超出 0..1439、投递日期过滤非法。mapper 仍抛 `BadRequestException` 的校验（空 daysOfWeek、日期窗口倒置、非法日期）在 service 层经 `mapperResult` 折叠为 `VALIDATION_FAILED`。
- **P2002 → `RESOURCE_CONFLICT`（409，`fromPrismaResult` 映射）**：dose log 唯一约束竞态、settings upsert 竞态；**P2025 → `RESOURCE_NOT_FOUND`**；未知 DB/连接错误 rethrow（500），不伪装成 4xx。
- **基础设施失败不伪装成功**：`reportLocalCapability` 缓存写入失败仍 rethrow（500，保留原 warn 日志）；user-settings 缓存 del/读失败、投递回执"写入后回读缺失"不变式破坏均 rethrow。本批模块无限流/暂态重试错误，未设置任何 `retryable`/`retryAfter`——所有写入失败均非 retryable，客户端不得自动重试（仅幂等读取可 retryable，本批读取无此场景）。

### 契约变化（相对迁移前）

- 外部用户提醒资源从统一 404 改为 403 `FORBIDDEN`（owner 不匹配）；其余 status 不变。
- `user-settings` 的 `updateSettings`、`notification-preferences` 的 `patch`、`medicine-reminders` 的 `create/update/delete/upsertGroup/listDeliveries`、`medicine-dose-logs` 的 `create/mark/update/delete` 由 Promise/throw 改为 `ResultAsync`；空集合（list）、无配置行返回默认值（get）、幂等回执重复上报返回现有行、204 删除仍为成功值，不因 Err 改 404。
- `I18nService` 从 reminders/ownership/dose-logs service 构造函数移除（title/detail 由 ProblemCatalog 统一输出）；`notification-preferences` 的分钟校验从抛 `BadRequestException` 改为返回 `VALIDATION_FAILED`（detail 保留原字段文案）。
- 四个 controller 全部用 `unwrapResult` 折叠（`list`/`getSettings`/`get` 等无失败路径读取保持 Promise）；204 无 body，成功资源直接返回，不增加 envelope；为产生 DomainFailure 的端点补齐 400/403/404 Problem Details Swagger 声明并重新导出 `docs/openapi.json`（409 声明在 dose-log `create`/`mark` 与 settings `PATCH` 上遗漏、settings `PATCH` 未声明 400，见下文 Task 8.2 P2 修复）。

### 模块要点

- **medicine-reminders**：repository 的 `createReminder`/`updateReminder` 返回 `ResultAsync`（`fromPrismaResult`）；ownership service 的 `ensureOwnedByUser`/`ensureCurrentMedicineOwnedByUser` 返回 `ResultAsync`；`upsertGroup` 事务回调返回 `Result<ItemDto[], DomainFailure>`，外层 `fromPrismaResult` 处理事务内 P2002/P2025 竞态，`andThen` 直接展开同步 Result；`emitReminderChanged` 保持 best-effort（结构化 error 日志），写入不因事件发送失败而失败。
