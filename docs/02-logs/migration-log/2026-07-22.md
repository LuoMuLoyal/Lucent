# 2026-07-22 迁移日志

## 修复开发服务器启动崩溃（stack-trace + urlencoded content-type parser 冲突）

### 背景

`pnpm start:dev` 启动后立即崩溃，报错 `TypeError: stackTrace.parse is not a function`。
该错误掩盖了真正的启动失败原因，导致无法定位问题。

### 根因分析

两个独立问题叠加：

1. **stack-trace@0.0.1 缺少 `parse` 函数**：`winston@3.19.0` 依赖 `stack-trace: "0.0.x"`，
   pnpm lockfile 解析到 `0.0.1`，该版本只导出 `get()`，没有 `parse()`。
   当应用抛出未捕获异常时，winston 的 `ExceptionHandler.getTrace()` 调用 `stackTrace.parse(err)`
   导致二次崩溃，掩盖了原始错误。
2. **Fastify urlencoded content-type parser 重复注册**：`@adminjs/fastify` 的 `buildAuthenticatedRouter`
   内部注册了 `@fastify/formbody`（注册 `application/x-www-form-urlencoded` 解析器），
   随后 NestJS 的 `app.listen()` → `init()` → `registerParserMiddleware()` 试图再次注册同一解析器，
   抛出 `FastifyError: Content type parser 'application/x-www-form-urlencoded' already present`。
   Node.js v24 默认将未处理的 Promise rejection 转为 `uncaughtException`，触发了上述 winston 崩溃。

### 修复

#### 1. stack-trace 版本修复

- `pnpm-workspace.yaml` 新增 `overrides.stack-trace: 0.0.10`
- pnpm v11 不再从 `package.json` 的 `pnpm.overrides` 读取配置，须使用 `pnpm-workspace.yaml`

#### 2. Body parser 冲突修复

- `src/main.ts`：`NestFactory.create()` 选项新增 `bodyParser: false`，禁用 NestJS 默认 body parser
- `src/setup-app.ts`：手动注册 `application/json` content-type parser（urlencoded 由 AdminJS 的
  `@fastify/formbody` 处理）

### 涉及文件

| 文件                  | 改动                                              |
| --------------------- | ------------------------------------------------- |
| `pnpm-workspace.yaml` | 新增 `overrides.stack-trace: 0.0.10`              |
| `src/main.ts`         | `NestFactory.create` 选项新增 `bodyParser: false` |
| `src/setup-app.ts`    | 手动注册 JSON content-type parser                 |
| `pnpm-lock.yaml`      | stack-trace 从 0.0.1 更新到 0.0.10                |

### 验证结果

- `pnpm start:dev` — 启动成功，无崩溃
- `GET /api/v1/health` — 响应正常，database + cache 组件均 up
- `pnpm lint:check` — 0 errors
