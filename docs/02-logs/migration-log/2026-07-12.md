### 测试输出噪音治理

- **问题**：E2E 测试全量运行时 pino-pretty 直接写 stdout，每条 HTTP 请求产生一行日志，226 个文件共输出数千行应用日志，淹没了 Vitest 的测试结果输出
- **根因**：pino 的 transport（pino-pretty / pino/file）通过 worker 线程直接写 stdout fd，绕过 `console.*`，因此 Vitest 内置的「仅失败测试显示 console 输出」机制无法拦截
- **修复**：
  - `src/common/logger/logger.config.ts`：测试模式（`NODE_ENV === 'test'`）下不配置 transport，level 默认 `'silent'`（可通过 `LOG_LEVEL` 环境变量覆盖）
  - `.env.test` / `.env.test.example`：`LOG_LEVEL` 从 `debug` 改为 `silent`
  - `src/config/environment.validation.ts`：`LOG_LEVEL` 的 Joi 校验添加 `'silent'` 到合法值列表
  - `vitest.e2e.config.ts`：修复 Vitest 4 弃用的 `poolOptions.forks.singleFork` → 顶层 `singleFork: true`
- **调试方式**：需要查看应用日志时，运行 `LOG_LEVEL=debug pnpm test:e2e` 即可恢复日志输出

### Pino → Winston 迁移

- **动机**：Pino 的 worker 线程 transport 绕过 `console.*` 导致测试噪音问题；PinoLogger 与 NestJS `new Logger()` 两套 logger 并存造成认知负担；Pino 的 `(obj, msg)` API 顺序敏感不够直观
- **依赖替换**：移除 `nestjs-pino`、`pino`、`pino-http`、`pino-pretty`、`pino-roll`（-29 包）；新增 `nest-winston`、`winston`、`winston-daily-rotate-file`（+27 包）
- **配置重写**：`src/common/logger/logger.config.ts` 完全重写为 Winston 配置：
  - 开发环境：`Console` transport，`debug` 级别
  - 生产环境：`Console`（JSON）+ `DailyRotateFile`（`lucent-YYYY-MM-DD.log`，500MB 上限，14 天保留，自动 gzip）
  - 测试环境：`Console` transport，`error` 级别（仅输出错误，接近静默）
  - 移除 `genReqId`、`customLogLevel`、`customSuccessMessage`、`customErrorMessage`、`serializers`、`autoLogging` 等 pino-http 特有配置（request ID 关联已由 `requestIdMiddleware` + `AsyncLocalStorage` 独立处理）
- **模块更新**：`logger.module.ts`：`PinoLoggerModule` → `WinstonModule.forRootAsync()`
- **Bootstrap 更新**：`main.ts`：`app.useLogger(app.get(Logger))` → `app.useLogger(app.get(WINSTON_MODULE_NEST_PROVIDER))`
- **Interceptor 清理**：`setup-app.ts`：移除 `LoggerErrorInterceptor`（nestjs-pino 特有，Winston 无对应组件，异常日志已由 `ApiExceptionFilter` 覆盖）

### 关闭 pino-http 每请求 autoLogging

- **问题**：pino-http 的 `autoLogging` 对每个 HTTP 请求打印一行访问日志（如 `GET /api/v1/medicines completed 200 in 42ms`），与已有的可观测性组件完全重复：
  - Nginx `access_log` — 已记录每个请求的 IP、method、URL、status、bytes、UA、referer
  - `ApiExceptionFilter` — 已记录所有 4xx/5xx 错误（requestId + error stack + message，上下文更丰富）
  - `SlowRequestInterceptor` — 已记录慢请求（可配置阈值 + handler name）
  - Prometheus histogram + counter — 已聚合响应时间和请求计数
- **变更**：`src/common/logger/logger.config.ts` 设 `autoLogging: false`，删除 `customLogLevel`、`customSuccessMessage`、`customErrorMessage`、`serializers`、`formatDurationSuffix` 等仅供 autoLogging 使用的代码；保留 `genReqId`（request ID 关联）和 transport / level 配置（业务日志仍由 PinoLogger 输出）
- **测试**：`logger.config.spec.ts` 移除 4 个 autoLogging 消息格式测试，新增 3 个 `genReqId` 测试 + 1 个 `autoLogging === false` 断言 + 1 个测试模式 silent 断言（共 8 个测试全部通过）
