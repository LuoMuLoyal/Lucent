## 队列与缓存增强

审计 BullMQ 队列和 NestJS CacheModule 使用情况，确认 BullMQ 无需升级为 RabbitMQ（项目是单体 NestJS，所有队列场景都是 fire-and-forget + 重试，BullMQ 完全胜任），但有多处任务应使用队列却同步执行、有多处读密集数据应加缓存却每次查库。

### 缓存增强（8 项）

- **A1: SuggestionCacheService 接入** — `SuggestionCacheService` 声明了 3 层缓存（signals 5min / suggestions 3min / baseline 1h）但从未接入 `SuggestionService.generate()`。现在已接入：`generate()` 先查 suggestion cache → 未命中查 signal cache → 未命中跑 collector → 写 signal cache → 跑 rule engine → 写 suggestion cache。`FeedbackService.recordFeedback()` 后调用 `invalidateSuggestions()`。`DailyRecordsService` 和 `MedicineDoseLogsService` 的 create/update/delete 操作后调用 `invalidateSignals()`。
- **A2: Reports Dashboard 缓存** — `ReportsService.getDashboard()` 按 `userId:range:startDate:endDate:locale` 缓存，TTL 5 分钟。
- **A3: Today Analysis Context 缓存** — `TodayAnalysisContextService.build()` 按 `userId:date` 缓存，TTL 3 分钟。
- **A4: Legal Documents 缓存** — `LegalDocumentsService.findAll()` 和 `findOne()` 按 `docType:lang` / `list:lang` 缓存，TTL 1 小时。
- **A5: User Settings 缓存** — `UserSettingsService.getSettings()` 按 `userId` 缓存（TTL 10 分钟），`updateSettings()` 后主动失效。
- **A6: Medicine Safety Tips 缓存** — `MedicinesService.getRandomSafetyTips()` 通过 `MedicinesCacheService.getOrSetSafetyTips()` 缓存完整 active tips 列表，TTL 10 分钟。
- **A7: Support Resources AppInfo 初始化读一次** — `SupportResourcesService.getAppInfo()` 从每次 `readFileSync` 读 `package.json` 改为构造函数中读一次并缓存到实例变量。
- **A8: Suggestion History 缓存** — `LifecycleService.getHistory()` 按 `userId:startDate:endDate:lifecycleState:type:limit` 缓存，TTL 1 分钟。

### 队列增强（5 项）

所有队列复用现有 `BullmqQueueFactory`，Redis 不可用时降级为内联同步处理。保留所有现有同步端点兼容旧客户端，新增 `/async` 后缀端点。

- **B3: Today Analysis 非流式生成入队** — 新增 `TodayAnalysisQueueService`，队列名 `today-analysis`，并发 2。`POST /today-analysis/generate/async` 入队，`GET /today-analysis/generate/status/:jobId` 轮询。
- **B4: Report AI Summary 非流式生成入队** — 新增 `ReportSummaryQueueService`，队列名 `report-summary`，并发 2。`POST /reports/summary/generate/async` 入队，`GET /reports/summary/generate/status/:jobId` 轮询。
- **B5: Suggestion AI 解释入队** — 新增 `ExplanationQueueService`，队列名 `suggestion-explanation`，并发 2。`POST /today/suggestions/:id/explain/async` 入队，`GET /today/suggestions/explain/status/:jobId` 轮询。
- **B1: 药品图片识别入队** — 新增 `MedicineRecognitionQueueService`，队列名 `medicine-recognition`，并发 1。`POST /medicines/recognize/async` 入队，`GET /medicines/recognize/status/:jobId` 轮询。
