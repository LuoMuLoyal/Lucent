# 2026-07-23 代码审查修复

## i18n 缺失 key 检测逻辑修复

### 背景

代码审查报告指出 `SuggestionService.localizeEvidenceValue()` 使用 `startsWith('today-suggestion.evidence_value.')` 前缀匹配来检测 i18n key 是否缺失，这种方式脆弱——如果某个翻译文本恰好以该前缀开头，会错误回退到原始值。

### 修复

将 `startsWith` 前缀匹配改为与完整 key 路径的精确比较（`===`）。nestjs-i18n 在找不到翻译 key 时返回 key 路径本身，因此 `translated === key` 是可靠的缺失检测方式。

**文件:** `src/modules/today-suggestion/services/suggestion.service.ts`

## AI Copy 缓存跨用户共享设计说明

### 背景

代码审查报告指出 `SuggestionCopyService.buildCacheKey()` 不包含 userId，不同用户共享同一缓存。虽然当前安全（copy 文案不包含用户敏感信息），但这是隐式假设。

### 修复

在 `buildCacheKey()` 方法上添加文档注释，明确说明缓存是**有意跨用户共享**的，并禁止在 params 中传入用户敏感信息。

**文件:** `src/modules/today-suggestion/services/copy/copy.service.ts`

## `localizeEvidenceValue` 类型修复

### 背景

`pnpm typecheck` 报错 TS2322：`this.i18n.t()` 返回类型为 `unknown`，赋值给局部变量 `translated` 后在三元表达式 `translated === key ? value : translated` 中返回时，无法赋给函数的 `string` 返回类型。

### 修复

对 `i18n.t()` 的返回值添加 `as string` 类型断言，使 `translated` 推断为 `string`，三元表达式类型正确。

**文件:** `src/modules/today-suggestion/services/suggestion.service.ts`
