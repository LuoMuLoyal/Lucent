## 审查报告修复（Lucent-review-2026-07-30）

根据 `plans/Lucent-review-2026-07-30.md` 审查报告，修复 4 个严重问题和 1 个警告。

### 修复 1：prisma.config.ts import 路径断裂

- **文件**: `prisma.config.ts:6`
- **变更**: `import { getDotenvLoadOrder } from './src/config/env-file-paths'` → `'./src/config/env/env-file-paths'`
- **原因**: 07-29 目录重构将 `src/config/env-file-paths.ts` 移动到 `src/config/env/env-file-paths.ts`，但此文件未更新，导致 `pnpm install` 的 postinstall 阶段 `prisma generate` 加载失败

### 修复 2：scripts/shared/env.ts import 路径断裂

- **文件**: `scripts/shared/env.ts:4`
- **变更**: `require('../../src/config/env-file-paths')` → `require('../../src/config/env/env-file-paths')`
- **原因**: 同上，目录重构后路径未同步更新，导致所有依赖此脚本的工具（数据库迁移、seed 等）运行时 MODULE_NOT_FOUND

### 修复 3：Dockerfile COPY 路径断裂

- **文件**: `Dockerfile:48-49`
- **变更**: `COPY --from=builder /app/src/config/env-file-paths.ts ./src/config/env-file-paths.ts` → `COPY --from=builder /app/src/config/env/env-file-paths.ts ./src/config/env/env-file-paths.ts`（含注释同步更新）
- **原因**: 文件已移动但 Dockerfile COPY 指令未更新，Docker 构建时找不到源文件，生产部署受影响

### 修复 4：CI trivy-action 版本标签缺少 v 前缀

- **文件**: `.github/workflows/lucent-ci.yml:247`
- **变更**: `uses: aquasecurity/trivy-action@0.36.0` → `uses: aquasecurity/trivy-action@v0.36.0`
- **原因**: GitHub Actions 无法解析无 `v` 前缀的 action 引用，docker job 在 "Set up job" 阶段报错，CI 永久失败

### 修复 5：proposal-draft-extractor.ts 正则匹配忽略否定语义

- **文件**: `src/modules/assistant/tools/proposal/proposal-draft-extractor.ts`
- **变更**: 新增 `hasAffirmativeMatch` 辅助函数，使用 `matchAll` 遍历所有匹配项并检查匹配位置前方是否存在否定词（不要/别/不用/无需/不/don't/do not/never）。`extractSettingsDraft` 和 `applyContextToggle` 中的 `.test()` 调用全部替换为 `hasAffirmativeMatch()`
- **原因**: 用户说"不要关闭 ai"或"别 disable memory"时，正则 `关闭.*ai` / `disable.*ai` 仍会命中，错误地将 `assistantEnabled` / `assistantMemoryEnabled` 设为 `false`。修复后否定意图的匹配被跳过，不执行操作
