## 用药安全风险检查 — 后端 API 重构（Prisma + Service + Controller + LLM Generator）

来源：`Luminous/plans/2026-07-27-medicine-safety-risk-check-redesign.md`

### 背景

原先用药风险检查逻辑全部在 Flutter 客户端执行（`risk_checker.dart` 等 6 个文件），每次打开用药 Tab 都要拉取所有药品详情再本地交叉分析，延迟高且无法利用 LLM。本次将全部检查逻辑迁移到后端，通过 API 持久化检查记录，支持 static + LLM 两种检查类型。

### Prisma Schema

- 新增 `MedicineRiskCheckRecord` model（`prisma/schema.prisma`）：
  - `userId`（FK → User）、`checkType`（`static` | `llm`）、`result`（Json：findings + coverageIssues + redFlags + overallRecommendation）、`riskScore`（0–100）、`riskLevel`（`safe` | `caution` | `risk` | `danger`）、`stale`（boolean）
  - `@@unique([userId, checkType])` 确保每种类型只有一条最新记录
  - `@@index([userId])` 查询优化

### DTO

- `RiskCheckResponseDto`（`dto/risk-check-response.dto.ts`）：`overallRiskLevel`、`overallRiskScore`、`currentMedicineCount`、`checkedMedicineCount`、`findings`、`coverageIssues`、`redFlags`、`overallRecommendation?`
- `RiskCheckRecordDto`（`dto/risk-check-response.dto.ts`）：`checkType`、`result`、`riskScore`、`riskLevel`、`stale`、`createdAt`、`updatedAt`
- `RiskCheckRecordsDto`：`static` + `llm` 两条记录
- `RunRiskCheckDto`（`dto/risk-check-request.dto.ts`）：`type: 'static' | 'llm'`

### Service

- `MedicineRiskCheckService`（`services/medicine-risk-check.service.ts`）：
  - `getRecords(userId)` — 返回 static + llm 两条最新记录
  - `runStaticCheck(userId)` — 静态检查：过敏匹配、成分重复、药物相互作用（DrugBank）、食物相互作用、覆盖缺口、红旗评估
  - `runLlmCheck(userId)` — LLM 检查：构建上下文 JSON → 调用 `MedicineRiskLlmGeneratorService` → 映射结构化输出
  - `markStale(userId)` — 标记记录为 stale（由 Listener 调用）
  - `buildLlmContext(userId)` — 汇总用药 + 过敏 + 疾病 + 提醒为 LLM 上下文 JSON

- `MedicineRiskLlmGeneratorService`（`services/medicine-risk-llm-generator.service.ts`）：
  - 继承 `BaseLlmGeneratorService`，复用 circuit breaker / retry / metrics 基础设施
  - 使用 Zod schema `risk-check.schema.ts` 验证 LLM 结构化输出
  - Prompt 模板 `prompts/risk-check.prompt.ts` 包含系统指令 + 用户上下文注入

### Controller

- `MedicinesController` 新增两个端点（`medicines.controller.ts`）：
  - `GET /api/v1/medicines/risk-check` — 获取最新风险检查记录（static + llm）
  - `POST /api/v1/medicines/risk-check` — 触发风险检查（body: `{ type: 'static' | 'llm' }`）

### Listener

- `MedicineRiskCheckListener`（`services/medicine-risk-check.listener.ts`）：
  - 监听 `HEALTH_CONTEXT_CHANGED` 和 `REMINDER_CHANGED` 事件
  - 自动调用 `markStale` + debounce 5 秒后触发静态检查
  - 避免"添加药品 + 创建提醒"连发两次事件的场景下重复检查

### OpenAPI

- `pnpm export:openapi` 已重新生成 `docs/openapi.json`（104 paths / 224 schemas），新增 risk check 相关 schema。

## 队列服务构造函数竞态修复

### 背景

运行时报错 `Suggestion copy generation job failed: this.copyService.generateViaLlm is not a function`。根因是所有继承 `BaseAsyncQueueService` 的队列服务在 `super()` 调用中使用了 `this.xxxService`，但 TypeScript 参数属性（`private readonly xxxService`）的赋值在 `super()` 返回之后才执行。如果 Redis 中有遗留任务，Worker 在 `super()` 内部就会拾取并执行，此时 `this.xxxService` 尚未赋值。

### 改动

6 个队列服务统一修复，将 `super()` 回调中的 `this.xxxService` 改为直接引用构造函数参数 `xxxService`（局部变量在 `super()` 调用期间就可用），同时移除不再需要的 `private readonly` 参数属性修饰符：

- `SuggestionCopyQueueService`（`today-suggestion/services/copy/copy-queue.service.ts`）
- `ExplanationQueueService`（`today-suggestion/services/explanation/queue.service.ts`）
- `TodayAnalysisQueueService`（`today-analysis/services/analysis-queue.service.ts`）
- `ClinicSummaryPdfQueueService`（`reports/services/clinic-summary/pdf-queue.service.ts`）
- `ReportSummaryQueueService`（`reports/services/ai-summary/summary-queue.service.ts`）
- `MedicineRecognitionQueueService`（`medicines/services/medicine-recognition-queue.service.ts`）

### 验证

- `pnpm lint:check` 通过
- `pnpm build` 通过
- 33 个队列相关测试全部通过
