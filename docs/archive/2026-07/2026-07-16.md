### AdminJS Session 迁移验证（待手动执行）

1. `pnpm start:dev` 启动服务
2. 访问 `/admin`，使用管理员凭据登录

若发现 session 行为异常，需在 `src/admin/services/auth-router.service.ts` 的 `buildAuthenticatedRouter` 调用中补充必要的 session 配置。

## 数据库索引优化（schema.prisma + migration）

### 概述

对 `prisma/schema.prisma` 进行系统性索引优化，涵盖四个类别：冗余索引删除、缺失索引补充、低基数索引清理、ILIKE 搜索 GIN trigram 索引。新增 migration `20260716120000_optimize_indexes`。每条索引变更均经过代码级查询模式验证，确保索引与实际 Prisma `where`/`orderBy` 对齐。

### P0：删除冗余索引（10 个）

以下索引被唯一约束或复合索引的最左前缀覆盖，删除以减少写入开销：

| 模型                           | 删除的索引                                                   | 被覆盖的约束                                      |
| ------------------------------ | ------------------------------------------------------------ | ------------------------------------------------- |
| `CnMedicineProductLeafletLink` | `@@index([productId])`                                       | `@@unique([productId, leafletId])`                |
| `MedicineLeafletChunk`         | `@@index([leafletId])`                                       | `@@unique([leafletId, sourceField, chunkIndex])`  |
| `DrugbankPassageChunk`         | `@@index([drugbankId])`                                      | `@@unique([drugbankId, sourceField, chunkIndex])` |
| `UserSetting`                  | `@@index([userId])`                                          | `@@unique([userId, key])`                         |
| `DataExportRequest`            | `@@index([userId, createdAt])`                               | `@@index([userId, kind, createdAt])` 超集         |
| `AssistantConversation`        | `@@index([userId, updatedAt])`                               | `@@index([userId, status, updatedAt])` 超集       |
| `UserMedicineDoseLog`          | `@@index([userId, currentMedicineId])`                       | 4 列复合索引前缀                                  |
| `UserDailyRecord`              | `@@index([userId, occurredAt])`                              | 3 列复合索引前缀                                  |
| `CnMedicineProduct`            | `@@index([bestMatchType])`, `@@index([matchQualityOverall])` | 导入时字段，运行时不查询                          |
| `UserSuggestionBaseline`       | `@@index([userId, dimension, establishedAt])`                | `@@unique([userId, dimension])` 前缀              |

### P1：补充缺失的跨用户索引（2 个）

后台定时任务需要跨用户扫描，但现有索引全部以 `userId` 开头，无法服务这些查询：

| 模型                   | 新增索引                  | 查询场景             |
| ---------------------- | ------------------------- | -------------------- |
| `UserSession`          | `@@index([expiresAt])`    | 定时清理过期 session |
| `UserReminderDelivery` | `@@index([scheduledFor])` | 提醒投递调度器扫描   |

### P2：低基数索引清理

分为三种子策略，每条均经过代码级查询验证：

**保留 partial index（3 个）** — 查询模式与索引列完全匹配：

| 模型                   | 原索引                                 | 新 partial index                                                                                  | 匹配的查询                             |
| ---------------------- | -------------------------------------- | ------------------------------------------------------------------------------------------------- | -------------------------------------- |
| `UserCurrentMedicine`  | `@@index([userId, isCurrent])`         | `("user_id") WHERE is_current = true`                                                             | `where: { userId, isCurrent: true }`   |
| `UserMedicineReminder` | `@@index([userId, isActive])`          | `("user_id", "scheduled_hour", "scheduled_minute") WHERE is_active = true AND deleted_at IS NULL` | `where + orderBy scheduledHour/Minute` |
| `UserNotification`     | `@@index([userId, isRead, createdAt])` | `("user_id", "created_at" DESC) WHERE is_read = false`                                            | `where: { userId, isRead: false }`     |

**仅删除不重建（3 个）** — 表极小或无运行时查询，seq scan 更优：

| 模型                | 删除的索引                       | 理由                                                |
| ------------------- | -------------------------------- | --------------------------------------------------- |
| `User`              | `@@index([status])`              | 无运行时查询按 status 过滤；PK 索引服务所有 id 查找 |
| `MedicineSafetyTip` | `@@index([isActive, sortOrder])` | 表极小（数十行），seq scan 足够                     |
| `LegalDocument`     | `@@index([isActive])`            | 表极小（< 10 行），findOne 走 PK                    |

**Partial index（1 个）**：

| 模型               | 原索引              | 新 partial index                                   | 匹配的查询                                                               |
| ------------------ | ------------------- | -------------------------------------------------- | ------------------------------------------------------------------------ |
| `MealDishTemplate` | `@@index([status])` | `("normalized_dish_name") WHERE status = 'active'` | `where: { status: 'active', OR: [{ normalizedDishName: { in: ... } }] }` |

**B-tree on JSONB 删除（1 个）**：

| 模型                | 删除的索引                 | 理由                                             |
| ------------------- | -------------------------- | ------------------------------------------------ |
| `CnMedicineLeaflet` | `@@index([approvalCodes])` | B-tree 索引对 JSONB 列无效；无运行时查询过滤此列 |

### P3：GIN trigram 索引

启用 `pg_trgm` 扩展，为所有 `ILIKE '%query%'` / `contains(mode: insensitive)` 搜索列添加 GIN trigram 索引。当前 B-tree 索引对 ILIKE 完全无效（每次全表扫描），GIN trigram 索引可将搜索性能提升 100x+。每条索引均经过代码级查询验证：

| 表                       | 索引列                                                                                  | 查询来源                                                                                 |
| ------------------------ | --------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------- |
| `cn_medicine_products`   | `name`, `brand_name`, `approval_number`, `barcode`, `national_drug_code`, `search_text` | `CnMedicinesService.buildWhere()` — 6 列 OR contains                                     |
| `drugbank_drugs`         | `name`, `cas_number`, `unii`, `search_text`                                             | `DrugbankMedicinesService.buildWhere()` + `entity-resolve.service.ts` — 4 列 OR contains |
| `food_composition_items` | `normalized_name`, `search_text`                                                        | `grounding.service.ts` fuzzyCandidates — startsWith 前缀匹配                             |

**移除的无用 GIN 索引**（原方案中错误添加，审查后移除）：

| 表                            | 移除的索引列                    | 理由                                     |
| ----------------------------- | ------------------------------- | ---------------------------------------- |
| `food_composition_items`      | `name`                          | 不参与任何 WHERE 查询                    |
| `food_composition_categories` | `name`, `search_text`           | 无任何 Prisma 查询引用此模型             |
| `meal_dish_templates`         | `display_name`, `search_text`   | 查询使用 `in`（精确匹配），非 `contains` |
| `cn_medicine_leaflets`        | `generic_name`                  | 无 ILIKE 查询                            |
| `cn_medicine_leaflets`        | `approval_codes` (GIN on JSONB) | 无 JSONB 过滤查询                        |
| `medical_qa_chunks`           | `question`, `answer`            | 使用 pgvector 语义搜索，非 ILIKE         |
