# 2026-10-12

## chore(deploy): compose 与 .env 按机器拆分(一机一文件)

原形态是「一份 `compose.yaml` 在主站与图库机各部署一份,靠显式服务名决定起哪些」
(ADR-0023 决定 2),`.env` 则是三台机器共用一份 569 行模板。本次按**机器边界**拆开。

### 为什么拆

1. **图库机必须凑齐主站的口令才能启动。** compose 对**整个文件**插值,所以只跑
   `neo4j` + `semantica` 的图库机也必须有 `LUCENT_IMAGE` / `LUCENT_DB_IMAGE` /
   `POSTGRES_PASSWORD` / `REDIS_PASSWORD`。用只含图库变量的 `.env` 实测
   `docker compose config`,exit 1:

   ```
   error while interpolating services.app.image: required variable LUCENT_IMAGE is missing a value
   error while interpolating services.postgres.environment.POSTGRES_PASSWORD: required
   error while interpolating services.postgres.image: required variable LUCENT_DB_IMAGE is missing
   error while interpolating services.redis.command: required variable REDIS_PASSWORD is missing
   ```

   而 `docs/howto/deploy.md` §二 给图库机列的 `.env` 只有 `NEO4J_PASSWORD` /
   `API_TOKEN` / `SEMANTICA_IMAGE` —— **照文档照做会在插值阶段直接失败**。
   要跑起来就得把主站的生产口令复制到一台不需要它们的机器上。

2. **`profiles: ['semantica']` 是拆分缺失的症状。** 它存在的唯一原因是两个服务集
   挤在一个文件里,需要一种办法让主站"别起它"。
3. **同步单位被人为放大。** 2026-10-05 记录:服务器上的 `compose.yaml` 是旧副本,
   `TRUST_PROXY: 'true'` 仍在,限流可被伪造 XFF 绕过。共用文件时"同步 compose"
   意味着同步两台机器的并集。
4. **`.env` 模板被迫写条件说明。** 569 行被三台共用,每台只用一部分,模板里满是
   "阿里云那台只需把这些抄过去"这类注记;2026-10-05 还记着手工合并要留
   `.env.bak-merge-` 备份。

### 验证

- **拆分前后对照**(同一份只含图库变量的 `.env`):
  - 旧 `compose.yaml`:exit 1,四条 required-variable 报错(见上);
  - 新 `compose.graph.yaml`:exit 0,`--services` 输出 `neo4j` `semantica`。
- 三份 compose 各自的模板**活行**直接当 `.env` 喂给对应文件,均 exit 0:
  `.env.graph.example` → `compose.graph.yaml`(neo4j/semantica)、
  `.env.monitoring.example` → `compose.monitoring.yaml`(4 个监控服务)、
  `.env.production.example` → `compose.yaml`(5 个主站服务)。
- 主站 compose 完整 `config` 解析通过,`DATABASE_URL` 按
  `POSTGRES_PASSWORD` 正确拼成 `postgresql://lucent:…@postgres:5432/lucent`。
- 两份新文件均无 `profiles:` 残留(注释里的历史说明除外)。
- `pnpm docs:verify` / `pnpm docs:links` 通过。

### 部署注意(换文件)

图库机上要从 `cp compose.yaml` 改为 `cp compose.graph.yaml`,`.env` 模板名同步换;
**服务器上现存的是旧副本**,需同步后再 `up -d`(否则仍是共用形态,且缺主站变量会
在插值阶段失败)。主站与监控机的文件名不变,只需同步内容。
