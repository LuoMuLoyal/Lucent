## 修复 CI 与 Dockerfile 中 Prisma client .js 文件缺失导致 export:openapi 失败

### 问题

Prisma 7 的 `prisma-client` generator（`moduleFormat = "cjs"`）只生成 `.ts` 文件。`package.json` 的 `prisma:generate` 脚本包含两步：`pnpm exec prisma generate && node scripts/dev/fix-generated-prisma-internal.ts`——后者用 SWC 将 `generated/prisma/` 下的 `.ts` 编译为 `.js`。

CI workflow 和 Dockerfile 均直接调用 `pnpm exec prisma generate`，跳过了 `fix-generated-prisma-internal.ts`，导致 `dist/` 中编译后的 `require("../../../../generated/prisma/client.js")` 找不到 `.js` 文件，`export:openapi` 在 CI 中报 `Cannot find module '../../../../generated/prisma/client'`。

### 修复

- `.github/workflows/lucent-ci.yml`：3 个 job（ci-lint-typecheck / ci-unit / ci-e2e）的 `Generate Prisma client` 步骤由 `pnpm exec prisma generate` 改为 `pnpm prisma:generate`，确保 `.ts` → `.js` 编译步骤执行。
- `Dockerfile`：builder 阶段的 `RUN pnpm exec prisma generate` 改为 `RUN pnpm prisma:generate`；新增 `COPY scripts ./scripts` 以使 `fix-generated-prisma-internal.ts` 在 Docker 构建上下文中可用；修正注释（原注释错误声称"prisma 7 在 Docker 中直接生成 .js"）。

### 验证

- 本地 `pnpm export:openapi` 通过（Paths: 127, Schemas: 316）。
- 模拟 CI 流程（`pnpm prisma:generate && pnpm build && pnpm openapi:export`）通过。
- 无 API 契约变化、无 Prisma schema 变更。
