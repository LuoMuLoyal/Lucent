### Scalar 自托管路由健壮性

- `src/setup-app.ts`
  - `/scalar/standalone.js` 路由增加 `try/catch`：文件不存在（`ENOENT`）时返回 404 而非 500（原 `readFile` 未捕获异常被 Fastify 转为 500，生产排障无法直观判断文件缺失）。
  - 文件路径由 `process.cwd()` 改为基于 `__dirname` 定位项目根：`join(__dirname, '..', 'node_modules', ...)`。`__dirname` 在 dev（`src/`）与 `nest build` 产物（`dist/`，rootDir=src，产物为 `dist/setup-app.js`）下均为项目根，规避 PM2 / systemd / Docker 下工作目录非项目根导致的路由 404/500。审查建议的 `'..','..'` 按本项目实际产物结构修正为单级 `'..'`。
  - 响应增加 `Cache-Control: public, max-age=31536000, immutable`：bundle 仅在 `@scalar/api-reference` 版本变更时变化，可安全长期缓存，减少重复磁盘 I/O。

### JSON 解析器容忍空 body

- `src/setup-app.ts`
  - 自定义 `application/json` content-type parser 增加空 body 分支：body 为空或全空白时 `done(null, undefined)`，不再抛 `Unexpected end of JSON input`。
  - 根因：生成的 OpenAPI/Dart 客户端对无请求体 POST 仍带 `Content-Type: application/json`，Fastify 以空字符串调用解析器导致 400。此修复使前端可移除 `clearLatestConversation` 的手工 `dio.post` workaround，改用生成客户端方法（Luminous 侧同步修改）。
