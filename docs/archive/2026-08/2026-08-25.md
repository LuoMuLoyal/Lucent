### 设计决策

- **不引入新依赖**：`winston-transport` 是 winston 的内部依赖，通过 `require('winston-transport')` 获取基类（运行时可用，类型层面为 `any`），无需在 `package.json` 中添加。
- **不使用 Winston 自带 `Http` transport**：它发送的是 JSON-RPC 格式（整个 `options` 对象序列化为一个 JSON body），而 VictoriaLogs 期望的是 newline-delimited JSON（每行一个独立 JSON 对象）。
- **批量 + fire-and-forget**：避免每条日志行一个 HTTP 请求的开销，错误不阻塞应用。

### 关于 `/v1/traces` 端点

`http://127.0.0.1:4318/v1/traces` 是 **OpenTelemetry Protocol (OTLP) HTTP 标准规范端点**，不是 Lucent 的业务 API。OTLP/HTTP 规范规定 trace 导出路径为 `/v1/traces`（metrics 为 `/v1/metrics`，logs 为 `/v1/logs`）。所有兼容 OTLP 的后端（Jaeger、Tempo、VictoriaMetrics 等）都在此路径接收 trace 数据。与 Lucent 的 `/api/v1/...` 业务 API 无关。
