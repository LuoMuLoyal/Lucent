## 修复 fastify 双副本导致的 5 处 typecheck 错误

`pnpm typecheck` 长期有 5 处错误（`src/admin/setup.ts`、`src/setup-app.ts`），报
`FastifyInstance` "incompatible between these types"。根因是**两份 fastify 共存**：

- `@nestjs/platform-fastify@12.1.0` 要求 fastify **恰好 5.12.5**（精确版本）
- 应用自身声明 `^5.12.1`，lockfile 解析停在 **5.12.1**
- 两份副本使 `FastifyInstance` 成为两个不同的名义类型；`withTypeProvider().decorate`
  签名不匹配，于是所有把 `FastifyInstance` 传给 Nest 插件/cookie 的地方都报错

**处置**：在 `pnpm-workspace.yaml` 的 `overrides` 中钉死 `fastify: 5.12.5`（该文件已有
`stack-trace`/`find-my-way` 两条同类 override），`package.json` 的声明同步改为 `^5.12.5`。
**注意 pnpm 12 不再读取 `package.json` 的 `pnpm.overrides`**，必须写在 `pnpm-workspace.yaml`。

**过程中的坑**：`pnpm install` 后 `.pnpm` 下仍残留 `fastify@5.12.1` 目录（已无任何符号链接指向它），
且 `node_modules/.cache/tsbuildinfo.json` 缓存了旧路径，导致删目录后 typecheck 仍报 5.12.1。
**两者都要清**才能生效。

结果：`typecheck` 由 5 个错误降到 **0**；`build` 通过；`test:ci` 全绿。

## 修复 apple-oauth 的 lint 错误（实为真实缺陷）

`pnpm lint:check` 报 `apple-oauth.provider.ts:134` "Unnecessary conditional, value is always falsy"。
**该告警指向一个真实的上游类型缺陷**：`@nestjs/jwt` 把
`decode(token, { complete: true })` 重载声明为**非空返回**，但它委托的 `jsonwebtoken.decode`
对畸形 token **确实返回 `null`**（已用安装版本实测：`jwt.decode('not-a-jwt',{complete:true})`
→ `null`，空串同样 `null`）。

因此原有的 `if (!decoded)` 守卫**运行时是必需的**，删掉它会让畸形 token 在
`decoded.header` 处抛 `TypeError`。**修法是把返回类型断言回真实的 `DecodedAppleToken | null`
并写明理由**，而不是删除守卫或加 lint 豁免——后者会把一个真 bug 静音掉。

### 改判依据

选型在两天内反转六次，最终结论**不是**由性能基准决定的，而是由一个架构事实：

**AGE 缺多跳能力，已把推理整体推到另一个引擎**——`/reason` 的实现主体（541 行端点 +
`DatalogReasoner` + 不动点 + 前提恢复 + 事实预算 + 规则库装载）与图→事实桥（`export.py` 781 行）
都建立在 Oxigraph/Datalog 上。`rules/reasoning.yaml` 的三条随附规则**形状完全一致**，都是
`A ─一跳→ 中间节点 ←一跳─ B` 的二跳模式；若 AGE 支持可靠二跳，三条都可直接写成
一条 Cypher（`MATCH (a)-[:INHIBITS]->(e)<-[:SUBSTRATE_OF]-(b) WHERE a<>b`）。

**⚠️ 本次更正一处此前的错误归因**：早先草稿把"不等式 `A != B` 不生效（12 个自反假阳性）"
与"`load_from_graph` 静默返回 0"当作**当前补偿层的静默缺陷**，并称"现行应对是绕过而非修复"。
**该表述是错的。** 复核 `semantica-service` 后确认：**两者都是上游 Semantica 的 bug，
fork 已修复并加了回归测试**——`export.py` 头注释明写 `load_from_graph` 现抛 `TypeError`
（_"a fork fix; upstream returned 0 and silently reasoned over an empty fact base"_）；
`scripts/check_reasoning.py` 断言 "inequality enforced"；
`tests/test_endpoints.py::test_reason_honours_inequality_constraints` 与
`docs/VERIFICATION.md`（`X != Y` 生效 ✅）覆盖。这两条的正确含义是**引擎信任成本**
（外部规则引擎的正确性需靠 fork 自建回归保证、失效静默），而非该层当下有错。

同时更正一处错误类比：先前把 12 个自反假阳性与 `VERIFICATION-SCALE.md` §3.3 并称"同级"。
§3.3 实为**名称解析完整性**缺陷（节点/边查询各自独立使用同一 `limit`，
`limit=1000` 时 13 个边端点无名），与"约束未生效"不同类，该类比不成立。

并更正"删除补偿层"的表述：由于该层就是 `/reason` 的实现且引擎**通用**
（`ReasonRequest.rules` 接受最多 100 条调用方规则），P4 实为**引擎收编**，
代价是失去"规则即数据"的设计与 `premise` 现成恢复机制，收益是单引擎单方言。
该取舍独立于图后端迁移，可单独取消（计划 §3.5）。

### 记录在案的两个推理错误

本计划把纠错过程写入正文（§〇ter），因为这两个错误比结论更值得保留：

1. **把测试集当需求**。用 232 次真实 LLM 输出 → 真实 AGE 执行的压测结果判定
   "AGE 撑不住"，但那 29 道题是**自出题集**，其中 Q24–Q27 是最短路径题，并非
   产品需要问的场景。且 deepseek 的失败原因是**超时**（20 万边上的无向 `*1..3`
   实测 12 分钟未完成），是图遍历复杂度问题，被误读为引擎不胜任。
2. **把「生产没写」读成「生产不需要」**。`graph/range.py` 六条查询全是固定长度
   单跳，全服务 grep 无变长路径，据此推断"产品不需要多跳"。真相是多跳**换到了
   Datalog 层实现**，不是消失。`range.py:72-74` 的注释已写明绕开的理由是实测超时
   （`-[r]-` 在 200,182 条边上超出 `statement_timeout`），**是做不到，不是不需要**。

用户给出的判据被采纳并验证：**"Datalog 不就是纯妥协吗，AGE 能力足够强的话要
Datalog 干什么"**——检查三条规则是否存在 Cypher 无法表达的构造（递归传递闭包），
结果**一条都没有**，故 Datalog 层无独立价值，可整体删除。

`statement_timeout` 收敛）；变长路径上的属性访问 `[rel IN r | rel.prov]` 报
`could not find properties for rel`。

### 232 题 AGE 执行基线

29 题 × 2 条件 × 2 模型 × 2 轮，真实 LLM 输出对真实 AGE 执行，共 232 次。
通过 205 / 232（88.4%）。提示词修复有效：`shortestPath` 写入率 qwen 6/8 → 0/8，
deepseek 4/8 → 0/8。但 deepseek 出现新的失败模式——被禁 `shortestPath` 后改用无向
变长路径触发超时，说明**提示词能教会模型"别用这个语法"，教不会它引擎没有的能力**。

测试工具自身有两个缺陷已修正并重跑（非改分）：v1 检测器把已绑定的无类型别名误判
为未绑定（虚高至 31%，真实约 19%）；提取器未剥离 `-- Rationale:` 注释致 3 条
qwen 输出被误判为语法错误（修正后 qwen B_fixed 93.1% → 96.6%）。

分模型结果（A_blind 不告知限制 / B_fixed 告知限制并可复制模板）：

| 模型                | 条件    | 通过    | 失败   | 通过率    |
| ------------------- | ------- | ------- | ------ | --------- |
| qwen3.8-max         | A_blind | 52      | 6      | 89.7%     |
| qwen3.8-max         | B_fixed | 56      | 2      | 96.6%     |
| deepseek-v4.1-flash | A_blind | 50      | 8      | 86.2%     |
| deepseek-v4.1-flash | B_fixed | 47      | 11     | 81.0%     |
| **合计**            |         | **205** | **27** | **88.4%** |

失败原因分布（**全部为 AGE 能力缺陷**，非模型缺陷）：

| 原因                                    | qwen A / B | deepseek A / B |
| --------------------------------------- | ---------- | -------------- |
| `shortestPath` 不支持                   | 6 / 0      | 4 / 0          |
| 多类型边 `[r:A\|B]`                     | 0 / 0      | 2 / 3          |
| 变长路径超时（45s `statement_timeout`） | 0 / 0      | 0 / 5          |
| `[rel IN r \| rel.prov]` 属性访问失败   | 0 / 2      | 0 / 0          |
| 模型自身语法错误                        | 0 / 0      | 1 / 1          |
| 未定义标识符                            | 0 / 0      | 1 / 0          |

**零行返回 = 0 / 205：无静默漏数。** 该基线的有效结论只有两条——①提示词修复有效；
②AGE 的多跳能力确实不可用。**不能**据此推断"生产需要多跳"（232 题是合成题集），
**也不能**因 `range.py` 里没有多跳就推断"生产不需要"（多跳当时在 Datalog 层）。
