## fix(deploy): 修复 dev 栈 SeaweedFS 容器启动失败(command 多写了 `weed` 前缀)

### 现象与根因

- `pnpm dev:stack` 起栈后 `lucent-seaweedfs` 反复退出(`Exited (2)`,RestartCount 递增),
  日志固定重复 `weed: unknown subcommand "weed"` / `Run 'weed help' for usage.`。
- 根因:`chrislusf/seaweedfs:4.41` 的镜像 ENTRYPOINT 已改为 `/entrypoint.sh`,该脚本按
  `$1` 分发子命令(`master` / `volume` / `server` / `filer` / `s3` / `shell` / `mini`),
  未命中则兜底 `exec /usr/bin/weed $@`。compose 里写成 `command: weed server ...`,
  于是 `$1` = `weed` 落入兜底分支,实际执行 `weed weed server ...` —— 未知子命令,退出 2。
  即 4.x 镜像入口与 3.x 的 `ENTRYPOINT ["/usr/bin/weed"]` 语义不同,旧写法在该版本失效。

### 变更

- `compose.dev.yaml`:`seaweedfs` 的 `command` 去掉 `weed` 前缀,直接以 `server -dir=/data
-s3 -master.port=9333 ...` 交给入口脚本分发(脚本本身会补 `-dir=/data -volume.max=0
-master.volumeSizeLimitMB=1024`),并就地加注释说明入口约定,避免再次误加前缀。
- healthcheck(`weed shell -master=localhost:9333 ... cluster.check`)保持原样:它走
  `CMD` exec 形式、不经过 entrypoint,直连 master 端口,实测可正常判定健康。

### 验证

- `docker compose -f compose.dev.yaml up -d --force-recreate seaweedfs` 后容器
  `Up (healthy)`,日志无未知子命令报错,master / volume / filer / s3 均正常拉起。
- 端口实测:S3 `127.0.0.1:8333` 根路径返回 403 AccessDenied(S3 网关在线),
  Filer `127.0.0.1:8888` 返回 200。
- 用 compose 内的 dev 凭据做签名 S3 往返:CreateBucket → PUT → GET(内容一致)→
  DELETE 对象 → DELETE bucket 全部成功,数据卷已还原为无桶状态。
