### BUG-02: 抽象 `BaseAsyncQueueService` 基类

**问题**：5 个队列服务结构完全一致，`isConfigured` getter、`enqueue`/`getStatus` 流程、`processJob` try-catch-cache 模式、`resultKey` 生成、`RESULT_TTL_MS` 硬编码均完全相同。07-13 报告已提出，至今未修复。

**涉及文件**：

- `src/modules/medicines/services/medicine-recognition-queue.service.ts`
- `src/modules/today-analysis/services/analysis-queue.service.ts`
- `src/modules/reports/services/ai-summary/summary-queue.service.ts`
- `src/modules/reports/services/clinic-summary/pdf-queue.service.ts`
- `src/modules/today-suggestion/services/explanation/queue.service.ts`

**已确认重复点**：

- `const RESULT_TTL_MS = 30 * 60 * 1000` 在 5 个文件中各定义一次
- `get isConfigured()` getter 完全相同
- `enqueue` → `processJob` → `cache.set(resultKey, RESULT_TTL_MS)` 模式完全相同

**修复方案**：

1. 新建 `src/common/queues/base-async-queue.service.ts`
2. 定义 `BaseAsyncQueueService<TData, TResult>` 抽象基类：
   - `isConfigured` getter
   - `enqueue(data, userId)` → 返回 `jobId | null`
   - `getStatus(jobId, userId)` → 返回状态对象
   - `resultKey(jobId)` → 生成缓存 key
   - `RESULT_TTL_MS` 作为类常量
   - 抽象方法 `processJob(job)` 由子类实现
3. 5 个队列服务改为继承基类，仅保留 `processJob` 实现
4. 将 `RESULT_TTL_MS` 提取到基类或 `common/constants.ts`

**验证方式**：

- `pnpm build` + `pnpm test` + `pnpm lint:check` 全部通过
- 各队列服务 spec 文件不改动即可通过（接口不变）

**预估工作量**：约 500 行重复代码消除，2-3 小时

### BUG-08: 修复 `deploy.ts` `rollback()` 错误覆盖

**问题**：smoke test 失败后调用 `rollback()`，如果 `rollback()` 也抛异常，原始 smoke test 失败原因会被覆盖。

**涉及文件**：

- `deploy/deploy.ts:347-353`

**修复方案**：

```typescript

  runSmokeTest();

    rollback();
  } catch (rollbackErr) {
    console.error('  Rollback also failed:', rollbackErr);
  }
  throw err; // 始终抛出原始错误
}
```

## P2 — 建议：代码质量与安全加固

### BUG-10: 修复 `deploy.ts` `.env` 引号未剥离问题

**报告原分析有误**：报告称 `readEnvFile` 未处理值中包含 `=` 的情况，但实际代码使用 `indexOf('=')` + `slice(eqIndex + 1)` 已正确处理第一个 `=` 之后的全部内容。

**实际问题**：`.env` 值如果用引号包裹（如 `KEY="value with spaces"`），`readEnvFile` 返回的值会包含引号字符，可能导致 Docker Compose 解析异常。

**涉及文件**：

- `deploy/deploy.ts:70-83` — `readEnvFile()` 函数

**修复方案**：

- 在 `value` 赋值前剥离首尾配对的单引号或双引号

```typescript
let value = trimmed.slice(eqIndex + 1).trim();
// 剥离配对引号
if (
  (value.startsWith('"') && value.endsWith('"')) ||
  (value.startsWith("'") && value.endsWith("'"))
) {
  value = value.slice(1, -1);
}
map[key] = value;
```

**验证方式**：

- 编写简单单元测试验证带引号的 `.env` 解析正确

**预估工作量**：约 5 行代码变更，15 分钟

### BUG-14: 验证码哈希加 per-identity salt

**问题**：6 位数字验证码仅 100 万种组合，SHA256 无盐哈希在 Redis 被攻破时可预计算反向查找。结合 rate limiting 和 5 分钟 TTL，实际攻击窗口有限但仍可加固。

**涉及文件**：

- `src/modules/auth/services/verification-code.service.ts:187-188`

**修复方案**：

```typescript
private hashCode(code: string, scene: string, email: string): string {
  return createHash('sha256').update(`${scene}:${email}:${code}`).digest('hex');
}
```

- 同步修改 `safeCompareCode` 传入 `scene` 和 `email`

**验证方式**：

- `pnpm test` 通过（需同步调整 verification-code spec 中的哈希断言）

**预估工作量**：约 10 行代码变更，30 分钟
