## 🟡 警告

### 1. AssistantRuntimeService.runConversation 未集成熔断器

**文件：** `src/modules/assistant/agent/runtime.service.ts` 第 86-110 行（`runConversation` 方法）

`runConversation` 通过 LangGraph 构建工具循环图，内部 `agent` 节点会调用 `boundModel.invoke(state.messages)` 进行 LLM 推理。但此方法没有调用 `this.circuitBreaker.acquire()`，也未在失败时调用 `recordFailure()`。

同类的 `generateStream` 方法（第 128-176 行）已正确集成熔断器。遗漏导致 assistant 聊天场景的 LLM 调用在下游服务不可用时不会快速失败，仍然会把请求发到故障的 LLM provider，加剧过载。

**建议：** 在 `runConversation` 的 `graph.invoke()` 前后增加 `acquire()` / `recordSuccess()` / `recordFailure()` 调用。注意 LangGraph 的 agent↔tools 循环可能多次调用 LLM，需要确保每次 LLM 调用都在熔断器保护范围内。

---

### 2. generateStream 中 recordSuccess 过早调用，流处理失败不计入熔断器

**文件：**

- `src/common/llm/base-llm-generator.service.ts` 第 125 行
- `src/modules/assistant/agent/runtime.service.ts` 第 142 行

两处 `generateStream` 实现中，`recordSuccess()` 都在 `withLlmRetry()` 成功返回 stream 之后立即调用。但后续 `for await` 循环处理流内容时，如果发生以下情况会抛出 Error，却**不会**调用 `recordFailure()`：

- stream 为空（`accumulated === undefined`）
- JSON 解析失败或 schema 验证失败（`parser.parseResult` 或 `this.schema.parse` 失败）
- 流在传输过程中连接中断（网络断开）

这意味着熔断器只统计"连接建立失败"，不统计"流处理失败"。当 LLM 服务处于"半可用"状态（能连接但返回垃圾数据或流中断）时，熔断器不会 trip，其他请求仍会涌入。

**建议：** 将 `recordSuccess()` 的调用时机推迟到流完整处理完毕且结果验证通过之后。或者，在 `for await` 循环的 catch 块中增加 `recordFailure()` 调用。

### 3. recordFailure 在 open 状态下仍会累加 consecutiveFailures

**文件：** `src/common/llm/llm-circuit-breaker.service.ts` 第 154-159 行

```typescript
recordFailure(): void {
  const state = this.getState();
  if (state === 'halfOpen') { ... }
  // closed 分支
  this.consecutiveFailures += 1;   // ← 当 state === 'open' 时也会执行
  if (this.consecutiveFailures >= this.options.failureThreshold) {
    this.trip();  // trip 内部会检查 if (this.state === 'open') return;
  }
}
```

当熔断器已经是 `open` 状态时，`recordFailure()` 会进入 `closed` 分支并增加 `consecutiveFailures`。虽然 `trip()` 在内部有 `if (this.state === 'open') return;` 保护，不会重复触发 `open` 状态，但 `consecutiveFailures` 计数器会持续累加。

这会导致 `snapshot()` 返回的 `consecutiveFailures` 在 `open` 状态下不准确（包含被拒绝请求的计数），可能误导基于 `snapshot()` 的监控面板。

**建议：** 在 `recordFailure()` 的 `closed` 分支前增加 `if (state === 'open') return;` 保护，或在 `trip()` 时确保 `consecutiveFailures` 被正确维护。
