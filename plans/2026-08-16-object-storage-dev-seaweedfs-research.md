## 额外的端点与公开读风险

`http://<host>:8888/buckets/lucent-dev/<key>` 是 filer 直接读路径，不经过 S3 gateway 或 SigV4。它适合开发时的公开图片预览，但不等同于对象存储的签名下载 URL：任何能访问该 filer 的局域网客户端都可按对象 key 读取；filer 的目录暴露也默认开启。[filer 参数源码](https://github.com/seaweedfs/seaweedfs/blob/f530102c45861f9af955b1bde41f7da8ce3f24a6/weed/command/server.go#L119-L126)

计划应将其标为「仅开发公开读」，并在非开发环境禁止这种 base URL。若要测试下载 URL 的授权/过期语义，应使用 S3 gateway 上的签名 GET，而不是 filer URL。

## 推荐的 compose 方向

保持 `weed server` 时，最小关键形态为：

```yaml
command: server -dir=/data -s3 -master.port=9333 -volume.port=8080 -filer.port=8888 -s3.port=8333
```

若目标是单机开发且需要「预建桶 + 真实凭据」，官方 `weed mini -dir=/data` + `AWS_ACCESS_KEY_ID`、`AWS_SECRET_ACCESS_KEY`、`S3_BUCKET=lucent-dev` 是更直接的受支持路径；注意它的 volume 默认端口为 9340，而非 `server` 的 8080。[官方 Docker/mini 快速开始](https://github.com/seaweedfs/seaweedfs/blob/f530102c45861f9af955b1bde41f7da8ce3f24a6/README.md#L59-L109)
