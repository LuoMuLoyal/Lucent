## 一、这份计划要解决的五件事

1. **推理用上**：`/reason`（Datalog）与 `/validate`（SHACL）今天在 sidecar 上可用，
   但 Lucent 没有任何工具调用它们，`/reason` 自身也还建立在**随机切片**之上。
2. **推理结论可审计**：推理输出必须能沿"结论 → 规则 → 前提断言 → 来源行"走回去，
   与图谱问答共用同一条 PROV-O 引用链。
3. **图谱数据缺口**：ATC 类名缺失、相互作用边单向。
4. **服务硬化**：推理的资源上限今天**不存在**（配置项是装饰）、导出桥不确定、
   sidecar 传输层无重试。
5. **评测集落地**：两轮的 20 道题固化成仓内可复跑的评测集（S0）。

## 三、硬约束（先于实现，违反即回退）

1. **结论必须区分"断言"与"推理"**：`verifiability` 新增 `derived` 档；由规则推出的关系
   绝不允许与 DrugBank 直接断言的关系同形呈现。
2. **不得在截断的图上做否定结论**：`/reason` 的输入范围必须显式且确定；载入不完整时
   返回值里要写明"这是切片"，而不是让"没推出"看起来等于"不存在"。
3. **每条派生结论必须带前提引用**：前提断言用其 `prov` id 引用（与问答链同一套），
   缺失前提引用的结论不得进 envelope。
4. **SHACL 形状的命名空间必须与桥一致**（`http://lucent.local/graph#`），否则校验会
   静默通过——一个"看起来成功"的空校验比没有校验更危险。
5. **未复核的中英 `SAME_AS` 不得被结论级推理消费**（ADR-0021 §9）。
6. 每个阶段都要有：单测、当日迁移日志、本计划状态同步、以及一条可复跑的命令。

## 四、工作面与阶段

### A. 推理接线（R1–R5）

| 阶段                                        | 工作量 | 内容                                                                                                                                                                                                                                                                                                                                                                                        | 验收                                                                                                                      |
| ------------------------------------------- | ------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| **R1** 推理输入桥（前置，不可跳过）         | 1 天   | 导出桥改为**确定性**：按内部 id 排序 + keyset 分页，`/reason` 的 `load_from_graph` 只接受显式范围（drugbank_id 列表或 ATC 前缀 + `limit`），并在响应里 echo 实际载入的节点/边数与范围；同时产出 **fact → 断言** 映射（节点用业务键、边用 `(source, type, target)` 规范键 → `prov` id 或 `null`）                                                                                            | 同一请求连发两次，载入集合的哈希相等；抽样 20 条 fact 全部能解出 `prov`；截断时响应显式标注                               |
| **R2** 规则库（规则是数据，不是请求参数）   | 0.5 天 | 规则以仓内文件版本化（`rules/*.yaml`，含 `id`/`intent`/`body`/`citation_hint`），sidecar 启动时加载并校验（规则必须引用词表内的关系类型）；首批三条：`potential_ddi_inhibitor_substrate`（`inhibits(A,E), substrate_of(B,E), A != B`）、`in_class`（ATC 传递闭包）、`prodrug_activation_chain`（按需）                                                                                      | 每条规则在真实图上有可复现的输出规模与样例；fixture 小图上单测通过；规则 id 出现在响应里                                  |
| **R3** Lucent 侧推理工具与可审计封装        | 1 天   | 新工具 `reason_over_rules`：入参 `intent`（或 `rule_id`）+ 范围；envelope 返回 `derived` 结论集、每条结论的 `ruleId` + 前提 `citations`（复用 PROV-O 链路）、`verifiability: 'derived'`、以及范围声明；SSE 把 `citations` 与 `executedQuery` 的等价物（规则名 + 范围）透传；Luminous 来源条区分"断言"与"由规则推出"                                                                         | 模型能引用结论；来源条显示"由规则 R 从 N 条断言推出"；未登记规则不可调用；`policy` 门控与 `ASSISTANT_OAG_TOOL_NAMES` 同步 |
| **R4** 资源上限真正生效                     | 0.5 天 | `max_reasoning_facts` / `reasoning_timeout_s` 接进 `/reason`（当前是装饰）；`facts`/`rules` 加 `max_length`；派生规模与墙钟超限返回结构化错误（不是挂住）；`/query` 与 `/reason` 的 CPU-bound 工作走多 worker                                                                                                                                                                               | 构造超限请求返回结构化错误；并发 16 冒烟无 5xx、无线程池饿死                                                              |
| **R5** 词表 YAML + 手写 SHACL 门禁（原 S3） | 1 天   | 落 `Lucent` 侧词表 YAML（实体类型 / 关系类型 / 每类必填属性）；从词表**手写** SHACL 形状，命名空间对齐桥；形状覆盖已知错误类型（关系类型必须 ∈ 词表、`Drug` 必须有 `drugbank_id`、`SUBSTRATE_OF` 目标必须是 `Protein`、`IN_ATC_CLASS` 的 code 必须存在于 `ATCClass`）；导出后与 CI 各跑一次 `/validate`；顺带修正 `/validate` 的错误语义（非法 Turtle / 错误 ontology dict → 422 而非 500） | 故意注入 3 类违规各被报出、合法图 conforms；形状随词表版本化；`arch:check` 或 CI 里有调用点                               |

> **R1 是其余推理工作的前置**：今天的 `/reason` 在一张随机切片上做"没有推出即不存在"的
> 推理，先把输入桥修成确定的，R2/R3 才谈得上正确性。

## 五、风险

| 风险                                                             | 事实                                                                 | 应对                                                                                              |
| ---------------------------------------------------------------- | -------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------- |
| **推理假阳性**（抑制某酶的 A × 该酶底物 B 不等于临床上必须避免） | 规则是组合性的，`INHIBITS × SUBSTRATE_OF` 会给出远多于临床相关的对数 | `verifiability: 'derived'` + 结论措辞固定为"潜在、需专业复核"；不用绝对化措辞；不进入任何自动建议 |
| **在切片上推理**                                                 | 今天的导出桥取随机 1000 条边                                         | R1 前置；未完成 R1 前 `load_from_graph` 不得投入产品使用                                          |
| **SHACL 静默通过**                                               | 命名空间不匹配时 pyshacl 报 conforms                                 | 硬约束 §4；形状落仓并有"故意违规"的反例测试                                                       |
| **规则与数据漂移**                                               | 关系类型演进会让规则静默失效                                         | 规则引用词表内类型（R2 的启动校验）；词表变更即触发规则单测                                       |
| **外部依赖**（模型供应商配额 / 凭据）                            | 本轮评测中途失效，连续两点复现                                       | 评测阶段开始前先确认配额；E2 把这类失败显式记录，不混进功能结论                                   |
| **fork 跟随 `main` 的漂移**                                      | 不钉 SHA，行号与行为都可能变                                         | 每次 rebase 重跑：fork 改动是否被上游修掉、AGE Cypher 子集探针、`--verify` 链校验                 |

## 六、非目标

- **不接 Semantica 的生成能力**：答案出口唯一（ADR-0021 §7）。它的四类生成（答案 / 查询 /
  本体候选 / 实体关系抽取）都不用。
- **不接 Rete / SPARQL / 时态推理 / 决策智能**：Rete 需要 `Rule` 对象而非 Datalog 文本且没有
  fixpoint；SPARQL 需要三元组库（Oxigraph 在我们这里只是 extra）；时态与决策记录没有产品
  场景。**"解释"也不走它的 `ExplanationGenerator`**（它吃不了 Datalog 的字符串输出）——
  我们自己的"规则名 + 前提引用"就是解释。
- **不引入它的嵌入 / NER / 消解 / 文档解析链路**：英文侧是确定性灌入，不需要。
- **中文侧不引入 Semantica / AGE**（ADR-0021 §1）。
- **不把推理结论写成诊断或用药建议**：结论只作为"待复核的潜在关系"呈现。
