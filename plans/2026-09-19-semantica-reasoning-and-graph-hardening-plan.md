## 三、硬约束（先于实现，违反即回退）

1. **结论必须区分"断言"与"推理"**：`verifiability` 新增 `derived` 档；由规则推出的关系
   绝不允许与 DrugBank 直接断言的关系同形呈现。
2. **不得在截断的图上做否定结论**：`/reason` 的输入范围必须显式且确定；载入不完整时
   返回值里要写明"这是切片"，而不是让"没推出"看起来等于"不存在"。
3. **每条派生结论必须带前提引用**：前提断言用其 `prov` id 引用（与问答链同一套），
   缺失前提引用的结论不得进 envelope。
4. **SHACL 形状的命名空间必须与桥一致**（`http://lucent.local/graph#`），否则校验会
   静默通过——一个"看起来成功"的空校验比没有校验更危险。
5. **未复核的中英 `SAME_AS` 不得被结论级推理消费**（ADR-0021 §9）。
6. 每个阶段都要有：单测、当日迁移日志、本计划状态同步、以及一条可复跑的命令。

| **R2** 规则库（规则即数据）          | 已完成 | 规则以 `semantica-service/rules/reasoning.yaml` 版本化（`id`/`intent`/`body`/`citation_hint`/`consumes`），启动时加载并对照图上实际词表校验；`/reason` 支持 `intent`/`rule_id`，返回 `rule` + `conclusions`（每条含 `verifiability: derived`、前提 `citations`、`uncited_premises`）；新增 `GET /rules`；请求方自带规则文本仍可推导，但不产生带归因的结论。**结论按 `query` 收窄**（原先无视 query，单药范围实测返回全部 20,116 条），**前提恢复在收窄之后做**（原先上限取整个事实库的前 500 条，导致查询真正问的 67 条一条引用都没有） |
| **R3** Lucent 侧推理工具与可审计封装 | 已完成 | 新工具 `reason_over_rules`：入参 `intent` + `query` + **必填**范围（`drug_names` / `atc_prefixes`）+ `limit`；envelope 用独立的 `SemanticaReasonOutcome` 类型承载，与断言的 `SemanticaQueryOutcome` **类型上分开**（`cypher` 换成 `rule` + `query` + `derivedNote`），每条结论带 `ruleId` 与前提 `citations`；范围缺失、未命中、全变量模式（`(?A, ?B)`）三种都在参数边界或按结构化 `kind` 拒绝，且理由归属正确（可修正的输入问题说成 scope，不说成 unavailable）。真机验证 `semantica-oag-pilot/lucent-oag-eval/verify-rules.mjs` 11/11 |
| **R4** 资源上限真正生效              | 已完成 | `max_reasoning_facts` / `reasoning_timeout_s` 接进 `/reason`；`facts`/`rules` 加 `max_length`；派生规模与墙钟超限返回结构化错误（`kind` + `detail`），不挂住                                                                                                                                                                                                                                                                                                                                                                            |
| **R5** SHACL 命名空间门禁            | 已完成 | `graph/shapes.py` 在调用校验器前断言形状能在本图里选到目标，拒绝「前缀被绑到别的 IRI」与「声明了前缀却没有任何词落在图的命名空间」。动机：形状选不中目标时 SHACL 报 `conforms=true`，与"确实满足"无法区分 —— 实测同一形状在正确命名空间报 895 条违规，在错误命名空间报 0 条且 conforms                                                                                                                                                                                                                                                  |

> R3 的两处范围决定，均有实测依据：
>
> - **`limit` 是"子图边数"而不是"返回行数"**。它与 `SEMANTICA_MAX_LIMIT`（25/100
>   行）刻意不复用：推理代价随范围超线性增长，把两者当一个数，要么让范围小到
>   推不出东西，要么让范围大到必然超时——而超时会被读成"图上没有"。
> - **全变量模式被拒绝**。`potential_ddi(?A, ?B)` 语义上成立，但它的答案是整个
>   结论集（单药范围实测 20,116 条）。那不是提问，是把子图的全部推导倒进上下文。
>
> 还有一处**已知未修**：`REASONING_TIMEOUT_S` 覆盖不动点，不覆盖导出阶段。
> 导出侧已从 57s 降到 12.7s（50,000 边），但在更小的预算下仍可能击穿调用方的
> 超时预期。见 `semantica-oag-pilot/CORRECTIONS-r3.md`。
>
> 相对原计划的两处调整，均有实测依据：
>
> - **R5 的词表 YAML 未落**。原设计要落一份实体/关系词表 YAML 并据此手写 SHACL 形状。
>   但词表已有两处事实源（`/schema` 从图实时读、规则库的 `consumes` 声明），再加一份
>   YAML 就是第三个需要手工同步的地方，而它一旦漂移恰恰会让校验静默失效 —— 正是这一步
>   要防的问题。改为把「形状必须真的约束到本图」做成运行时门禁，并在启动时用
>   `verify_against_vocabulary` 对规则做同类检查。SHACL 形状本身**不预置**：形状承载的是
>   产品语义（如"Drug 必须有 drugbank_id"），应由产品侧按需提交，门禁保证它们不会静默失效。
> - **R1 的分页不是 keyset**。原计划写 keyset 分页；实现用「LIMIT 递增 + 查询自带
>   `ORDER BY`」，因为 keyset 需要沿排序键做游标比较，而「机制边优先 + 类型内按 id」的
>   两级排序没有单一可比较键。代价是每页重读前面的行，收益是避开 `OFFSET`（`OFFSET`
>   会让深翻页逐页变慢、整体二次方）。读取上限由调用方给定，总代价与答案规模成正比。

## 五、风险

| 风险                                                             | 事实                                                                 | 应对                                                                                              |
| ---------------------------------------------------------------- | -------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------- |
| **推理假阳性**（抑制某酶的 A × 该酶底物 B 不等于临床上必须避免） | 规则是组合性的，`INHIBITS × SUBSTRATE_OF` 会给出远多于临床相关的对数 | `verifiability: 'derived'` + 结论措辞固定为"潜在、需专业复核"；不用绝对化措辞；不进入任何自动建议 |
| **在切片上推理**                                                 | 今天的导出桥取随机 1000 条边                                         | R1 前置；未完成 R1 前 `load_from_graph` 不得投入产品使用                                          |
| **SHACL 静默通过**                                               | 命名空间不匹配时 pyshacl 报 conforms                                 | 硬约束 §4；形状落仓并有"故意违规"的反例测试                                                       |
| **规则与数据漂移**                                               | 关系类型演进会让规则静默失效                                         | 规则引用词表内类型（R2 的启动校验）；词表变更即触发规则单测                                       |
| **外部依赖**（模型供应商配额 / 凭据）                            | 本轮评测中途失效，连续两点复现                                       | 评测阶段开始前先确认配额；E2 把这类失败显式记录，不混进功能结论                                   |
| **fork 跟随 `main` 的漂移**                                      | 不钉 SHA，行号与行为都可能变                                         | 每次 rebase 重跑：fork 改动是否被上游修掉、AGE Cypher 子集探针、`--verify` 链校验                 |

## 六、非目标

- **不接 Semantica 的生成能力**：答案出口唯一（ADR-0021 §7）。它的四类生成（答案 / 查询 /
  本体候选 / 实体关系抽取）都不用。
- **不接 Rete / SPARQL / 时态推理 / 决策智能**：Rete 需要 `Rule` 对象而非 Datalog 文本且没有
  fixpoint；SPARQL 需要三元组库（Oxigraph 在我们这里只是 extra）；时态与决策记录没有产品
  场景。**"解释"也不走它的 `ExplanationGenerator`**（它吃不了 Datalog 的字符串输出）——
  我们自己的"规则名 + 前提引用"就是解释。
- **不引入它的嵌入 / NER / 消解 / 文档解析链路**：英文侧是确定性灌入，不需要。
